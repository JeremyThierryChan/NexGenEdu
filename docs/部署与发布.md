# 部署与发布

> 读者：要在这台电脑上跑起来、或要把改动发布上线的人。
> 架构层面为什么这么部署，见 [技术架构.md](./技术架构.md#5-宣传网站)；后端整体方案见 [后端开发方案.md](./后端开发方案.md)。

线上地址：**https://jeremythierrychan.github.io/NexGenEdu/**（GitHub Pages 项目站点，子路径部署）。

**上线的只有宣传站。** 教务后台是**本机使用**的：它连的是这台电脑上的 Node + SQLite 后端
（`npm run server`），没有任何服务端部署环节；线上那份后台页面会直接提示「后台需要本机后端」，
不会给一个登不上的登录框（这是有意的 —— 假登录框比一句说明更让人困惑）。

## 1. 本机环境

| 项 | 值 / 注意 |
| --- | --- |
| Node | **≥ 22.6**（CI 用 22；本机与 Actions 都在 22 上验证）。本项目多数 npm 脚本（`check`、`server`、`check:both`、`check:auth`、`accept`、`drill:restore`）用 `--experimental-strip-types` 直接跑 `.mts`/`.mjs`，Node 18/20 会报 `unknown option --experimental-strip-types` —— 所以不要用旧版本"只跑宣传站" |
| 装依赖 | `npm install --cache ./.npm-cache` —— 这台机器的 `~/.npm` 是只读的，必须把缓存指到项目内 |
| 开发服务器 | `npm run dev`（`scripts/dev.mjs` 包装，先同步内容再起 Next） |
| 本地访问 | http://localhost:3000 （本地**不设**子路径前缀） |
| 后端 | `npm run server` —— 本机 Node + SQLite，默认**只绑 `127.0.0.1:4000`**（`NEXGENEDU_HOST` / `PORT` 可改）；数据文件 `server/data/nexgenedu.db` |
| 后台连后端 | 在 `.env.local` 里设 `NEXT_PUBLIC_API_BASE=http://localhost:4000`（照 `.env.example` 复制，该文件不会被提交）。**不设这一项，后台就没有后端可连**，页面会显示「后台需要本机后端」 |
| 登录口令 | 取 `NEXGENEDU_ADMIN_PASSWORD`；没设就首次启动随机生成一份，写进 `server/data/admin-credential.json`（权限 0600）**并且只在启动日志里打印一次**。口令不进数据库，前端只拿令牌，**后端重启后需要重新登录** |
| 备份 | 每天自动一份到 `server/backups/`（启动补齐 + 每小时检查），保留最近 90 份（`NEXGENEDU_BACKUP_KEEP` 可改）；文件名形如 `nexgenedu-YYYY-MM-DD-HH-mm-ss.db`（本地时间），清理只碰符合这个命名的文件 |

## 2. 命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 本地开发（含内容同步与"网站内容用哪一份"的判定） |
| `npm run sync-content` | `data/site/*.md` → `data/site/*.ts` |
| `npm run sync-site-data` | 构站前问一次后端：连得上就用库里的内容，连不上就用模版（会打印「本次网站数据来源」） |
| `npm run site:snapshot` | 把库里的教师 / 课程 / 正文 / 报价导回仓库模版，让 GitHub Pages 那份也跟着更新 |
| `npm run start` | 运行生产构建产物（宣传站） |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run check` | 内容 + 报价 + 服务层 + 接口契约与文档一致性（当前 700+ 项断言，以命令输出为准） |
| `npm run check:404` | 校验 404 产物（分流、样式、文案） |
| `npm run check:links` | 校验产物里的全部站内链接 |
| `npm run check:all` | 上面三个 check 连着跑 |
| `npm run build` | 同步内容 + 静态导出到 `out/` |
| `npm run server` | 启动后端（本机 Node + SQLite，默认 127.0.0.1:4000） |
| `npm run server:migrate` | 跑数据库迁移（迁移前自动备份一份带 `nexgenedu-migrate-` 前缀的快照） |
| `npm run server:health` | 探活：`curl -s http://localhost:4000/health`（公开的只有服务名与库文件名） |
| `npm run server:import` | 把 JSON 导入库里（导错可用备份回滚） |
| `npm run server:backup` | 手动备份一次（`-- --list` 看清单，`-- --force` 忽略「今天已备份」） |
| `npm run check:both` | 同一套自检**对两种后端各跑一遍**（内存 + 真实 HTTP 服务端） |
| `npm run check:auth` | 服务端认证自检（未登录 401、令牌、退出、操作人来自会话） |
| `npm run accept` | 逐页验收：自己起一个**临时后端**，对后台各页面做真实读写（当前 43 项，以命令输出为准） |
| `npm run drill:restore` | 恢复演练：备份 → 删库 → 只靠备份文件恢复 → 核对数据 |

**改动内容后必须跑**：`npm run sync-content` → `npm run check` → `npm run build`。

**网站内容用哪一份，由构建时的三件事决定**（详见 [技术架构 §5.1](./技术架构.md#51-网站内容从哪来三层来源构站时决定整体切换)）：

| 情况 | 结果 |
| --- | --- |
| 本机构建、后端开着（`npm run server` 在跑） | 页面用**库里**的教师 / 课程 / 正文 / 报价生成 |
| 本机构建、后端没开 | 页面用 `data/site/site-snapshot.json`（上次导出的**仓库快照**）生成；没有快照就用 `data/site/*.md` **模版** |
| GitHub Actions 构 Pages | 必然是**模版**（那台机器上没有后端；工作流里显式写了 `SITE_CONTENT_SOURCE=template`） |

> 注意工作流里那一行是**刻意的**：Pages 要显示库里的内容，靠的是
> `npm run site:snapshot` 导出的快照提交进仓库，而不是在 Actions 里连后端（连不上）。

| 环境变量 | 作用 |
| --- | --- |
| `SITE_CONTENT_SOURCE` | `auto`（默认）/ `backend`（必须用后端，连不上就构建失败）/ `template`（强制模版） |
| `SITE_API_BASE` | 后端地址，默认 `http://127.0.0.1:4000` |
| `SITE_API_STRICT=1` | `auto` 下连不上也**让构建失败**。正式部署建议打开：免得悄悄发了一版模版上去 |

**改完库里的内容要重新构站**才会反映到网站上（静态站点的固有节奏）。
GitHub Pages 那一份永远来自仓库里的模版，要让它也跟上就跑 `npm run site:snapshot` 再提交。

**回到本机用法**（后台完整跑起来）需要一个终端 A 起后端、一个终端 B 起前端：

```bash
npm run server     # 终端 A：后端，记下启动日志里的口令
npm run dev        # 终端 B：前端 → http://localhost:3000/admin
```

**CI 不跑最后那几条**：`check:both` / `check:auth` / `accept` / `drill:restore` 都要起服务端，
它们是**本机门禁**——CI 里跑不了，也正因为如此，推送前要自己跑一遍（见第 4 节的步骤 1）。

## 3. 本地验证「线上形态」

GitHub Pages 部署在子路径 `/NexGenEdu/` 下，而本地开发不带前缀。要检查前缀相关的问题（资源 404、链接错位），本地按线上方式构建一次：

```bash
rm -rf out && NEXT_PUBLIC_BASE_PATH=/NexGenEdu npm run build
npm run check:404 && npm run check:links
```

`next.config.ts` 里 `basePath`（路由）与 `assetPrefix`（静态资源）都跟着这个变量走；`trailingSlash: true` 让产物是目录形式（`/courses/` → `courses/index.html`）。静态导出不支持图片优化，因此 `images.unoptimized: true`。

这一段只对**宣传站**有意义：后台不在 Pages 上，没有「线上形态」可验 —— 它在本机跑，
验的是「起后端 + 起前端 + 用启动日志里的口令登录」这条链路（见第 5 节清单）。

## 4. 发布流程

1. 改完内容/代码，本地跑通命令后提交：

   ```bash
   git add <明确列出的文件>      # 不要 git add -A：仓库里有 .xmind 等源文件
   git commit -m "type(范围): 说明"
   ```

   提交信息风格：`feat(咨询): …`、`fix(排课): …`、`content(时间): …`、`docs(手册): …`。

   **动了后台/服务端就多跑一遍本机门禁**：`npm run check:both` → `npm run check:auth` → `npm run accept`。
   这三条 CI 不会替你跑（它们要起服务端），所以「CI 绿」不等于「服务端没坏」。

2. 需要上线时推送（**只有推送才会部署**）：

   ```bash
   git -c http.version=HTTP/1.1 push origin main
   ```

   这台机器访问 github.com 偶尔失败，失败就重试几次（用上面的 `-c http.version=HTTP/1.1` 更稳）。

3. GitHub Actions（`.github/workflows/deploy-pages.yml`，main 分支）按顺序执行：

   ```
   npm ci → lint → sync-content → typecheck → check
          → build（NEXT_PUBLIC_BASE_PATH=/<repo>）
          → touch out/.nojekyll → check:404 → check:links
          → 上传产物 → 部署到 Pages
   ```

   **任何一步失败都不会部署**：线上会停留在上一个成功版本，这是有意的（宁可不上线，也不上线一个自检没过的版本）。
   CI 只跑这条「构站 + 静态产物自检」的链路，`check:both` / `check:auth` / `accept` / `drill:restore`
   与后端有关的四条**不在里面**（要在本机起服务端），这是当前有意的分工。

4. 等 workflow 变绿，再按下面的清单核对线上。

## 5. 上线后核对清单

线上的宣传站（这一节的前半）与本机的后台（后半）是两件事，别混着看。

- [ ] 首页：品牌名、首屏、教学特色、教师团队、学生案例、试课、课程、教室环境都在；
- [ ] 课程页：六栏目 → 卡片；点进任意一张卡片正常打开（不是 404）；
- [ ] 智能报价：随便选一套（阶段/课程/科目/班型/时长/节数）能算出课单价与总价；
- [ ] 随手点一个不存在的地址（例如 `/nope`），404 页面正常；
- [ ] 页脚的营业时间（9:00–21:00）与上课时间（8:00–22:00）都对；
- [ ] 线上 `/admin`：应当显示「后台需要本机后端」而不是登录框 —— 静态站没有后端可连，这是预期行为，不是故障；
- [ ] **本机**（`npm run server` + `npm run dev`，`.env.local` 里设了 `NEXT_PUBLIC_API_BASE`）：
      能看到登录页，用后端启动日志里打印的口令能进去，未登录时直接敲接口拿到的是 401；
- [ ] 本机 `GET /health` 能返回（只回服务名与库文件名），`server/backups/` 里有当天的备份文件。

## 6. 常见故障

| 症状 | 原因 / 处理 |
| --- | --- |
| CI 报 `TS2307: Cannot find module './.sync-stamp'` | 同步脚本的产物没进仓库：本地跑 `npm run sync-content` 后提交 `data/site/*.ts` |
| `npm run check` 红，提示「接口契约没有漏登记的方法」 | 给 `api.ts` 加了方法但没补 `lib/backend/contract.ts` 与 `docs/后台API约定.md` |
| `npm run check` 红，提示「API 文档漏掉的方法」 | 同上：文档必须提到每一个方法名 |
| `check:links` 红 | 产物里有指向不存在页面的链接：多半是卡片 `路径` slug 写错了（见内容维护手册） |
| 线上改的内容没出现 | 只提交没推送；或 workflow 失败（去看 Actions 日志）；或浏览器缓存（强刷） |
| 页面某段内容突然不显示 | 内容文件格式被破坏（标题层级/字段块）—— 本地 `npm run check` 通常会指出是哪一段 |
| 后台显示「后台需要本机后端」 | 这次构建没有后端地址：`.env.local` 里没设 `NEXT_PUBLIC_API_BASE`（或没重起 `npm run dev`）。线上那份**永远**是这样 |
| 后台一直跳到登录页 / 提示未登录 | 后端没在跑（终端 A 的 `npm run server`），或**后端重启过**（会话只在服务端内存里，重启即失效），或令牌过期 —— 重新登录即可 |
| 登录说口令不对 | 口令只在**首次启动**的日志里打印过一次：看日志还是丢了就设 `NEXGENEDU_ADMIN_PASSWORD` 后重起后端；忘了又没设环境变量时，口令在 `server/data/admin-credential.json`（0600，只有哈希与盐，看不回原口令） |
| 报 `unknown option --experimental-strip-types`（起后端或跑自检） | Node 版本太老：本项目要求 **≥ 22.6**（`package.json` 的 `engines` 也这么写）。`node -v` 确认一下，用 nvm/fnm 切到 22 |
| 起后端报端口被占用 | 4000 已被别的进程占用（上一次没退干净），`PORT=4001 npm run server` 并把 `.env.local` 里的后端地址一起改 |
| 后台数据「不见了」 | 数据在服务端的 `server/data/nexgenedu.db`，**不在浏览器里**：换设备/清缓存都不会丢。真丢了先看 `server/backups/`（每天一份、保留 90 份），用备份文件恢复或跑 `npm run drill:restore` 练一遍 |
| 备份没生成 / 想临时关掉 | 日常不用管：服务端启动会补齐「今天那份」，之后每小时检查一次。被 `NEXGENEDU_NO_BACKUP=1` 关掉（测试用）就不会有；换目录用 `NEXGENEDU_BACKUP_DIR` |
| `npm install` 报权限错误 | 必须带 `--cache ./.npm-cache`（`~/.npm` 只读） |
| `push` 失败 | 网络问题，重试；项目不需要在每次提交后都推送 |

| **dev 报 `Cannot find module './NNN.js'`（或页面 500）** | **`npm run build` 与 `npm run dev` 共用 `.next` 目录**：build 会把 dev 的编译产物覆盖掉，dev 随即找不到自己的 chunk。这不是代码问题。处理：停掉 dev → `rm -rf .next` → 重新 `npm run dev`。**别在 dev 开着的时候跑 build**（想验证构建就先停 dev） |

## 7. 回滚

- **网站**：`git revert <提交>` 后推送，Actions 会重新部署上一版内容；也可以在 GitHub Actions 页面里重新运行上一个成功的工作流。
- **后台数据（本机数据库）**：日常靠 `server/backups/` 里的每日备份 —— **先停掉后端**，把 `server/data/nexgenedu.db`
  连同 `-wal` / `-shm` 一起挪走（或删掉），再把某一份 `nexgenedu-YYYY-MM-DD-HH-mm-ss.db` 复制成 `server/data/nexgenedu.db`，
  然后重起后端核对条数（`npm run drill:restore` 走的就是这条路径，可以先跑它练一遍）。
  迁移前还会自动多备一份带 `nexgenedu-migrate-` 前缀的快照，专门用来回退一次迁移。
- **后台数据（界面内）**：后台「数据与备份」页在每次导入前自动备份，可一键恢复；「重置示例数据」会把本机数据恢复成示例数据（**会丢失本机改动**）。
- **报价配置**：后台报价页有「恢复为站点内容」，把配置退回 `data/site/pricing.md` 里的价格。

## 8. 本机注意事项

- 仓库里有你自己的源文件（`*.xmind`、`docs/陈林维祎老师.md`、`docs/教师信息登记表.md`）也会被 git 跟踪：**提交时按路径明确列出文件，不要 `git add -A`**。
- `out/` 是构建产物，不要提交。
- `server/data/` 与 `server/backups/` 也要**留在本机**：库里是真实数据，`admin-credential.json` 是口令凭据（权限 0600）—— 都不进 git，也不要往里塞临时文件（备份清理只删符合命名规则的文件，其他东西原样留着）。
- 后端默认**只绑 `127.0.0.1`**：这是有意的（单用户本机使用）。要让别的设备访问得显式设 `NEXGENEDU_HOST`，那等于把没有并发控制的系统暴露出去，请先想清楚。
- `.DS_Store` 这类系统文件不要提交；构建前如果发现产物里有，先删掉再构建。
- 默认**只在需要上线时推送**：本地提交即可，避免每次小改动都触发一次部署；后台与本机数据库的改动本来也不会通过推送影响线上。
