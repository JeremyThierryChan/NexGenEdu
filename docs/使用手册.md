# 教务后台使用手册

> **给谁看**：辅导机构的前台 / 教务老师。不需要懂技术，不需要问开发。
>
> **怎么用**：不需要从头读到尾。**第 0 节是五分钟上手**，先照着做一遍；
> 之后遇到具体事情，直接跳到对应那一节（按「你今天要做什么」分节，不按系统模块分）。
>
> **阅读顺序建议**：
> 1. 第 0 节（五分钟上手）+ 第 1 节（登录）；
> 2. 你每天最常做的三件事：第 7 节（排课）、第 4 节（报课与收费）、第 12 节（报价）；
> 3. 其余章节按需查；第 15 节是「出错了怎么办」，第 17 节是「现在做不到的事」。

## 现在怎么用（本机 + 后端数据库）

**每天开两个终端**（进了项目目录）：

```bash
npm run server     # 终端 A：后端（数据存 SQLite）
npm run dev        # 终端 B：前端
```

然后打开 **http://localhost:3000/admin**，用账号 **`admin`** 登录。

> ⚠️ **地址以终端里打印的那行为准。** Next 默认用 3000，但**如果 3000 已被别的程序占用
> （哪怕是你另一个项目），它会自动改用 3001、3002…**，终端会打印
> `- Local: http://localhost:3001`。这时你打开 3000 看到的是**别的程序**的页面 ——
> 在那儿怎么输口令都进不了这个后台，还很容易误以为"密码不对"。
> 判断方法：本项目后台的标题是「NexGenEdu 教务后台」。

**密码从哪来**：第一次启动后端时，它**自己生成一个随机口令并打印在终端 A 里**，
像这样：

```
[登录] 账号：admin（口令来源：本次新生成）
[登录] 本次新生成的口令：xxxxxxxxxxxxxxxx
[登录] 已存到 server/data/admin-credential.json（权限 0600，重启后继续有效）
```

- 把那行口令记下来（也可以直接打开 `server/data/admin-credential.json` 看）；
- 想自己定口令：启动时加环境变量，例如
  `NEXGENEDU_ADMIN_PASSWORD=你的口令 npm run server`；
- **如果找不到 `admin-credential.json`**：说明后端是用 `NEXGENEDU_ADMIN_PASSWORD`
  启动的（那种情况口令来自环境变量，不会落文件），或者这台机器上还没启动过后端。
  这时用启动时给的那个口令；忘了就删掉该文件并用环境变量重新启动一次来换口令。
- **密码只在服务端**（不再写在网页代码里），所以源码公开也不影响；
- 后端重启后需要**重新登录**一次（登录状态不落盘，这是刻意的）。

- 页面顶部若显示「**已连接后端**」→ 你录的数据进服务端数据库，换设备/清缓存都不会丢；
- 若显示「**线上静态站点**…」→ 这个页面没有连上后端（没设置 `NEXT_PUBLIC_API_BASE`）：
  检查终端 A 是否在跑、前端是否重启过。

**备份**：后端**每天自动备份一份**到 `server/backups/`（保留最近 90 份）。
想手动备一次：`npm run server:backup`；看现有备份：`npm run server:backup -- --list`。
「数据与备份」页导出的 JSON 是**跨系统搬运**用的（换机器、换数据库），也建议偶尔留一份。

> **备份由后端进程触发**（启动时补当天的份 + 每小时检查一次）。所以有两条边界要知道：
> ① 某天完全没开后端 → 那天不会产生备份（当天也没有新数据，风险很小，但你要知道它不"自动"）；
> ② 备份文件与数据库**在同一台电脑的同一个项目目录里** —— 它能救"误删/改坏数据"，
> 救不了"这台电脑坏了"。要防后者，得把导出的 JSON 定期存到这台电脑之外（第 13 节）。

**后端没开时**页面还能打开，但会提示连不上——**这不代表数据丢了**，库文件一直在。

> 逐页功能与数据链路已通过自动化验收（`npm run accept`，43/43）；
> 备份的**恢复能力**也演练过（`npm run drill:restore`：删库 → 只靠备份文件恢复 → 核对一致）；
> 但**界面的显示与交互**还没逐页人工确认过，用着别扭的地方请记下来。

## 第一次使用前，先做完这五步（新同事/换机器照这个走）

| # | 做什么 | 怎么确认做对了 |
| --- | --- | --- |
| 1 | 装好 Node（**22.6 以上**）并在项目目录里装依赖 | `npm install --cache ./.npm-cache` 不报错；`node -v` 显示 v22.6 以上。**电脑本身不用高配**：十年前的笔记本也够（依据见 [后端开发方案 §5.8](./后端开发方案.md)） |
| 2 | 两个终端分别起后端与前端（见上） | 后端终端出现「后端已启动」；浏览器打开 http://localhost:3000/admin 有登录框 |
| 3 | **把终端 A 打印的口令记到安全的地方**（或自己用 `NEXGENEDU_ADMIN_PASSWORD` 指定） | 能登录进后台；口令记在密码管理器/纸条上，不要只留在终端里 |
| 4 | 到**「课程库」页点一次「从网站同步课程」** | 课程库里出现课程；这时排课、报课、咨询的下拉里才选得到科目 |
| 5 | 到「数据与备份」**导出一次 JSON**，存到这台电脑之外（网盘/U 盘） | 机器坏了也有可搬回来的一份（日常备份只在同一台电脑上） |

> 第 3 步与第 4 步最容易漏：**口令只打印一次**（虽然也能在那个 json 文件里找到），
> 而**课程库不点同步就是空的** —— 空着的话，排课与报课的下拉里什么都选不到。

## 三条必须知道的边界（先看这个，只要 30 秒）

| 你要知道的事 | 意味着什么 | 你该怎么做 |
| --- | --- | --- |
| **数据在这台电脑的数据库文件里** | 文件是 `server/data/nexgenedu.db`：换电脑不会自动跟过去；这台电脑丢了、硬盘坏了，数据就没了 | 备份已经是自动的（每天一份，但和库文件在**同一台电脑**上）；换机器时用「数据与备份」导出 JSON 或复制库文件；要防电脑丢，请把导出的 JSON 存到这台电脑之外（第 13 节） |
| **登录是真校验了，但仍然只是"一个人用的门"** | 口令在服务端、不再写在网页里，未登录的接口一律 401；但系统目前**只有一个账号**，也没有"谁是谁"的权限区分 | 不要在系统里存身份证号、银行卡号这类敏感信息 |
| **「清空数据」会清掉业务数据** | 它不可撤销，会清空学生、排课、收款、课时流水（课程库与报价配置保留） | 动手前先导出备份（导入空库那条路会自动先备一份） |

另外：**档案类删除是真删**（学生 / 教师 / 教室 / 排课删了就没了）；而**课时与收款不提供删除**，只能通过「撤销」「退款」留痕处理 —— 这是刻意的，账不能凭空消失。

## 0. 五分钟上手

今天就能做完的四件事：

1. **登录**：打开后台地址 → 输入用户名 `admin` 与**终端 A 里打印的口令** → 点「登录」。
2. **建一个学生**：左侧「学生」→ 右上角「新增学生」→ 填**姓名**和**年级**即可 →
   保存（其余资料以后再补，建档只需要这两项）。
3. **给他排一节课**：左侧「课程安排」→「排课」→ 选日期、开始时间、时长、科目、教师、教室 →
   在「上课学生」里勾上他 → 点「排课」。表单会在保存前提示有没有冲突。
4. **记一次报课和收款**：进这个学生的详情 → 「报课与课时」页签 → 点「报课」→
   填科目、班型、课时数、单价、约定应缴、本次实收 → 点「确认报课」。

做完这四步，你已经把系统的核心（学生 · 教师 · 教室 · 课程 · 课时）跑通了一遍。

> 建议自己截图：在 `docs/screenshots/` 放几张自己的界面截图（例如 `home.png`、
> `lesson-form.png`），比文字更快教会新同事。

## 1. 登录与后台导航

**登录**：用户名 `admin`，口令由后端生成并打印（见上面「现在怎么用」）。
登录状态记在这台浏览器里，关掉再打开通常还在；**后端重启后需要重新登录**。
忘记密码：打开 `server/data/admin-credential.json` 能看到当初生成的口令（那是明文存的，
因为能读到这个文件的人本来就能读到数据库）；也可以停掉后端，用
`NEXGENEDU_ADMIN_PASSWORD=新口令 npm run server` 启动一次来换口令。

**左侧导航（15 项，按这个顺序）**：

| 导航 | 什么时候用它 |
| --- | --- |
| 今日概览 | 每天上班第一眼：今天谁上课、有没有课时要见底 |
| 咨询 | 新家长打电话/上门问「这个时间能不能排」 |
| 学生 | 建档、报课、收费、退课、看课时与记录 |
| 教师 | 教师档案、在职状态、可带科目、排课量 |
| 教室 | 教室与自习室的容量、可用时段、占用 |
| 课程库 | 课程的台账：网站课程 + 机构自己加的课（围棋、书法…） |
| 课程安排 | 排课、改课、标记已上、安排补课 |
| 日历 | 按天 / 按周看排课密度与空档 |
| 课表与占用 | 按周看某位老师的课表，或某间教室的占用 |
| 统计 | 教室利用率、教师课时、退课与流失 |
| 待跟进 | 系统挑出今天该联系谁，附话术草稿 |
| 话术 | 按场景摆好的沟通草稿：接待、报价、试课、请假、续费、欠费、退费… |
| 收费 | 本月收入、欠费清单、退费口径 |
| 报价 | 改价格与系数、给家长当场试算、算教师课时费 |
| 数据与备份 | 导出 / 导入数据、按需导出、看操作日志 |

## 2. 今日概览

打开就会看到四块数字：**今日课程 · 今日授课教师 · 学生档案 · 课时预警**。

- 「今日课程」里除了课程，还会列出**今天的空档**（课前 / 课间 / 课后，虚线浅底那几行），
  标题旁写明当天的空档合计（如「3 节 · 空 11 小时 30 分钟」）——
  想知道「今天还能不能加一节课、接一个学生」，看这里最快。
- 「课时预警」是今天最该看的一行：哪些学生课时快见底（阈值见第 10 节）。
- 想联系家长时，别在这里手动找 —— 直接去「待跟进」，那里把原因和话术都写好了。

## 3. 咨询：家长问「这个时间能不能排」

这是唯一一个「**先别答应，先算一下**」的页面。家长当场问「每周六上午十点，陈老师，先来 12 节行不行」，
以前只能凭印象回答，现在先登记再判定。

**登记字段**：学生姓名、年级、家长联系方式、想上的科目、每次时长、频率（每周一次 / 每两周一次）、
计划节数、从哪天开始、备注。

**候选时段**：可以加**多个**候选（星期 + 开始时间），点「+ 再加一个候选」。
家长如果说「我们周六上午或者周日下午都行」，两个都加上 —— 系统会依次尝试，第一个能排下的就用它。
另外可以标注**跳过某几周**（例如春节、考试周），课会顺延，总节数不变。

**点「登记并判定可行性」之后会看到**：

| 报告内容 | 含义 |
| --- | --- |
| 每个候选时段能不能排 | 检查的是**一整串日期**（每周一次 × 12 节 = 未来 12 个同一时段都得空着），不是只看某一天 |
| 不能排时，挡路的是谁 | 具体到哪节课 / 哪位老师 / 哪位已有学生 —— 因为接着要决定是让新学生换时段，还是去协调老学生 |
| 最接近的方案 | 排不下时给出的替代建议（换时段 / 换老师 / 换教室） |
| 「协调已有学生：把这节课挪走 →」 | 针对挡路的**已有课**给出可挪的时间（挪到哪里不会再撞，系统已经算过） |

**采用与放弃**：

- 可行的方案点「**采用这个方案**」→ 系统一次性把整串课建出来（12 节课一次成型，不用一节节点）；
  落库前会**再检查一次**，因为这中间可能有人排了别的课。
- 排不了就「**放弃**」并记下原因（线索状态：待确认 / 已安排 / 已放弃）。

> ⚠️ **采用方案前，先跟家长确认时段。** 采用后课就已经在系统里了。
> ⚠️ 采用之后，那串课里**还没有学生名单**（咨询时学生往往还没建档），
> 请到「学生」页建档，再把这节课的学生补选上。这是两个动作，别漏第二个。

## 4. 学生：建档、报课、收费、退课、课时

### 4.1 建档

「学生」→ 右上角「新增学生」→ **姓名 + 年级**就能建档（其余以后补）。
列表里能直接看到：姓名、年级、家长、状态、报读科目、剩余课时、「需提醒」标记。

### 4.2 学生详情有三个页签

| 页签 | 内容 |
| --- | --- |
| 报课与课时 | 报课、续费、收退款、退课、课时流水（账本） |
| 信息采集表 | 完整的学生资料采集表（按钮「填写采集表」） |
| 排课记录 | 他的每一节课（上过的、要上的、取消的） |

**信息采集表**分六节、当前共 **72** 项：一、基本与家庭信息；二、学业基础信息；三、学习行为与习惯；
四、排课相关信息；五、心理与情绪健康；六、健康与特殊需求。字段数量以后可能增减，
以页面上「填写采集表」实际显示的为准（字段是键值对存的，增减不影响老档案，读不到就是空）。

### 4.3 报课（最重要的一步）

「报课与课时」→「报课」→ 填表：

| 字段 | 说明 |
| --- | --- |
| 科目 | 与课程页的叫法一致（例如「初中数学」） |
| 班型 | 一对一定制课 / 一对二 / 一对三小组课 / 一对多小班课 / 大班课 / 晚托管… |
| 课时数 | 本次买的节数 |
| 单价 | 标价（元 / 节） |
| 约定应缴 | 与家长谈定的总额。可以低于标价（优惠），也可以高于实收（分期） |
| 本次实收 | 这次实际收了多少钱；填 **0** 表示先上课后付款 |
| 报课日期 / 备注 | — |

点「**确认报课**」后，这笔报课会同时产生：报课记录 + 课时余额 + （本次实收 > 0 时）一条收款流水。

**三个金额概念，别混**：

| 概念 | 怎么来的 |
| --- | --- |
| 标价 | 课时数 × 单价（机构挂牌价） |
| 约定应缴 | 与家长谈定的总额 |
| 实收 | **由收款流水累加得出**，不是手填的最终值 |

由此：**优惠 = 标价 − 约定应缴**；**欠费 = 约定应缴 − 实收**。

### 4.4 续费

同一条报课上的「续费」→ 加课时 + 同时收一笔款。续费不会新建一条报课，
而是把课时累加到原来那条上（余额连续，家长好理解）。

### 4.5 收退款（分期、补记）

用「**记收款**」「**记退款**」补记：分期付款、只收钱不加课时（例如材料费）。
付款方式可选：微信 / 支付宝 / 现金 / 银行转账 / 其他。

> ⚠️ **收钱记录在「学生」页，不在「收费」页。** 「收费」页是看报表和欠费清单的，
> 不是录入入口 —— 这一点新同事最容易搞错。

### 4.6 退课（先选退费口径，再看明细）

同一条报课上的退课流程，**先选口径**（页面会显示每种口径的算法与金额）：

| 口径 | 算法 | 什么时候用 |
| --- | --- | --- |
| **按实付比例退（默认）** | 实付 ÷ 总节数 × 剩余节数 | 最常见，对家长最好解释 |
| 追回已上课时的标价 | 实付 − 已上节数 × 标价 | 给过较大折扣、要防止「上完就退」 |

确认时有两个按钮：「**确认退课并退款**」和「**只退课，不退款**」（例如课时已经上完、或钱不退）。
退款会生成一条**退款流水**，报课记录标记为「**已退课**」（历史保留，不会消失）。

> ⚠️ 退课要改的是「账」，不是「删除记录」。退课后这条报课不能恢复，请核对清楚再点。

### 4.7 课时流水（账本）与撤销

每条报课下面就是它的**课时流水**：报课、续费、上课、调整、退课，每一笔都有时间和说明。

- 打了删除线并标「**已撤销**」的，是**不生效**的流水（不计入已用课时）。
- **没有「撤销」按钮**，也不需要：把课节状态从「已上」改回去、或者补录请假时间时，
  系统会**自动**按流水退回课时并留下撤销痕迹（不是删记录，账仍然可追溯）。

### 4.8 课时口径（背下来，家长问的时候不用猜）

| 问题 | 口径 |
| --- | --- |
| 剩余课时怎么算 | 总课时 − 已用课时（不会出现负数） |
| 已用课时怎么算 | 该报课下**有效的「上课」流水**合计 |
| 一节课扣哪条报课 | 找**同科目、仍在读**的报课；有多条时扣**剩余课时最多**的那条 |
| 找不到对应报课怎么办 | **不扣课时**，并明确提示「没有该科目的在读报课」——不会随便扣一条 |

## 5. 教师

字段：姓名、职务、可带科目、联系方式（列表里还有在职开关、今日本周课程）。

- **可带科目从课程库里勾选**（下拉里带搜索框，点一下展开、可多选；已选的会显示成小标签，
  点标签上的 × 就能去掉）。**不用手打**：手打最容易出现「围棋」和「围棋课」两个名字的同一门课，
  课时与统计就对不上了。课程库里没有的课，先到「课程库」里加一门。
- 可带科目在排课时有用：勾了科目的老师，排课选错科目会被提示；**没勾则不校验**（没登记不等于不能带）。
- 匹配规则是「科目名出现在课程名里」：填「物理」能命中「高中物理」。
- 教师信息是**数据驱动**的：新增一位老师、填上可带科目，课程页的「这门课谁带」就会自动出现他，
  不需要改代码。

## 6. 教室

字段：名称、用途（上课用教室 / 自习室）、容量、**可用时段**、备注。

- **可用时段**（点「+ 添加时段」）：选星期 + 起止时间，例如「周一–周五 17:00–21:00」。
- **不设任何可用时段 = 视为不限**（永远可以排）。自习室那种全天可用的就不填。
- 排课时如果课落在时段外，会提示「所选教室在该时段不开放」，并且**不允许保存**。
- 跨天时段不支持（机构的教室不会用到凌晨）—— 一行的结束时间必须晚于开始时间，否则那一行视为无效。

## 7. 课程安排：排课、标记已上、请假与补课

### 7.0 先有课程，才有排课（课程库）

排课时能选的科目、教师「可带科目」的候选、学生报课的科目，**都取自「课程库」**
（左侧导航 → 课程库）。它有两部分：

| 来源 | 怎么来的 | 能不能删 |
| --- | --- | --- |
| 网站 | 首次使用与点「从网站同步课程」时，网站课程页上的课自动进来 | 不能删（删了下次同步又回来）。不想再排就点「设为暂未开放」 |
| 后台 | 机构自己加的课（围棋、书法、编程这类网站上还没有的） | 可以删 |

- 要开一门网站上还没有的课：课程库 → 填课程名、分类（可以自己写一个新的，例如「兴趣才艺」）、
  可开班型、备注 → 添加。**添加后立刻能在排课、咨询、学生报课里选到它**。
- 两件容易误会的事：
  - 在课程库加课**不会**让宣传网站上多出一张卡片 —— 网站要展示得改内容文件（见内容维护手册）；
  - 课程名是**引用键**（排课、教师科目、报课记录都按名字记），所以课程名不能重复：
    系统会拦住重名，请把「围棋」和「围棋课」统一成一个叫法。
- 网站上新增了课程卡片之后，回这一页点一次「从网站同步课程」把它拉进来即可（不会动你改过的信息）。
- **和报价的关系**：课程库决定「能排哪些课」，报价页决定「这门课多少钱」。
  每门课下面写着它的报价状态（例如「报价 200 元/节（兴趣才艺）」或「未定价」）。
  没定价的课，到左侧「报价」→「课程库课程定价」里勾选课程、选一个阶段、填基础价即可。
  课程库里改了名字或设为暂未开放，报价配置会**自动跟着变**；删掉后台新增的课程时，
  报价里那一项会保留但自动停用（不会悄悄消失）。

> ⚠️ **先点一次「从网站同步课程」。** 这台机器上的课程库**现在是空的**（历史原因，不是坏了：
> 换成服务端数据库时库是新的，网站上的课程要手动同步一次才进来）。课程库空着的话，
> 排课、报课、咨询的下拉里都选不到科目 —— 到「课程库」页点一次「**从网站同步课程**」就补齐了，
> 之后不用再点。

### 7.1 排课

「课程安排」→「排课」→ 填：日期、开始时间、时长、状态、科目、班型、教师、教室、备注，
并在「**上课学生（已选 N 位）**」里勾选学生（**至少要选一位**，否则不能保存）。

保存按钮是「**排课**」（改已有的课时是「保存修改」）。

### 7.2 保存前系统会拦下这几种情况

| 情况 | 提示方式 |
| --- | --- |
| 同一**教师**时间重叠 | 提示与哪节课冲突（教师、教室、学生三类分开提示，因为处理方式不同） |
| 同一**教室**时间重叠 | 同上 |
| 同一**学生**被排了两节 | 同上 |
| 教室**不在可用时段** | 提示「该时段不开放」并禁止保存 |
| 学生数**超过场地容量** | 提示「学生数超过场地容量，请换场地或拆课」 |
| 教师**科目不符** | 教师登记了可带科目但不含这节课的科目时提示 |

**相邻不算冲突**：前一节 10:00–11:00、后一节 11:00 开始，是允许的。
**已取消的课不占时间**：取消了就不再挡别的课。

> ⚠️ 这些提示是**帮你先发现问题**，不是只在提交时才拒绝 —— 页面上改动时间/老师/教室就会实时提示。

### 7.3 标记已上（按出勤扣课时）

列表里每节课的「操作」列有「**标记已上**」（已经标记过的课不再显示这个按钮）。

- 点它时，系统按**每位学生的出勤**决定扣不扣课时，并写入课时流水。
- **幂等**：已经标记过的课再点一次**不会重复扣课时**（会提示「这节课之前已经标记过『已上』，没有重复扣课时」）。
- 课节状态只有三种：**已排 / 已上 / 已取消**。

> ⚠️ **把状态从「已上」改回「已排」或「已取消」时，已扣的课时会自动退回**（按流水撤销，留痕）。
> 也就是说「点错了」是可以救的，但会留下操作记录。

### 7.4 课堂记录（出勤 / 专注 / 互动）

每节课上可以给每位学生写课堂记录：**出勤**（到课 / 请假 / 旷课）、专注、互动、备注，
出勤选「请假」时会出现「**请假时间**」字段。

> **请假时间决定扣不扣课时**（见下）。老师请务必填 ——
> 不填的话，系统会按**临时缺课**处理（扣课时），因为「没记录」不能默认成对机构有利的解释。
> 补录之后课时会自动调整回来。

### 7.5 请假与补课：24 小时规则

一句话口径：**一节课扣一次，扣的是「这次时间被占用」。**

| 情况 | 扣课时 |
| --- | --- |
| 到课 | 扣 1 |
| **提前 24 小时（含）以上请假** | **不扣** |
| 临时请假（不足 24 小时）、旷课、请假但没记请假时间 | 扣 1 |
| 补课 | 扣 1（补课重新占用了老师和教室的时间） |

由此推出两个家长最常问的例子：

- **提前请假 + 补课 = 扣 1 节**（等于正常上了课）；
- **临时缺课 + 补课 = 扣 2 节**（缺课占了一次时间，补课又占一次）。

**安排补课**：在「课程安排」的待补课列表里点「**安排补课**」→ 填日期、开始时间、时长 →
点「**确认补课（扣 1 节）**」。补课课节会带上「补课 · 原课 X月X日」的标记，列表里一眼看得出。

> 「待补课」看的是**有没有上到课**，不是有没有扣课时 ——
> 所以提前请假（没扣课时）的学生，同样会出现在待补课里。

### 7.6 作业记录与阶段测评

- **作业记录**：科目、日期、正确率、本次错题知识点、提交情况（按时 / 迟交 / 未交）、备注。
- **阶段测评**：科目、测评日期、本次分数、薄弱知识点、备注。

这两项填了之后，「待跟进」才可能挑出「作业异常」「测评下滑」——
**不填就不会提醒**（系统不拿「没有记录」当「表现不好」）。

## 8. 日历与课表

- **日历**：按天 / 按周看排课密度与空档（**只读**，避免两处都能改导致冲突）。
- **课表与占用**：两个视角 —— 「按教师」（教师课表）/「按教室」（教室占用），按周切换；
  可以点「**导出本周课表（ICS）**」，老师在手机上导入日历就能看自己的课，不用来后台查。
- **空档会单独显示成虚线卡片**，三段各有各的说法：
  「上课前空 9 小时 30 分钟」（`08:00–17:30`）、「两节课之间空 30 分钟」（`18:30–19:00`）、
  「下课后空 1 小时」（`21:00–22:00`）。每天栏头还会给出**当天空档合计**
  （如「3 · 空 11 小时 30 分钟」），一眼看出哪天空、哪几天满。
  四条口径（都影响你怎么读它）：
  - **课前 / 课后按「上课时间」算**（取自内容里的「上课时间」字段，默认 8:00–22:00）：
    机构改上课时间，头尾两段跟着变；课排在窗口之外时不会凭空生出空档；
  - **已取消的课不算占用**：所以取消一节课后，空档会把两边连成一整段；
  - **时间重叠的课之间不会显示空档**（说明这两节课排重了，要去课程安排里核对）；
  - **一节课都没有的那天不显示空档卡片**（整天空着由「空档」空状态表达），
    因此那种日子栏头也不会显示空档合计。

## 9. 统计（数字的口径）

「统计」页回答的是决策问题：这间教室值不值、谁排满了、学生在什么阶段退。

| 指标 | 口径 |
| --- | --- |
| 教室利用率 | 已排时长 ÷ 可用时长。教室**设了可用时段**就按时段算；没设的按**上课时间**估算（每天 8:00–22:00，**14 小时** × 7 天）。已取消的课不占时间 |
| 空档日 | 该教室有可用时段、但这天一节都没排 |
| 教师课时 | 按教师汇总已排/已上的课时量 |
| 退课与流失 | 已退课报课数、退课时平均已上节数、退掉的剩余课时、暂停/结课学生 |

> 注意：利用率的分母用的是**上课时间（8:00–22:00）**，不是前台的**营业时间（9:00–21:00）**——
> 教室能不能用取决于「这个时段能不能上课」，不是「前台有没有人」。

## 10. 待跟进：今天该联系谁

打开就是清单，不用自己想。每一条都带：等级（紧急 / 提醒 / 关注）、原因（带具体数字）、
建议动作、以及一段**可直接复制的沟通话术**。顶部有「复制话术」「复制整份清单」。

**触发规则与阈值**（全部集中在一处，要调松紧只改一处）：

| 类型 | 触发条件 |
| --- | --- |
| 课时不足 | 某科目剩余课时 **≤ 5 节**（**≤ 2 节** 标为紧急） |
| 欠费 | 约定应缴 − 实收 **> 0**（标为紧急） |
| 久未排课 | 还有剩余课时，但**未来 7 天**一节课都没排 |
| 作业异常 | 最近 **5** 次作业里，「未交」≥ **2** 次，或「未交 + 迟交」≥ **3** 次 |
| 测评下滑 | 最近一次比上一次**低 10 分**及以上（低于 10 分只标「关注」） |
| 出勤异常 | 最近 **5** 次记录里，旷课 ≥ **1** 次（提醒）或请假 ≥ **2** 次（关注） |

### 10.1 话术专区（按场景直接复制）

左侧「话术」页把机构日常要说的话按 11 个场景摆好了（接待 / 报价 / 试课 / 排课 / 请假 /
续费 / 欠费 / 反馈 / 投诉 / 退费 / 教师），一共 30 多条，每条都写清了**什么时候用**、
**该说什么**、**不该说什么**。用法：

1. **先筛**：顶部按场景点分组，或用搜索框搜内容（例如搜「24 小时」「手续费」）；
2. **想套用到具体学生**：在「套用到某个学生」里选学生（有多个在读科目的再选科目）——
   话术里的 `{学生}` `{科目}` `{剩余课时}` 会自动填好；
3. 卡片右边点「**复制**」，粘到微信里；缺的占位符会在卡片上标红提示（例如 `{老师}` `{时间}`），
   提醒你补上再发；
4. 一次要发很多条时，点「复制全部」复制当前筛选结果（带分组标题）。

三条要知道的：

- 这些话术的**规则口径与系统一致**（提前 24 小时请假不扣课时、试课满 10 节免费、
  只报 1 节加收 10%、退费默认按实付比例退）—— 改了规则代码后话术会跟着一起更新；
- 里面**不会出现内部信息**（教师分成、机构留存这类内容一条都没有），可以放心转发；
- 但**它仍然是草稿**：称呼、时间、语气请按这位家长改两句再发。

> ⚠️ **话术是草稿，不是定稿。** 里面填好了具体数字，但发之前请自己看一遍、按这位家长的语气改两句 ——
> 别让家长收到机器味的话。

## 12. 报价：改价格、给家长试算、算教师课时费

### 12.1 四个价格维度（先理解这张表，后面都靠它）

| 维度 | 含义 | 默认 |
| --- | --- | --- |
| **基础价** | **一对一、1 小时、报 2 节及以上**的价格（元 / 节）—— 所有换算的基准 | 分阶段设定 |
| **科目系数** | 同一阶段里不同科目的差异 | 1.0（不加价） |
| **班级系数** | 人越多每人越便宜 | 一对二 0.7、一对三 0.6、一对多 0.5 |
| **时长乘数** | 一节课上多久（1 小时为基准） | 1 / 1.5 / 2 小时 → ×1.0 / ×1.5 / ×2.0 |

再加上两条规则：**手续费**（只报 1 节时加收，默认 10%；报 2 节及以上不加收）、
**试课**（报课后满 10 节则试课免费，否则按课程原价收 1 节试课费）。

两个**不是乘系数**的例外：

- **班课（9-20 人）**：按「教师课时总费用 ÷ 班级人数」分摊，不用班级系数；
- **试课费**：永远按课程**基础价原价**收，不带科目系数、班级系数、时长与手续费。

### 12.2 给家长试算

「报价」页上半部分：选课程、科目、班型、每节课时长、报课节数（**节数手动填**），
点「算一下」→ 显示**课单价 / 节**、正课总价、试课费、**总价**，以及每一项是怎么来的。

### 12.3 教师分成（教师课时费）

课内课程里**按系数计价**的班型（一对一定制课 / 一对二 / 一对三小组课 / 一对多小班课，1–8 人）适用：

```
教师课时费 = 小时数 × (课程单价 / 小时) × (0.4 + (学生人数 − 1) × 0.1)
```

人话就是：**第一名学生 40%，此后每多一名学生加 10 个百分点**（2 人 50%、3 人 60% … 8 人 110%）。
时长按实际小时数乘（1.5 小时乘 1.5）。

- 公式里的「课程单价」默认取**课程标准单价**（基础价 × 科目系数，不含班级人数折扣），
  也可以在页面上切成**班型课时价**（再乘班级系数）。切换**不影响家长看到的报价**。
- **9 人以上大班课不适用**这条规则：那类按「教师课时总费用 ÷ 班级人数」另议，页面上会直接说明。
- 页面上的「**人数对照表**」把 1–8 人各自的**分成比例 / 教师课时费 / 机构留存**列出来，
  老师问「这个班我拿多少」直接看表。试算结果里也会显示教师课时费与机构留存。

### 12.4 改价格

下半部分可以直接改：基础价（每门课）、科目系数、班级系数、课时时长、手续费、试课门槛、
教师分成（基准分成 / 每加一名学生 / 单价口径）、其他项目。

点「**保存修改**」。改完请**再用试算器核对一遍** —— 页面上会做合法性检查
（系数必须是正数、手续费 0–100、课程名不能重复），不合法的配置**存不进去**。

> ⚠️ **改价不会自动上线。** 后台的价格存在**服务端数据库**里，它不会写回网站的内容文件；
> 而家长看到的报价页读的是 `data/site/pricing.md`。所以必须点「**导出配置**」，
> 把导出的内容替换进 `data/site/pricing.md`
> （替换「## 学习阶段」及其后的部分，**页面文案字段不要动**），再提交发布，家长页面才会更新。
> 改过、还没导出的配置会显示「后台修改（未导出上线）」。

## 13. 数据与备份

**先说清谁在备份**：后端**每天自动备份一份**到 `server/backups/`，保留最近 **90 份**（约三个月），
**不需要你做任何事**（后端一启动就先把今天的份补上，之后每小时检查一次 —— 只要后端开着就不用管它）。
想手动备一次：`npm run server:backup`；看现有备份清单：
`npm run server:backup -- --list`。这套备份的**恢复能力演练过**（`npm run drill:restore`：
它自己起一个临时库，删库后只用备份文件恢复再核对一致，**不会碰真实数据**）。

页面上这些按钮，是给你**「要带走一份给别人 / 放到别处」**用的：

| 按钮 | 作用 |
| --- | --- |
| 导出全部数据（JSON） | **完整备份**（档案、报课、流水、记录、收款），也是换机器 / 换数据库时搬运用的文件 |
| 导出学生名单（CSV） | 只有学生名单，方便用 Excel 看 |
| 导出全部课程（ICS 日历） | 课表进手机日历 |
| 导入 | 用备份文件覆盖当前数据（**整体替换，不是合并**） |
| 恢复导入前的数据 | 导错了以后的后悔药 |
| 清空日志 | 只清操作日志，**不动**学生、排课、收款这些业务数据 |

> ⚠️ **导入是唯一能一次性毁掉全部数据的操作。** 它有三道保险：结构校验（不合格直接拒收、不动现有数据）、
> **导入前自动备份**、一键恢复。即便如此，导入前请自己再导出一份 JSON 放好。

> ⚠️ **自动备份和数据库在同一台电脑上。** 所以「这台电脑丢了 / 硬盘坏了」这种情况，
> 自动备份救不了你 —— 请**每周手动导出一次 JSON，并存到这台电脑之外**（网盘、U 盘、另一台机器）。
> 换电脑前也一定先导出。

> **页面上没有「重置示例数据」这个按钮了。** 那是早期纯前端阶段的临时功能（点一下会把机构真实数据
> 换成演示数据，很危险），已经撤掉。现在想「从零开始录真实数据」，走的是导入一份空库 JSON 这条路
> （这条路会先自动帮你备一份）。

### 13.1 按需导出（只导一部分）

「数据与备份」页有「按需导出」：**选数据集 → 选行 → 选格式 → 导出**。

- 数据集：学生 / 排课 / 教师 / 教室 / 课程 / 报课记录 / 收款记录 / 课堂记录；
- 选行：**不勾任何行 = 导出该数据集的全部**；勾了几行就只导这几行（顶部会写「共 N 条，已选 M 条」）；
- 格式：CSV（给 Excel）、JSON（给别的系统）；**排课**还可以导 ICS 直接进手机日历，
  **课程**可以导 Markdown —— 那是内容文件里的卡片行，粘进 `data/site/content.md` 的课程栏目即可；
- 常用场景：把某位老师的课导出来发给他（排课 → 搜索老师姓名 → 全选当前结果 → ICS）；
  把没定价的课导出来核对（课程 → CSV）；把某个月的收款导给会计（收款记录 → JSON/CSV）。

导出完成后请看一眼提示里的「已导出 M 条（共 N 条）」——如果 M 小于 N，说明你只导了一部分。

### 13.4 批量导入：把表格里的名单一次录进来

学生、教师、教室、课程都支持**批量导入**（CSV 或 JSON）。**两个入口，功能完全一样**：

- **各个页面上（推荐）**：「学生 / 教师 / 教室 / 课程库」页右上角，紧挨着「新增…」按钮
  有一个**次要样式的「批量导入」按钮**，点开就是导入面板 —— 这里的导入对象已经定好，
  不用再选（你正看着那份名单，导它就是了）；再点一次收起。
- **「数据与备份」页**：那里也有一个「批量导入（CSV / JSON）」面板，可以**切换导入对象**，
  适合一次处理几种数据；面板默认收起，不会占着页面。

**四步**：

1. **选对象**（在「数据与备份」页要选；在各实体页不用选）→ 点「下载 CSV 模板」或「下载 JSON 模板」；
2. **填数据**：模板第一行是表头（**列名不要改**），第二行是示例（可删）；存成 .csv 即可。
   - 用 Excel / 数字表格填写没问题：中文列名、`是/否`、用 `|` 或 `、` 分隔多个值都能识别；
   - 也可以**不存文件**：在表格里复制一块，直接粘进面板的文本框；
3. **看预览**：面板先说清"识别到几列 / 可导入几条 / 哪几行不通过（带行号与列名）"，
   改完再导；
4. **点「导入」**：显示"新增 N 条，跳过 M 条（已存在）"。

### 13.5 导入遇到同名怎么办（覆盖 / 跳过 / 保留两份）

导入**默认不会偷偷改你的数据**：点「检查并导入」时，它先**体检**一遍 —— 如果发现同名记录，
会把这 N 条列出来（显示"文件里那条"与"库里已有那条"），**此时一个字节都没写**，然后让你选：

| 选择 | 会发生什么 | 什么时候用 |
| --- | --- | --- |
| **跳过**（默认） | 保留库里那条，忽略文件里这条 | 库里已经录好，只是文件里有重复 |
| **覆盖** | 用文件里的值**更新**库里那条（id 不变，是更新不是新建） | 文件是更新过的版本，要以文件为准 |
| **保留两份** | 两条都留：第二条加序号后缀（王老师 → 王老师（2）） | 确实是两个人 / 两间房，或想留档对比 |

- 可以先选「**全部这样处理**」，也可以**逐条**改（一行一选）；选完点「按以上选择导入」；
- 选之前随时可以「取消」，库里不会有任何变化；
- **覆盖只改文件里真的填了值的字段**：文件里空着的格子不会把库里已有内容清掉；
  报课记录、采集表、可用时段这些**结构性数据也绝不会被导入覆盖**；
- 「保留两份」对**学生**不加后缀（同名同家长可能是兄弟姐妹 —— 那是真实数据，不能改）；
- 不确定时选「跳过」：那是最安全的，之后到对应页面手工改也很快。

**四条要记住的规矩**：

| 规矩 | 说明 |
| --- | --- |
| **默认只新增，不覆盖** | 同名记录先列出来问你（上面那三个选择），你不选就不会动已有数据 |
| **重复导入是安全的** | 同一份文件再导一次：新增 0 条、全部同名待你处理，不会翻倍 |
| **导入前自动留一份快照** | 导错了可以到「数据与备份」页的「恢复导入前的数据」回退（注意：**只回退最近一次**导入） |
| **报课、收款、课时不在这里导入** | 那些牵动账本（实收、已用课时），必须在学生的「报课与课时」页走正规流程 —— 一次导入几百条"看起来对"的账，是最难查的事故 |

### 13.6 从网站（前端内容）导入教师与场地名

网站上现成有两份**真实**名单，不必手录：

- **教师页的真实教师**（在「教师」页点「批量导入」→ 面板里的「从网站导入」）；
  **AI 智能体不会被导进来**（它们不排课，也不该出现在教师档案里）；
- **首页「教室照片格位」里的场地名**（301 教室、302 教室、自习区…）（在「教室」页同理）；
  名字里带「自习」的会按**自习室**导入，其余按上课教室；**容量与可用时段要导入后自己填**。

课程不用这样做 —— 它已经有「**从网站同步课程**」按钮（在课程库页），作用一样。
学生网站上没有，所以没有这个入口。

「从网站导入」同样走**体检 → 你选 → 写入**这套流程（见 13.5），不会直接改掉已有记录。

**导入后还要做的事**：教室的**可用时段**要单独设（「教室」页；不设 = 不限）；
教师的**可带科目**要与课程库里的课程名一致，否则排课时会提示「教师科目不符」。

## 14. 全局搜索与操作日志

- **全局搜索**（后台顶栏）：一个框搜五类对象 —— 学生 / 教师 / 教室 / 排课 / 课程。
  只做「不区分大小写的包含匹配」，不做拼音或模糊匹配：「张」和「章」是两个人。
- **操作日志**（数据与备份页）：记录「谁、什么时候、改了什么」，例如改价、挪课、安排补课。
  操作人取自当前登录账号（由**服务端**按会话记录，前端说了不算）。

> ⚠️ 日志是**草稿性质**的：它存在**服务端数据库**里（库文件就在这台电脑上，`server/data/nexgenedu.db`），
> 能打开库文件的人就能改。想要不可篡改的审计记录，需要另做（例如把日志同步到别的机器）。

## 15. 出错了怎么办

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 打开后台看不到数据 | 后端没在跑（页面会提示连不上），或后端连到的不是你以为的那个库 | 看终端 A 是否在跑 `npm run server`、页面顶部是否显示「**已连接后端**」；**换电脑或清缓存都不会丢数据**（数据存在服务端数据库里，不在浏览器里） |
| 忘了口令 / 口令提示不对 | 口令由后端生成，**不在网页代码里**，网页上查不到 | 打开 `server/data/admin-credential.json` 看；或停掉后端，用 `NEXGENEDU_ADMIN_PASSWORD=新口令 npm run server` 启动一次换掉（见第 1 节） |
| 用着用着被弹回登录页 | 后端重启过（登录状态不落盘，这是刻意的） | 重新输入用户名 `admin` 与口令即可 |
| 在线上站点打开后台（线上地址 + `/admin`）登不进去 | 线上是给家长看的静态站，那份后台连不上本机后端，会显示「后台需要本机后端」 | 后台只能在本机用：打开 http://localhost:3000/admin |
| 保存排课时提示冲突 | 教师 / 教室 / 学生时间重叠 | 页面上会说明和哪节课冲突：换时间、换人或换教室 |
| 提示「所选教室在该时段不开放」 | 课落在教室可用时段之外 | 换教室、改时间，或去「教室」页补一段可用时段 |
| 提示「学生数超过场地容量」 | 勾选的学生多于教室容量 | 换大教室，或把这节课拆成两节 |
| 学生课时该退回来 | 课节状态改错、或请假时间没填 | 把状态从「已上」改回「已排」，或补录请假时间 —— 课时会自动退回并留痕 |
| 标记已上没扣课时 | 可能已标记过（幂等，不重复扣）；或该科目没有在读报课 | 看课时流水与提示；没有报课记录就先报课 |
| 家长说「这个时间能不能排」但候选项都被否 | 挡路的是已有课 | 用报告里的「协调已有学生：把这节课挪走」，或改用最接近的方案 |
| 改了报价但家长页面没变 | 后台改价不会自动上线 | 点「导出配置」→ 替换 `data/site/pricing.md` → 提交发布 |
| 报价算出来是 0 或很奇怪 | 配置被改坏（系数填 0 等） | 重新保存配置（非法值存不进去），或点「恢复为站点内容」 |
| 数据被清空了（有人跑了清空脚本、或导入了空库） | 业务数据被整体清掉（课程库与报价配置会保留） | 先别录新数据：用「数据与备份」导入最近一次 JSON；后端每天也自动备了一份，可请技术同事从 `server/backups/` 里找回（见第 13 节） |

## 15.1 连不上后端怎么办（看状态信号 + 手动指定地址）

后台**右上角**（登录页上则是在表单上方）有一个**后端状态信号**，它显示的是**真实探活结果**，
不是"配了就当作连着"：

| 显示 | 含义 | 该怎么办 |
| --- | --- | --- |
| 后端：已连接 · 数据库 v2 | 探活通过，且已登录，数据库与最近备份都正常 | 无需处理 |
| 后端：已连接（未登录…） | 后端活着，但还没登录，数据库细节看不到 | 正常登录即可 |
| 后端：检查中… | 正在探活 | 等一下；点开可手动"重新检查" |
| **后端：连不上** | 探活失败（后端没跑 / 地址或端口不对 / 端口上跑着别的程序） | 点开看原因，或手动填地址 |

点开这个信号，里面有：

- **当前地址**，以及它是"界面手动指定"还是"构建期配置"来的；
- **重新检查**：立刻再探一次；
- **自动探测本机**：依次试 `localhost:4000`、`127.0.0.1:4000`、`4001`、`4002`，
  找到第一个**自报为本系统后端**的地址并记住它 —— 端口上跑着别的程序时**不会被误判**；
- **手动指定地址**：直接填，例如 `http://localhost:4000`。

改完地址要**刷新页面**才全局生效（页面加载时才会决定"走本地还是走后端"）。

> ⚠️ 填**非本机**地址（例如局域网里另一台机器）时，登录口令会发到那台机器 ——
> 只有确认那是你自己的机器时才这么做，界面上会一直显示提醒。
>
> ⚠️ **端口号一定要看终端里打印的那行**：前端默认 3000，被占用时会自动换成 3001，
> 而后端默认 4000。前端地址与后端地址是两个东西，别混。

### 15.2 点某个按钮后页面跳回顶部

这是**界面在刷新时把整个列表换成了"加载中…"**造成的：页面高度一下子从很高塌成一行，
浏览器只好把滚动位置拉回顶部，等数据回来你就得重新往下滑。

已修的地方：**课程库**里「设为开放 / 设为暂未开放」「从网站同步」「保存编辑」「删除」「批量导入」
这些"就地动作"都不会再清空列表（课程库的开放状态切换还改成**就地更新那一条**，连重载都不发生）。

如果别的页面以后出现同样的情况，判断方法很简单：**点一下按钮，看列表是不是短暂变成一行"加载中…"**。
是的话就是同一个原因 —— 让"刷新时不替换已有内容"即可（首屏加载仍然显示加载态，那是正常的）。

## 16. 术语速查

| 术语 | 意思 |
| --- | --- |
| 后端（服务端） | 在你这台电脑上跑着、管数据库的那个程序（终端 A 的 `npm run server`）。后台要能干活，它必须开着 |
| 数据库文件 | `server/data/nexgenedu.db` —— 所有业务数据真正存放的地方（**不在浏览器里**） |
| 自动备份 | 后端每天自动存一份到 `server/backups/`（保留 90 份），见第 13 节 |
| 报课记录 | 一个学生一门课的一条账：总课时、已用、单价、约定应缴、实收 |
| 课时流水（账本） | 课时的每一笔变动（报课 / 续费 / 上课 / 调整 / 退课），撤销不是删除 |
| 到课 / 请假 / 旷课 | 出勤的三种情况，直接决定扣不扣课时（24 小时规则） |
| 补课 | 因为学生缺课而另外安排的课，扣 1 节，会标出原课日期 |
| 待补课 | 缺了课还没补的学生（包括提前请假没扣课时的） |
| 班型 | 一对一定制课 / 一对二 / 一对三小组课 / 一对多小班课 / 大班课 / 晚托管 / 预习课… |
| 标价 / 约定应缴 / 实收 | 见 4.3 的三个金额表 |
| 口径 | 同一个数字按不同算法算出来的结果，例如两种退费口径 |

## 17. 现在做不到的事（别白等）

| 你可能会想要 | 现状 |
| --- | --- |
| 多人同时用、各自账号 | 不行。只有一个账号 `admin`，也没有并发控制（两人同时改同一份数据会互相覆盖） |
| 手机 / 平板上用 | 页面能开，但后台是按电脑屏幕设计的高密度表格，手机上会难用 |
| 在外面（家里、校区外）用后台 | 不行。后台只在这台电脑上跑，数据也不上公网；线上那份后台连不上后端，登不进去 |
| 家长自己查课时 / 线上支付 | 没有做（V1 明确不做支付与家长端） |
| 改完价格直接自动生效 | 需要「导出配置 → 替换内容文件 → 提交发布」，见 12.4 |
| 误删学生 / 教师 / 教室后恢复 | 做不到（是真删）。课时与收款反而不能删，只能撤销 / 退款 |
| 云端备份（电脑丢了也能恢复） | 没有。后端每天在本机自动备份一份，但备份和数据库在**同一台电脑**上；要防电脑丢，得自己把导出的 JSON 放到别处（见第 13 节） |

> 上面这些不是「以后再说」，而是当前阶段的边界：这套后台已经接上**真实服务端**
> （SQLite + 服务端会话认证 + 每天自动备份），但它按**单用户本机使用**来设计。
> 多人同时用、按人分权限、远程访问，要等真的需要时再做（见 docs/后端开发方案.md §7）。
