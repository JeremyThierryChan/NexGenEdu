# 教务后台使用手册

> **给谁看**：辅导机构的前台 / 教务老师。不需要懂技术，不需要问开发。
>
> **怎么用**：不需要从头读到尾。**第 0 节是五分钟上手**，先照着做一遍；
> 之后遇到具体事情，直接跳到对应那一节（按「你今天要做什么」分节，不按系统模块分）。
>
> **阅读顺序建议**：
> 1. 第 0 节（五分钟上手）+ 第 1 节（登录）；
> 2. 你每天最常做的三件事：第 7 节（排课）、第 4 节（报课与收费）、第 12 节（报价）；
> 3. 其余章节按需查；第 15 节是「出错了怎么办」，第 17 节是「现在做不到的事」。

## 现在怎么用（本机 + 后端数据库）

**每天开两个终端**（进了项目目录）：

```bash
npm run server     # 终端 A：后端（数据存 SQLite）
npm run dev        # 终端 B：前端
```

然后打开 **http://localhost:3000/admin**，用账号 **`admin`** 登录。

> ⚠️ **地址以终端里打印的那行为准。** Next 默认用 3000，但**如果 3000 已被别的程序占用
> （哪怕是你另一个项目），它会自动改用 3001、3002…**，终端会打印
> `- Local: http://localhost:3001`。这时你打开 3000 看到的是**别的程序**的页面 ——
> 在那儿怎么输口令都进不了这个后台，还很容易误以为"密码不对"。
> 判断方法：本项目后台的标题是「NexGenEdu 教务后台」。

**密码从哪来**：第一次启动后端时，它**自己生成一个随机口令并打印在终端 A 里**，
像这样：

```
[登录] 账号：admin（口令来源：本次新生成）
[登录] 本次新生成的口令：xxxxxxxxxxxxxxxx
[登录] 已存到 server/data/admin-credential.json（权限 0600，重启后继续有效）
```

- 把那行口令记下来（也可以直接打开 `server/data/admin-credential.json` 看）；
- 想自己定口令：启动时加环境变量，例如
  `NEXGENEDU_ADMIN_PASSWORD=你的口令 npm run server`；
- **如果找不到 `admin-credential.json`**：说明后端是用 `NEXGENEDU_ADMIN_PASSWORD`
  启动的（那种情况口令来自环境变量，不会落文件），或者这台机器上还没启动过后端。
  这时用启动时给的那个口令；忘了就删掉该文件并用环境变量重新启动一次来换口令。
- **密码只在服务端**（不再写在网页代码里），所以源码公开也不影响；
- 后端重启后需要**重新登录**一次（登录状态不落盘，这是刻意的）。

- 页面顶部若显示「**已连接后端**」→ 你录的数据进服务端数据库，换设备/清缓存都不会丢；
- 若显示「**线上静态站点**…」→ 这个页面没有连上后端（没设置 `NEXT_PUBLIC_API_BASE`）：
  检查终端 A 是否在跑、前端是否重启过。

**备份**：后端**每天自动备份一份**到 `server/backups/`（保留最近 90 份）。
想手动备一次：`npm run server:backup`；看现有备份：`npm run server:backup -- --list`。
「数据与备份」页导出的 JSON 是**跨系统搬运**用的（换机器、换数据库），也建议偶尔留一份。

> **备份由后端进程触发**（启动时补当天的份 + 每小时检查一次）。所以有两条边界要知道：
> ① 某天完全没开后端 → 那天不会产生备份（当天也没有新数据，风险很小，但你要知道它不"自动"）；
> ② 备份文件与数据库**在同一台电脑的同一个项目目录里** —— 它能救"误删/改坏数据"，
> 救不了"这台电脑坏了"。要防后者，得把导出的 JSON 定期存到这台电脑之外（第 13 节）。

**后端没开时**页面还能打开，但会提示连不上——**这不代表数据丢了**，库文件一直在。

> 逐页功能与数据链路已通过自动化验收（`npm run accept`，56/56）；
> 备份的**恢复能力**也演练过（`npm run drill:restore`：删库 → 只靠备份文件恢复 → 核对一致）；
> 但**界面的显示与交互**还没逐页人工确认过，用着别扭的地方请记下来。

## 第一次使用前，先做完这五步（新同事/换机器照这个走）

| # | 做什么 | 怎么确认做对了 |
| --- | --- | --- |
| 1 | 装好 Node（**22.6 以上**）并在项目目录里装依赖 | `npm install --cache ./.npm-cache` 不报错；`node -v` 显示 v22.6 以上。**电脑本身不用高配**：十年前的笔记本也够（依据见 [后端开发方案 §5.8](./后端开发方案.md)） |
| 2 | 两个终端分别起后端与前端（见上） | 后端终端出现「后端已启动」；浏览器打开 http://localhost:3000/admin 有登录框 |
| 3 | **把终端 A 打印的口令记到安全的地方**（或自己用 `NEXGENEDU_ADMIN_PASSWORD` 指定） | 能登录进后台；口令记在密码管理器/纸条上，不要只留在终端里 |
| 4 | 到**「课程」页 → 课程台账页签**看看有没有课 | 新装系统时内容文件里的卡片已经作为**初始数据**进库了；缺哪门课就在这一页直接「填写新课程」加一门 |
| 5 | 到「数据与备份」**导出一次 JSON**，存到这台电脑之外（网盘/U 盘） | 机器坏了也有可搬回来的一份（日常备份只在同一台电脑上） |

> 第 3 步与第 4 步最容易漏：**口令只打印一次**（虽然也能在那个 json 文件里找到），
> 而**课程台账不点同步就是空的** —— 空着的话，排课与报课的下拉里什么都选不到。

## 三条必须知道的边界（先看这个，只要 30 秒）

| 你要知道的事 | 意味着什么 | 你该怎么做 |
| --- | --- | --- |
| **数据在这台电脑的数据库文件里** | 文件是 `server/data/nexgenedu.db`：换电脑不会自动跟过去；这台电脑丢了、硬盘坏了，数据就没了 | 备份已经是自动的（每天一份，但和库文件在**同一台电脑**上）；换机器时用「数据与备份」导出 JSON 或复制库文件；要防电脑丢，请把导出的 JSON 存到这台电脑之外（第 13 节） |
| **现在是多账号、按角色分权的** | 口令在服务端、未登录一律 401；不同角色看到的后台不一样，越权操作会被服务端拒（403）。**行级范围也已落地**：普通教师的账号只看得到**自己带的课与自己课上的学生**（别人的学生、别人的课表、钱都看不到），老 REST 接口对教师整条关闭 | 给老师开账号**必须绑对教师**（在「账号」页的下拉里选人，不用抄 id）；没绑或绑错他会**什么都看不到**（后台顶部有提示说清原因）—— 怎么开账号见「账号怎么建、口令忘了去哪看」一节 |
| **「清空数据」会清掉业务数据** | 它不可撤销，会清空学生、排课、收款、课时流水（课程库与报价配置保留） | 动手前先导出备份（导入空库那条路会自动先备一份） |

另外：**档案类删除是真删**（学生 / 教师 / 教室 / 排课删了就没了）；而**课时与收款不提供删除**，只能通过「撤销」「退款」留痕处理 —— 这是刻意的，账不能凭空消失。

还有一条和"网站"有关的（细节见 [技术架构 §5.1](./技术架构.md)）：
**宣传网站上"库里才有的那五块" —— 教师页、课程卡片、课程正文、报价、学生案例 ——
在"能连上后端"时就以数据库为准**；你在后台改了它们，**重新构站一次**（`npm run build`）
网站就跟着变。三条口径：

- **连得上后端** → 那五块用库里的。某一块在库里是空的（没人在教师页勾「在宣传网站展示」、
  课程库没填「卡片路径」、课程正文还没导入、报价还没配、案例全删了），**那一块就是空的**；
  空的那些会在构建日志里点名，并说清去哪补；
- **连不上后端**（没起后端、或构站那台机器上没有后端）→ **那五块是空的**
  （机构确认的口径：需要后端数据的地方，没连上就该是空的，不拿模版顶上 ——
  否则分不清看到的到底是库里的还是文件里的）；
- **首页文案 / 关于 / 联系 / 常见问题 / 时间安排 / 特色课程 / 品牌与联系方式**不在库里，
  **永远来自 `data/site/*.md`**，与后端连不连无关。

构建日志里会打印一行「本次网站数据来源：**后端** / **空白** / **模版**」，
用后端时逐块报数，一眼能看出用的是哪一份。想在本机看模版那一份：
`SITE_CONTENT_SOURCE=template npm run dev`。

## 谁能做什么：角色与权限（**已落地**，含"只看自己的"行级范围）

**现在的真实情况**：账号不再只有一个，**权限由服务端按角色拦**（越权一律 403，前端藏起来不算数）；
而且从 Phase B 起**还有一层"行级范围"**：普通教师登录后**只看得到自己带的课与自己课上的学生** ——
全校学生名单、别人的课表、**钱**（收款 / 欠费 / 报课金额）都不在他的后台里（请求只会得到空结果）。
口径的完整说明（哪些接口受影响、金额为什么被剥掉）见
[后台API约定 §三 行级范围](./后台API约定.md)。

> **给老师开账号时必须在「账号」页给他绑对教师档案**（下拉里选人，不用抄 id）——
> 没绑或绑错的后果见下面「账号怎么建、口令忘了去哪看」那一节。

**四个角色**：

| 角色 | 定位 | 能做什么 | 看不到 / 不能做什么 |
| --- | --- | --- | --- |
| **普通教师** | 只关心自己的课 | 今日概览（自己的课）、自己的课表与日历、**标记已上**、课堂记录（出勤 / 专注 / 互动）、作业记录、阶段测评、请假与补课登记，**以及自己学生的课时余额**（机构确认：家长常直接问任课老师"还剩几节课"，这个数字要给） | 学生档案里的**钱**（报课金额、收款、退款）、退课、报价、教师 / 教室 / 课程库维护、数据与备份、操作日志、**别人的学生** |
| **招生老师** | 把家长接进来、把课报上 | 咨询线索与可行时段判定、待跟进与话术、学生建档、**报课（科目 / 课时 / 班型 / 教师）**、改报课、收款、报价试算、排课与调课、**以及退课**（机构确认：招生也要能退课）、**「网站内容」页里的学生案例**（见 §7.7） | 改价、教师 / 教室 / 课程库维护、**课程正文**（课程库页里那一块）、数据与备份、操作日志 |
| **财务管理员** | 管钱与账 | 收款 / 退款与分期补记、**退课与退费口径**、欠费清单与收费报表、课时账本（流水与撤销）、报价维护（改价），**以及学生建档与报课**（机构确认：财务也要能建档、能报课） | 教师 / 教室维护、数据与备份、操作日志 |
| **技术管理员** | 全权限 | 全部：账号与权限、教师 / 教室 / 课程库、报价配置、数据与备份（导出 / 导入 / 重置 / 恢复）、批量导入、操作日志、后端运维 | — |

**一个账号可以兼任多个角色**（机构确认）—— 例如校长既是财务管理员又是技术管理员。
因此权限是按**角色集合**判定的：只要你的角色里有一个允许，这件事你就能做。
**兼任多角色的账号不受行级范围限制**：给了更高角色，就按更高角色看
（兼任财务的教师要看全部钱的账，硬按"只看自己的课"限制他反而是错的）。

**一页一角色**：

| 后台页面 | 普通教师 | 招生老师 | 财务管理员 | 技术管理员 |
| --- | :---: | :---: | :---: | :---: |

| 咨询 | — | ✅ | — | ✅ |

| 学生（收退款 / 课时账本） | — | 只收款 | ✅ | ✅ |
| 学生（退课） | — | ✅ | ✅ | ✅ |
| 学生（课时余额） | ✅ 只看自己学生的 | ✅ | ✅ | ✅ |
| 教师 / 教室 / 课程库 | 只读 | 只读 | — | ✅ |
| 课程安排（排课 / 批量排课 / 调课） | — | ✅ | — | ✅ |

**看不到的按钮 = 你的角色做不了那件事**（2026-09 起）：界面上现在会**按角色隐藏**注定失败的按钮
（普通教师看不到「新增/编辑/删除学生」「取消/编辑/删除排课」「批量导入」，财务管理员看不到「标记已上」，
招生老师看不到报价页的「保存/恢复/导出」），并在旁边写一句"这件事归谁"。
判据与服务端**同一个函数**（不是两张会各自漂移的权限表），因此不会出现"按钮看得见、点了 403、
界面还什么都不说"那种情况。真要看全套动作，见下面这张表。

**读不出来时会给原因**：后端没开、登录过期、权限不足，页面会显示服务端那句话 + 一个「重试」，
而不是一直停在"加载中…"。屏幕上如果还留着内容，那是上一次读到的数据（会写明这一点）。

**两条实现原则**：

1. **权限必须由服务端拦**，前端藏起来不算数 —— 这是本项目一贯的纪律：
   "前端拦得住手滑，拦不住直接调接口"（见 [后台API约定 §四](./后台API约定.md)）。
   落地时按**方法分组**在服务端做一处闸门（`lib/backend/contract.ts` 的接口分组正好是这个粒度），
   而不是在每个页面上各写一遍判断。
2. **界面跟着权限走**：看不到的入口**不显示**（而不是显示了点进去报 403）——
   教师打开后台就该只看到自己那几页。左侧导航的分组正好按角色划（见技术架构的导航一节）。

**教师看数据时的两条口径**（说清楚，免得出现"一会儿 403 一会儿空列表"这种说不清的行为）：

- **不是自己的学生 / 不是自己的课 → 看不到**：列表里没有他、单条查不到（返回"没有这条记录"），
  而不是报一句"权限不足"。那种情况要找的是"这门课是不是你带的"，不是找管理员开权限。
- **整块不归教师的业务 → 明确拒绝**：钱（收款记录 / 财务汇总 / 欠费）、待跟进、排课、
  课程库写入，这些接口对教师是 403，并说清"这件事不归普通教师"。
  清单是固定的、写在代码里（`lib/auth/roles.ts` 的 `TEACHER_SCOPE_RULES` 标了 `hidden` 的那些），
  不是随手加的。

### 账号怎么建、口令忘了去哪看

**主路径：用后台的「账号」页**（左侧导航最后一项，**只有技术管理员能进**）。
加人、改角色、绑定教师、重置口令、停用、删除都在那儿做，**改完立刻生效**，不用重启后端：

| 想做这件事 | 在「账号」页怎么做 | 后果 |
| --- | --- | --- |
| **加一个人** | 「新建账号」：填账号名（登录名，不能重名）、初始口令（**至少 8 位**）、勾角色、选绑定教师、写备注 | 他**马上**就能用这个口令登录（不必重启后端） |
| **改角色 / 换绑教师** | 那一行点「改角色与教师」 | 角色是**多选**（一个账号能兼多个角色）；他**重新登录**后生效（角色记在会话里） |
| **忘了口令** | 那一行点「重置口令」，设一个新口令，**当面告诉他** | 旧口令**立刻失效**；这一页不显示、也不发送口令（读回来的任何东西里都没有口令） |
| **人走了 / 暂时不用** | 那一行点「停用」 | 他立刻登不进来（口令仍然留着）；**建议用停用而不是删除** —— 删除会让操作日志里的名字对不上人 |
| **彻底不要了** | 那一行点「删除」 | 他再也登不进来（会问两次确认） |

两条**删不掉 / 改不了**的情况（都在页面上说清了原因）：

- **最后一位技术管理员**不能被删除 / 降级 / 停用 —— 账号管理只有技术管理员能进、口令也只能在这里改，
  做完这一步就没人能进后台改账号了（等于把系统锁死）。正确做法：**先给接任的人加上「技术管理员」，再动原来那位**；
- 后端如果是用 `NEXGENEDU_ADMIN_PASSWORD` 启动的，与它**同名**的那条账号的口令会被同步回环境变量里的值：
  那种启动方式下，它的口令在这里改不了（会被同步回去）、也删不掉（会被自动建回来）——
  要动它就改用别的方式启动后端。

**备用路径：直接编辑账号表文件。** 账号表是**服务端的一个文件**：与数据库同目录
（默认 `server/data/accounts.json`，权限 0600），一条账号长这样：
`{ username, password（明文，找回用）, salt, hash, roles: [...], teacherId, disabled }`。
手工改仍然可以（例如后端起不来的时候），但**改完必须重启后端**才生效，而且容易写坏
（少个逗号会让下次启动谁也登不进来）。口令的 `salt` 与 `hash` 不用自己算：
照着现有那条复制、只改 `username` / `password` / `roles` 即可，后端会在读的时候按口令补出来。
**忘了口令**也可以看那一条的 `password` 字段（明文就在那儿，和原来的凭证文件同一约定）。

- **老部署升级上来**：文件不存在时会用原来的 `admin-credential.json` 自动建一条
  `admin` 账号，角色给**全部**（技术管理员）—— 原来的口令照用，不会突然"没权限"。
- **一个账号多个角色**：`roles` 写成数组即可，例如 `["财务管理员", "技术管理员"]`
  （「账号」页上是多选，存下来按固定的顺序排）。
- **停用**：`"disabled": true`。口令仍然有效，但不许登录；写错格式（例如写成字符串 `"true"`）
  按"没停用"处理 —— 宁可多给一次登录机会，也不要因为一个格式写错把还在上班的老师挡在门外。
- **普通教师账号必须填 `teacherId`**（第 5 条边界，最容易漏的一条）：

  | 填法 | 结果 |
  | --- | --- |
  | 填**教师档案的 id**（形如 `t_xxxxxx`，在「教师」页那条记录上，账号表里现有账号的 `teacherId` 也是这个形状） | 正常：只看得到自己带的课与自己课上的学生、他们的课时余额 |
  | **不填**（`"teacherId": ""`） | **登录成功但什么都看不到**（空范围）：学生名单、课表、今日概览全是空的。登录时会在后台顶部显示一句提示，说明"没绑教师档案 id"以及去哪里补 |
  | **填错**（填成姓名，或别的环境的 id） | 同上（一条数据都看不到），提示里会带上那个填错的 id —— 一眼能看出填的是什么玩意儿 |

  为什么不干脆拒绝登录：那是**数据配置**问题、不是身份问题。拒绝登录会让这位老师
  在机构现场彻底用不了系统（连"这节课是谁上的"都查不到），而账号表是手写的、
  漏填一个字段必然会发生。所以取"宁可少给"：不会多给一行数据，
  并且**把原因说清楚**（后台顶部那条提示 + 登录响应里的 `scopeWarning`）。

  **怎么拿到老师的档案 id**：以技术管理员进「教师」页 → 找到那位老师 → 那条记录的内部 id
  （页面上的排课下拉、报课表单用的就是它）。**在「账号」页把这一条账号的绑定教师改成他**
  （下拉里直接选人，不用抄 id），那位老师重新登录一次即可生效（角色与范围都记在会话里）。
  手工改文件也行，那种改法要重启后端。
  「账号」页的列表里会**直接标出**谁会"看不到数据"（普通教师 + 没绑 / 绑错的 teacherId），
  所以加完人扫一眼那一列就能发现漏填。

> **已经定了的四条**（机构确认）：① 财务管理员**能**建档 / 报课；② 招生老师**能**退课；
> ③ 普通教师**能**看到自己学生的课时余额；④ 一个账号**能**兼任多个角色。
> （Phase B 又加了一条：教师账号必须填 `teacherId`，见上表。）
>
> 这张表**已经写进代码**（`lib/auth/roles.ts`：页面 → 角色、接口分组 → 角色、方法 → 范围），
> 并且自检会盯着它：**新增页面 / 新增接口分组没定归属、或新增的读接口没定行级范围，
> `npm run check` 直接红** —— 权限最容易出的问题不是判错，而是新功能默认对所有人开放。
>
> **分工已经落地**：服务端按会话里的角色拦接口（越权一律 403，前端藏起来不算数）；
> **行级范围也已落地**（普通教师只看自己的课与自己学生的课时余额，金额字段被剥掉，
> 老 REST 接口对教师整条关闭 —— 见 [后台API约定 §三](./后台API约定.md)）；
> 界面按角色**隐藏入口**（普通教师打开后台只看到自己那几页）；
> 直接敲网址进不该进的页会看到一句"你的角色看不到这一页"，而不是坏掉的界面。
> 账号在哪、怎么加人、忘了口令怎么办，见上面那一节；范围怎么验的，见 `npm run check:auth`。
>
> 实现时留意一处：**退课与退款在今天的界面上是一步**（退课时会按选定的口径记一笔退款）。
> 因此"招生老师能退课"意味着他也能按下那笔退款。如果机构希望钱那一步留在财务，
> 就得把退课拆成两步（先退课、再由财务补记退款）—— 这一条要在实现前定下来。

## 2. 今日概览

> **谁能用**：所有登录的人（**普通教师只看到自己的课**）。

打开就会看到四块数字：**今日课程 · 今日授课教师 · 学生档案 · 课时预警**。

- 「今日课程」里除了课程，还会列出**今天的空档**（课前 / 课间 / 课后，虚线浅底那几行），
  标题旁写明当天的空档合计（如「3 节 · 空 11 小时 30 分钟」）——
  想知道「今天还能不能加一节课、接一个学生」，看这里最快。
- 「课时预警」是今天最该看的一行：哪些学生课时快见底（阈值见第 10 节）。
- 想联系家长时，别在这里手动找 —— 直接去「待跟进」，那里把原因和话术都写好了。

## 3. 咨询：家长问「这个时间能不能排」

> **谁能用**：招生老师 · 技术管理员。

这是唯一一个「**先别答应，先算一下**」的页面。家长当场问「每周六上午十点，陈老师，先来 12 节行不行」，
以前只能凭印象回答，现在先登记再判定。

**登记字段**：学生姓名、年级、家长联系方式、想上的科目、每次时长、频率（每周一次 / 每两周一次）、
计划节数、从哪天开始、备注。

**候选时段**：可以加**多个**候选（星期 + 开始时间），点「+ 再加一个候选」。
家长如果说「我们周六上午或者周日下午都行」，两个都加上 —— 系统会依次尝试，第一个能排下的就用它。
另外可以标注**跳过某几周**（例如春节、考试周），课会顺延，总节数不变。

**点「登记并判定可行性」之后会看到**：

| 报告内容 | 含义 |
| --- | --- |
| 每个候选时段能不能排 | 检查的是**一整串日期**（每周一次 × 12 节 = 未来 12 个同一时段都得空着），不是只看某一天 |
| 不能排时，挡路的是谁 | 具体到哪节课 / 哪位老师 / 哪位已有学生 —— 因为接着要决定是让新学生换时段，还是去协调老学生 |
| 最接近的方案 | 排不下时给出的替代建议（换时段 / 换老师 / 换教室） |
| 「协调已有学生：把这节课挪走 →」 | 针对挡路的**已有课**给出可挪的时间（挪到哪里不会再撞，系统已经算过） |

**采用与放弃**：

- 可行的方案点「**采用这个方案**」→ 系统一次性把整串课建出来（12 节课一次成型，不用一节节点）；
  落库前会**再检查一次**，因为这中间可能有人排了别的课。
- 排不了就「**放弃**」并记下原因（线索状态：待确认 / 已安排 / 已放弃）。

> ⚠️ **采用方案前，先跟家长确认时段。** 采用后课就已经在系统里了。
> ⚠️ 采用之后，那串课里**还没有学生名单**（咨询时学生往往还没建档），
> 请到「学生」页建档，再把这节课的学生补选上。这是两个动作，别漏第二个。

## 4. 学生：建档、报课、收费、退课、课时

> **谁能用**：招生老师（建档 / 报课 / 改报课 / 收款）· 财务管理员（收退款 / 退课 / 课时账本）· 技术管理员。**普通教师看不到这一节。**

### 4.1 建档

「学生」→ 右上角「新增学生」→ **姓名 + 年级**就能建档（其余以后补）。
列表里能直接看到：姓名、年级、家长、状态、报读科目、剩余课时、「需提醒」标记。

**建档时可以一次性把课也报上**（家长来报名时说的就是「数学 10 节、英语 20 节」）：

1. 「**报课科目与课时（选填，可多门）**」→ 点「报课科目」勾选（可多门，带搜索与分组）；
2. 勾完下面会列出**每门科目一行**，行内三样各自填：
   - **节数**（「A 科目 10 节、B 科目 20 节」就是这样填的）；
   - **班型**（默认是第一个班型，例如「一对一定制课」——数学一对一定制课、英语一对二小组课这种组合在这里一次录准）；
   - **指定教师**（默认「不指定」；要指定谁就在这一门上下拉选）；
3. 几门节数一样时更省事：左上「统一节数」→ 点「**应用到所有科目**」；
4. 每门课下面那句小字会说明默认值是哪两个，只有真正不同的那几门要动。

按钮会变成「**建档并报课（N 门）**」。一次提交就是**一次落库、一条日志**：
不会出现「学生建好了、课时没记上」的半成品（报课数据有问题时整条建档都会被拒，并说明原因）。

> **金额不在这里收**：建档只记科目与课时。「单价 / 约定应缴 / 实收」要按班型定价算，
> 而且常常分期 —— 家长的**每一笔钱都在「报课与课时 → 收款」里记**，钱的入口只留一个。
> 不勾科目也能建档（之后在详情里报课）。

### 4.2 学生详情有三个页签

| 页签 | 内容 |
| --- | --- |
| 报课与课时 | 报课、**改报课**、续费、收退款、退课、课时流水（账本） |
| 信息采集表 | 完整的学生资料采集表（按钮「填写采集表」） |
| 排课记录 | 他的每一节课（上过的、要上的、取消的） |

**信息采集表**分六节、当前共 **72** 项：一、基本与家庭信息；二、学业基础信息；三、学习行为与习惯；
四、排课相关信息；五、心理与情绪健康；六、健康与特殊需求。字段数量以后可能增减，
以页面上「填写采集表」实际显示的为准（字段是键值对存的，增减不影响老档案，读不到就是空）。

### 4.3 报课（最重要的一步）

「报课与课时」→「报课」→ 填表：

| 字段 | 说明 |
| --- | --- |
| 科目 | 与课程页的叫法一致（例如「初中数学」） |
| 班型 | 一对一定制课 / 一对二 / 一对三小组课 / 一对多小班课 / 大班课 / 晚托管… |
| 课时数 | 本次买的节数 |
| 单价 | 标价（元 / 节） |
| 约定应缴 | 与家长谈定的总额。可以低于标价（优惠），也可以高于实收（分期） |
| 本次实收 | 这次实际收了多少钱；填 **0** 表示先上课后付款 |
| 报课日期 / 备注 | — |

点「**确认报课**」后，这笔报课会同时产生：报课记录 + 课时余额 + （本次实收 > 0 时）一条收款流水。

**三个金额概念，别混**：

| 概念 | 怎么来的 |
| --- | --- |
| 标价 | 课时数 × 单价（机构挂牌价） |
| 约定应缴 | 与家长谈定的总额 |
| 实收 | **由收款流水累加得出**，不是手填的最终值 |

由此：**优惠 = 标价 − 约定应缴**；**欠费 = 约定应缴 − 实收**。

### 4.3.1 改报课：像手机日历那样「改这条 / 改这条及以后」

报课记录建好之后要能改：换了老师、班型从一对一定制课转成小组课，都是常事。
在「报课与课时」里每条报课右侧点「**改报课**」：

| 能改 | 班型 / 指定教师 / 单价 / 约定应缴 / 备注 |
| --- | --- |
| 不能改 | **科目**（报错了请「退课」后重报 —— 科目是"这节课扣哪条报课"的匹配键，改了它已排的课与账本会对不上）、**课时数**（走「续费」或「调整」） |

改的时候要选**影响到哪里**（与手机日历改日程一样）：

- **只改这条报课记录** —— 已排的课一节都不动；
- **这条报课记录 + 后续还没上的课** —— 换教师、换班型通常选这个（默认）。

**过去的一律不改**，这也是手机日历的规矩：已经上过的课、以及时间已经过去的课
（哪怕状态还挂着「已排」——那多半是忘了标记），都不会被这次改动碰到。
改完面板上会写明：**后续课节改了 N 节 · 跳过 M 节 · 已过去 K 节未动**。

**会撞课的节会跳过并说明原因**：换了老师之后，如果新老师那个时段已经有课，
那一节就跳过、并写明「某某老师 这个时段已有课」——宁可少改一节并说清楚，
也不要造出一堆撞课的课表让你事后一节节去查。没冲突的那些照改不误。

> 改单价与约定应缴**不会动已收的钱**：实收只由「收款 / 退款」记录决定，
> 所以「实收 = 收款合计 − 退款合计」这条账永远是平的。

### 4.4 续费

同一条报课上的「续费」→ 加课时 + 同时收一笔款。续费不会新建一条报课，
而是把课时累加到原来那条上（余额连续，家长好理解）。

### 4.5 收退款（分期、补记）

用「**记收款**」「**记退款**」补记：分期付款、只收钱不加课时（例如材料费）。
付款方式可选：微信 / 支付宝 / 现金 / 银行转账 / 其他。

> ⚠️ **收钱记录在「学生」页，不在「收费」页。** 「收费」页是看报表和欠费清单的，
> 不是录入入口 —— 这一点新同事最容易搞错。

### 4.6 退课（先选退费口径，再看明细）

同一条报课上的退课流程，**先选口径**（页面会显示每种口径的算法与金额）：

| 口径 | 算法 | 什么时候用 |
| --- | --- | --- |
| **按实付比例退（默认）** | 实付 ÷ 总节数 × 剩余节数 | 最常见，对家长最好解释 |
| 追回已上课时的标价 | 实付 − 已上节数 × 标价 | 给过较大折扣、要防止「上完就退」 |

确认时有两个按钮：「**确认退课并退款**」和「**只退课，不退款**」（例如课时已经上完、或钱不退）。
退款会生成一条**退款流水**，报课记录标记为「**已退课**」（历史保留，不会消失）。

三条与钱有关的细则（都是审计之后定下来的）：

- **金额按「实收」算，不按「约定应缴」**：家长欠着钱来退课时，按约定应缴算会退出**没收到过**的钱。
  例如约定 ¥2800、实收 ¥1900、一节课没上 → 退的是 ¥1900（公式在界面上写着）。
- **退款金额由服务端重算**：界面上显示多少只是预览；提交时服务端会按同一个口径再算一遍，
  **对不上就拒绝**并让你刷新 —— 那说明这条报课在你看这一页之后被改过，照旧退会退错钱。
- **退款不能超过实收**：想退的比收到的多时会被拦下，先核对这个学生的收款流水
  （可能是分期、也可能那笔收款记在别的报课上）。
- 退款也会写进**操作日志**（谁、什么时候、退了多少钱、按哪个口径）。

> ⚠️ 退课要改的是「账」，不是「删除记录」。退课后这条报课不能恢复，请核对清楚再点。

### 4.7 课时流水（账本）与撤销

每条报课下面就是它的**课时流水**：报课、续费、上课、调整、退课，每一笔都有时间和说明。
（建档时一并报的课也在这里，日期是报课日期。）

- 打了删除线并标「**已撤销**」的，是**不生效**的流水（不计入已用课时）。
- **没有「撤销」按钮**，也不需要：把课节状态从「已上」改回去、或者补录请假时间时，
  系统会**自动**按流水退回课时并留下撤销痕迹（不是删记录，账仍然可追溯）。
- 手工调减课时时，若填的节数超过剩余（例如剩 15 节却要减 20 节），账本记的是
  **实际生效的节数**（15 节）并注明原因 —— 课时不会被调成负数。

### 4.8 课时口径（背下来，家长问的时候不用猜）

| 问题 | 口径 |
| --- | --- |
| 剩余课时怎么算 | 总课时 − 已用课时（不会出现负数） |
| 已用课时怎么算 | 该报课下**有效的「上课」流水**合计 |
| 账本与余额的关系 | **有效流水之和 = 剩余课时**（自检里有一条不变式守着，报课/续费/调整/退课都进账本） |
| 一节课扣哪条报课 | 找**同科目、仍在读**的报课；有多条时扣**剩余课时最多**的那条 |
| 找不到对应报课怎么办 | **不扣课时**，并明确提示「没有该科目的在读报课」——不会随便扣一条 |

## 5. 教师

> **谁能用**：技术管理员（维护档案）· 招生老师与普通教师**只读**（看谁带什么课）。

> 教龄与两部分简介在上面的格子里填（网站上写着的那几项，照着填即可）；批量录入见 §13.2 与 §13.4。
> 类型选 **AI** 的表示智能体：留在档案里，但不进排课下拉。

字段：姓名、职务、可带科目、联系方式（列表里还有在职开关、今日本周课程）。

- **可带科目从课程库里勾选**（下拉里带搜索框，点一下展开、可多选；已选的会显示成小标签，
  点标签上的 × 就能去掉）。**不用手打**：手打最容易出现「围棋」和「围棋课」两个名字的同一门课，
  课时与统计就对不上了。课程库里没有的课，先到「课程 → 课程台账」里加一门。
- 可带科目在排课时有用：勾了科目的老师，排课选错科目会被提示；**没勾则不校验**（没登记不等于不能带）。
- 匹配规则是「科目名出现在课程名里」：填「物理」能命中「高中物理」。
- 教师信息是**数据驱动**的：新增一位老师、填上可带科目，课程页的「这门课谁带」就会自动出现他，
  不需要改代码。

## 6. 教室

> **谁能用**：技术管理员（维护）· 排课的人可看（招生老师）。

字段：名称、用途（上课用教室 / 自习室）、容量、**可用时段**、备注。

| **课程类型** | 坐标系：学段 × 学科 / 项目 × 内容模块 × 班型（原来的「课程类型」，见 §7.0.3） | **整份保存**（四张维度表一起交） |
| **开放矩阵** | 组合：哪些「学科 × 模块 × 班型」真的开（原来的「开放矩阵」，见 §7.0.4） | **整份保存**（勾完一次交） |

> ⚠️ **三个页签各有一个保存按钮，别在页签之间切换时忘了交**：切页签**不会**丢草稿
> （切回来还在），但也不会替你保存。台账那一块是逐条的，与其他两块互不影响。

**页签谁能看到**（v29 之前这三个页面的角色本来就不一样，合并后按页签照旧把关）：
课程台账 = 技术管理员 / 招生老师 / **普通教师（只读）**；课程类型与开放矩阵 = 技术管理员 / 财务管理员 / 招生老师。

**课程台账**这一块上有三块，职责分得很清楚：

| 页上的位置 | 管什么 |
| --- | --- |
| 「课程分区」（新增，见 §7.0.1） | **分区**：栏目（小学课内 / 初中课内 / 高中课内…）与栏目下的子栏目（必考科目 / 外语 / 七选三）。在这里新建分区；改名、排序、删除、把一区的课整批移走到下面「课程清单」每个分区的标题旁 |
| 上面的「新增课程」（在页面顶部，**默认收起**，点右边「填写新课程」展开） | **一门课的全部**：课程记录（名字 / **分区** / 状态 / 班型 / 备注）、网站上怎么展示（形态 / 路径 / 标签 / 靶点 / 顺序 / 一句话）、这门课在网站上的**小节正文**、以及它的**报价（元 / 节）**。改完点**一次**保存，这三样一起落盘 |
| 下面的「学科级设置与未挂到卡片的正文」 | 课程页标题、学科（语文 / 数学 / …）的导语与「整组暂未开放」，以及**没有卡片指向**的小节（默认收起，点「展开编辑」） |

#### 7.0.5 课程挂在维度上（v28）—— 「不靠枚举」的那一步

课程台账里的课是**枚举**出来的名字（`小学语文`、`高考外语`…），而「课程类型」是一套**维度**
（学段 × 学科 / 项目 × 内容模块 × 班型）。v28 起每门课都**挂到维度上**，两者接起来了。

**每张卡片上写着它的维度**（例如 `小学 · 语文`），并且：

- **能按维度筛课**：清单上方有「按维度筛：学段 / 学科」，再加上一个「只看未挂维度」的开关；
- **搜索也认维度名**：输「语文」能把小学 / 初中 / 高中的语文都筛出来（以前只能按课程名与分区名搜）；
- **两张表相互提示**：卡片上会写「矩阵里开放着 N 条组合」；如果这门课是「开放」却在
  「开放矩阵」里一条组合都没开（或全关着），这里会提醒你去核对 ——
  两层状态各管一层：**课程状态**＝这门课整体上不上网站 / 能不能被选；**开放矩阵**＝它的某条组合能不能卖。

**怎么挂**：点这门课的「编辑」，在表单里的「**所属维度**」选 学段 / 学科 / 内容模块
（模块只列你所选学科下面的那些；留空＝这门课不细分到模块，大多数卡片就是这样）。
挂的是课程类型里那些行的 **id** —— 你在「课程类型」页给学科改名，挂在上面的课不受影响。

**「高考外语」这种情况**：它是一张卡片覆盖五个语种（高考可以考日 / 俄 / 德 / 法 / 西），
因此它挂的是**五个学科**（卡片上会显示五个标签）。这不是错误，是这类"打包卖的课"的正常形状。

**还没挂的课**：台账里会有一块黄色的提示「有 N 门课还没挂到课程类型上」，点「只看这几门」再逐个挂上即可。
没挂的课**照样能排课、报课**（只是按维度筛课、开放矩阵、以后的排课与诊断推荐认不出它）；
新加的课在表单里选好维度即可；从旧库升级上来的课由迁移按名字挂一次，对不上的才落进这一块。

**清单怎么分组（v33）**：清单上方有一个「**分组方式**」开关，默认是
「**按维度（学段 → 学科）**」—— 先看学段，再看学科，每门课只出现一次；
一张卡片覆盖多个学科的（「高考外语」）归在**「多学科卡片」**那一桶里，不会重复列五次。
切到「**按分区（网站栏目）**」就是网站课程页那棵树 —— 分区的**改名 / 排序 / 删除 / 批量移课**
那几个动作就挂在它的表头上，要整理分区时切过去用。
（读不到课程类型时（后端没跑）会自动只能用分区视图。）

**这一步没有动网站**：网站上的卡片、路径、正文、报价取数与以前完全一样（机构口径："先做 A"）。
分区视图仍然保留 —— 它是网站的展示结构；等网站展示也由维度生成那一步做完，它才可以撤掉。

#### 7.0.2 网站内容（学生案例 · 特色课程）

「网站内容」页（左侧导航 → 网站内容）维护**对外文案**，共四类：

| 面板 | 管什么 | 网站上出现在 |
| --- | --- | --- |
| 学生案例 | 案例的标题、字段、过程描述 | `/cases` 与首页那块案例区 |
| 特色课程 | 三级课程树（一级 → 二级 → 三级） | `/courses` 底部那块 + `/courses/featured/**` |
| 常见问题 | 分组标题 + 问答 | `/faq` |
| **页面文案** | 品牌与联系方式 / 首页 / 关于我们 / 联系我们 / 课程时间安排（五个页签） | 页头页脚、首页、`/about`、`/contact`、`/schedule` |

四类都在库里，一次「保存」一起提交，服务端各写各的、互不覆盖。

#### 页面文案（五个页签）

- **品牌与联系方式**：站名、口号、电话、微信、地址、营业时间、上课时间、备案号…
  它出现在**页头页脚与每一页的标题**里 —— 改错了是全站的事，改完记得看一眼页脚；
- **首页 / 关于我们 / 联系我们 / 课程时间安排**：短字段（标题、说明、按钮文案…）
  加上若干**分组**（分组标题 + 条目）。分组标题就是页面上的小标题；
- **左栏那个灰底的名字（`phone`、`trial_title`…）是页面取值用的键，不能改** ——
  改它会让页面上对应那一处**静默空掉**（没有报错）。要改的是右边的值；
- 分组里的条目可以增删、可以 ↑↓ 调顺序；条目有「标题 / 值 / 正文」三样，
  正文留空就不显示（内容文件里就是 `#### 标题 | 值` 加下方一段正文）；
- **短字段里的每一行**：像「试课要点」那种一行一条的字段，**一行就是一条**
  （页面上显示成 ✓ 列表）。

> **网站只根据后端**：这三块外加教师页、课程卡片、课程正文、报价，构站时连得上后端就**全部**按库里的内容出；
> 连不上（没起后端 / GitHub Pages 默认口径）时**标题与分区标题照常显示，底下的条目为空**
> （页面上会写明"由后台维护"）。详见 [技术架构 §5.1](./技术架构.md)。

#### 常见问题（`/faq`）

| 页上的位置 | 管什么 |
| --- | --- |
| 上面的短字段 + 「页面说明」 | 页面的眉题、标题、说明与页脚提示 |
| 每个「分组」 | **分组标题**（网站上就是一个分区标题，例如「试课与报名」）、组内的问答 |
| 每条问答 | 问题与答案（答案支持 **粗体** 与 - 列表；多行答案写在同一个框里，空行分段） |
| 右上角 / 每行 | 「新增分组」、↑ ↓ 调分组顺序、删除分组；每组里有「+ 在这一组加一条问答」 |

三条口径：**分组标题不能为空、不能重名**（它就是页面上的分区标题，重名会让两节看起来一样）；
**问题与答案都不能空**（一条问不出问题、或问了没答案的条目在页面上就是断掉的一处）；
**分组可以有零条问答**（组标题照常显示，组内写明"这一组暂时没有问题"）。

#### 特色课程（三级课程树）

| 页上的位置 | 管什么 |
| --- | --- |
| 上面的短字段 + 「页面说明」 | 那一页的眉题、标题、说明与页脚提示 |
| 每门课程 | 课程名、**路径分段**（网址里那一段）、描述字段（适合对象 / 课程定位 / 主要做法 / 可以期待，**可自己加**）、详细介绍 |
| 每门课程右侧 | ↑ ↓ 调顺序、删除；一级与二级下还有「+ 加一门子课程」 |
| 底部 | 「+ 加一门一级课程」与「保存特色课程」 |

几条口径：

- **最多三级**（一级 → 二级 → 三级，每级在网站上都有自己的页面）。到第三级就不再显示
  「加子课程」——第四级在网站上没有任何入口，服务端也会拒绝；
- **改名不会改网址**：网址用的是「路径分段」那一个字段（与课程名分开存）。
  留空就按课程名自动派生；想换网址才去改它；
- **二级课程名不再决定「班型」**（v23 起）：班型的唯一口径是「课程 → 课程类型」页签里的**班型**维度，
  课程库 / 学生建档 / 报课 / 排课表单里的班型下拉都取自那里（改完立刻生效，不用重新构站）。
  特色课程树里那些「一对一定制课 / 一对三小组课」现在只是**网站上的一段介绍文字**；
- **删除有护栏**：有子课程的、或名字还被某门课当班型用的，都删不掉，并会点名是哪几门课；
- **请勿编造**：课程能不能开班取决于当前排课与人数，页脚那句提示就是给家长看的。

#### 学生案例

**为什么这两块要在后台改**：都是**要经常更新**的对外文案（新学生进来、老案例过时），
而它原先只写在 `data/site/cases.md` 里 —— 改一条分数要打开文件、改完还要重新构站，
招生老师在后台根本看不到。现在它和教师、课程一样在库里，改完**重新构站一次**网站就更新。

| 页上的位置 | 管什么 |
| --- | --- |
| 上面的三个短字段 + 「页面说明」 | 页面的眉题、标题、说明，以及页脚的「页脚提示」（例如"案例均经家长同意后发布"） |
| 每条案例 | 标题（如「初二 李同学｜数学从 62 分到 91 分」）、若干**字段**（年级 / 科目 / 入学水平 / 当前水平 / 辅导周期 / 主要问题…）、以及一段**过程描述** |
| 每条案例右上角 | ↑ ↓ 调顺序、删除 |
| 右上角 | 「新增案例」与「保存」 |

几条口径：

- **字段可以自己加**（点「+ 加一个字段」）：艺术类案例写「考级等级」、竞赛类写「获奖情况」都行，
  不用等改代码。页面顶部的「前后对比」取的是**名称正好是「入学水平」与「当前水平」**的两个字段，
  因此这两个名字要照写才有对比效果（写成别的名字也不会报错，只是不参与顶部对比）；
- **一条案例都没有是允许的**：网站那一页会显示成"案例整理中"的空状态。
  内容文件里那句"不希望公开就把分组整段删掉"就是这个意思；
- **请勿编造**：写真实的过程与数字，姓名用「初二 李同学」这类称呼；
- **保存按钮只管案例**：在「课程库」页保存课程正文**不会**动案例，反过来也一样
  （两块内容各有一个保存入口，谁也不覆盖谁）。

> **谁能改**：技术管理员与**招生老师**（见上面的角色表）。
> 普通教师与财务管理员能看，不能改（页面上会写明归谁管）。

> **和"网站内容从哪来"的关系**：构站那台机器**连得上后端**时，网站就用这里的案例；
> **连不上**（例如 GitHub Pages）时，整站用 `data/site/cases.md` 那份模版 —— 这是全站统一的
> 两态口径（见 [技术架构 §5.1](./技术架构.md)），不是这一页的特殊行为。

### 7.0.1 课程分区（栏目 → 子栏目）

「课程清单」里的「小学课内」「初中课内」这些**小标题不是写死的，是一份可以自己维护的数据**
（v18 起）。分区只有两级，因为这正是宣传网站课程页的结构：

```
栏目（小学课内 / 高中课内…）
  └ 子栏目（高中课内下的 必考科目 / 外语 / 七选三）
      └ 课程（高中物理 / 高考外语 / …）
```

- **加一个分区**：到「课程分区」填名字、选上级（「（一级栏目）」就是新栏目）→ 点「新建」。
  新建的排在**同级最后**，不会抢到最前面。分区**可以是空的**（先建好、以后再放课），
  但空分区**不会出现在宣传网站上**（网站上渲染一块空区域只会让家长以为坏了）。
- **改分区名**：点分区标题旁的「改名」。改一次，**下面每一门课都跟着变** ——
  课程挂的是分区本身（不是分区名字），所以不需要逐门课去改（这正是这一版要修掉的老毛病）；
  主站上的栏目名、科目下拉里的名字、导出的「分类」列会一起变。
- **调顺序**：↑ ↓ 换位。栏目的顺序、子栏目的顺序都由它决定 ——
  改完网站课程页的栏目顺序跟着变（以前只能去改每张卡片的「显示顺序」，而且后台看不到结构）。
- **删除**：**有课或者有子栏目的分区删不掉**，会告诉你先做什么。
  这不是为难人：分区删掉了，那些课会变成「未归类 / 分区已失效」，网站上那一整块消失，
  而**没有任何提示**。要删就先把它下面的课移走（用分区标题旁的「移到…」）。
- **把一区的课整批移走**：分区标题旁选「移到」→ 选目标分区。一次移完、只记一条日志。
- **未归类**：新增课程时「分区」选「（未归类）」是允许的中间状态（先建课、之后再分区）。
  清单最后会把它们单列一块；如果那里写着「分区已失效」，说明这些课指向的分区已经不在了
  （通常是从别处的备份恢复过来的数据），用每张卡片的「编辑」重新选一个分区即可。

> **谁能改**：新建 / 改名 / 排序 / 删除分区与移动课程都是**课程库写入**，与新增课程同一档
> （技术管理员 / 财务管理员 / 招生老师）。**普通教师只能看**（这一页的清单要按分区分组，
> 所以分区列表对教师是只读可用的）。

课程的来源与能不能删，还是这两类：

| 来源 | 怎么来的 | 能不能删 |
| --- | --- | --- |
| 网站 | 新装系统时，内容文件里的课程卡片作为**初始数据**自动进库 | 不能删（它是初始数据的一部分）。不想再排就点「设为暂未开放」 |
| 后台 | 机构自己加的课（围棋、书法、编程这类网站上还没有的） | 可以删 |

**「一门课一个地方改完」**：在课程清单里点某门课的「编辑」，**编辑器就直接在这张卡片下面
展开**（卡片左边亮起来并标着「正在编辑」，页面**不会**跳到最顶端 —— 你刚才点的那门课还在眼前）。
卡片字段、它在网站上的正文、报价都在这一个表单里，点一次保存就都写好；保存成功的提示会说清
这一回改成了什么，例如
「已保存「初中数学」：卡片 + 报价（初中阶段 · 220 元/节）+ 网站正文（1 个小节）」。
三样是一起交的，**顺序是课程记录 → 网站正文 → 报价**（记录是主体，正文与报价都挂在它上面）；
中途有一处被拒时会明确告诉你被拒的原因，接着改就行，不必回头核对三处。

**新增课程那块默认是收起的**（一行说明 + 「填写新课程」按钮）：它整块都在课程清单**上面**，
一直摊开的话，点下面某张卡片的「编辑」时它会被收起 —— 那等于"你正在看的地方上方突然矮了一块"，
浏览器可能因此把滚动位置往上收（§15.3 的原因二）。收起之后点编辑不会再动页面位置；
要新增时点「填写新课程」把它展开即可（展开是长高，不会把你推回顶部）。保存成功后它保持展开，
连着加几门课不用反复点。

几条与它有关的小规矩：

- **同一时刻只开一个**：点别的课程的「编辑」，原来那个自己收起、新那个在它自己的卡片下面展开。
- **保存成功 / 点「取消」都会把编辑器收起来**，页面位置不动（不会跳回顶部，也不会跳到别处）。
- 卡片上的「设为开放 / 暂未开放」「删除」照旧**就地生效**，不受"是不是正在编辑这门课"影响；
  删掉的正好是正在编辑的那门课时，编辑器随着卡片一起消失，页面回到「新增课程」的样子。
- **点了之后的结果就显示在那张卡片上**（一行绿字或一行红字，例如「已设为「暂未开放」。」）。
  失败也写在那儿（最常见的是登录已失效，见 §15.3）—— 不必再往页面上方找提示。
  切换期间按钮会变成「切换中…」并暂时不能点，避免连点两下发出两条相反的写。
- 编辑到一半改了搜索词 / 来源筛选，把这张卡片挡在清单外时，页面上会有一行提示告诉你
  编辑器去哪了 —— 清掉搜索（或切回「全部」）它就回到原处，改过的内容不会丢。
- 删小节被拒时（有卡片指着它），**原因写在你刚点的那一个小节的框里**，页面不动；
  没有"滚到页面顶部去看原因"这件事了。

#### 网站上这门课的正文（就在卡片里改）

「网站上怎么展示」里填了网站形态（学科 / 选修）与卡片路径的课，表单里会多出一块
**「网站正文（小节）」**——它只列出**这张卡片指向的那些小节**（＝卡片自己的「卡片点进哪一节」
+「卡片标签」里各个标签的目标，按小节锚点或小节标题对上），不用在几十个小节里翻：

- **精编一小节**：标题、锚点、正文都能直接改。标题可以写成「初中数学｜建立数学模型」，
  竖线之后是你想要的导语（网站上就显示成副标题）。
- **新增一节**：点「新增小节」，新的一节加到**命中小节所在的学科**下；这张卡片还没指向
  任何小节时，先用下拉选一个学科再新增。标题与锚点默认是「课程名 + 小节N」，
  锚点**重复时会自动换成另一个可用的名字**（不会等到保存才报错）。
- **删除一节**：如果**还有卡片指着它**（某张卡片的靶点或标签写的正是这个锚点），
  系统会**拒绝**并告诉你*是哪门课*在指着它 —— 请先改那门课的标签 / 靶点，再回来删。
  理由很实在：卡片就是靠这个锚点跳转的，锚点没了，网站上那张卡片点进去会落到空处
  （网站不会报错，只是停在页首，很难发现）。这条判定在服务端也拦一次，绕不过去。
- 只有**正文真的被改过**时才会写正文那一次：没改正文就只写课程与报价，不会每次都整份重写。

> 不在这张卡片上的东西仍在页面下方的「**学科级设置与未挂到卡片的正文**」面板里：
> 课程页标题、学科名 / 顺序 / 整组暂未开放 / 学科导语、新增学科，以及那些**没有卡片指向**的小节。
> 那块面板里也会列出全部小节，带「课程卡片 X 管」/「未挂到卡片」的标记：带标记的日常在卡片里改；
> 写着「未挂到卡片」的，要么在某张卡片里把它选作靶点 / 标签，要么删掉。

其余几条老规矩：

- 要开一门网站上还没有的课：先到「课程分区」建一个栏目（例如「兴趣才艺」），
  再回「课程库」→ 填课程名、分区选它、可开班型、备注 → 添加。
  **添加后立刻能在排课、咨询、学生报课里选到它**。
- 两件容易误会的事：
  - 在课程库加课**不会**让宣传网站上多出一张卡片 —— 网站要展示得改内容文件（见内容维护手册）；
  - 课程名是**引用键**（排课、教师科目、报课记录都按名字记），所以课程名不能重复：
    系统会拦住重名，请把「围棋」和「围棋课」统一成一个叫法。
- **v32 起课程以库为准**：「从网站同步课程」「从网站导入内容」两个入口已删 —— 新增课直接在这一页「填写新课程」。
- **和报价的关系**：课程库决定「能排哪些课」，报价页决定「这门课多少钱」。
  每门课下面写着它的报价状态（例如「报价 200 元/节（兴趣才艺）」或「未定价」）。
  报价有两种改法：在课程卡片的「报价（元 / 节）」里填（推荐 —— 跟卡片一起保存），
  或者到左侧「报价」→「课程库课程定价」里勾选课程、选一个阶段、填基础价。
  卡片里**留空基础价表示「这门课不参与报价页」**（内部课程用不上），不会把价格清成 0。
  课程库里改了名字或设为暂未开放，报价配置会**自动跟着变**；删掉后台新增的课程时，
  报价里那一项会保留但自动停用（不会悄悄消失）。

> ⚠️ **课程库空着的话，排课 / 报课 / 咨询的下拉里什么都选不到。**
> 新装系统时内容文件里的课程卡片会作为**初始数据**进库（不用你点任何按钮）；
> 缺哪门课就在「课程 → 课程台账」页直接「填写新课程」加一门 ——
> v32 起不再有「从网站同步课程 / 从网站导入内容」两个入口（机构口径：现在都以后端为主）。

#### 7.0.3 课程类型（课程由哪四个维度组合而成）

「课程类型」页（左侧导航 → 课程类型）管的是**维度**，不是一条条课程 ——
这是这一页最容易误会的地方，先说清楚：

> 一门课 = **学段 × 学科 / 项目 × 内容模块 × 班型** 的一次组合。
> 例如「小学 · 语文 · 一年级 · 一对一 · 网课」。
> 机构那份清单全铺开有四百多条，但它们全是这四张表的**乘积**：
> 所以这一页四张表，组合不写在这里。

> **「网课」「网课+答疑」「网课+一对一针对性答疑」「托管」这些不是"交付形态"**（v26 更正）：
> 它们是**独立的项目**，与小学 / 初中 / 高中那些按学段的课程**没有组合关系**。
> 它们在「学科与项目」页签里（类别选「项目」，挂在「不分班型项目」分组下），
> 不在这张矩阵的列里 —— 因此系统里不会出现"小学语文 × 网课"这种机构并不卖的课程。

**为什么不做成"一门课一条记录"**：加一个语种、加一级等级，记录数就翻倍；
改一次班型名字要在几百条里改一遍；而且 AI 排课与"这个学生该补什么"的诊断推荐
只能靠把几门课硬绑在一个诊断项上。维度是数据、组合按需解析，后面这两件事才做得动。

页面上五个页签，一屏一个：

| 页签 | 里面是什么 | 加东西的典型场景 |
| --- | --- | --- |
| **学段** | 小学 / 初中 / 高中 / 大学 / 其他类型 | 机构开始做「研究生」或「成人」这一支 |
| **学科与项目** | 语文 / 数学 / 英语 / 雅思 / 托管…（**学科与学段解耦**：勾「开设学段」即可） | 新开一门「编程」；把某个学科挪进「外语等级考试」这类分组 |
| **内容模块** | 教材进度（一年级…必修选修）/ 能力点（客观题 / 阅读 / 文言文 / 作文 / 听力）/ 语言等级（CEFR-A1…B2 / N5…N1 / CET-4·6） | 加一级「CEFR-C1」；加一个「口语」能力点 |
| **班型** | 一对一 / 一对二 / 一对三 / 一对多（4-8）/ 班课（9-20），带人数区间与计价模式 | 开一个「一对六」 |

每行都能改名、换类别、勾学段、换分组、↑↓ 排序、删除；右上角「新增」加一行；
底部「保存修改」一次落库，「**恢复种子**」把这一份恢复成机构清单的初值（后台改过的会丢）。

几条口径：

- **改名与网址无关，也不影响已有课程**：全系统按 **id** 引用这些维度，
  因此把「班课（9-20）」改成别的写法，报价的系数、已有课程与报课记录都跟着走；
- **班型是全系统唯一口径**：报价里的「班级类型」就是这份班型表（逐个同名），
  后台各处的「班型」下拉也取自这里 —— 改完**立刻**生效，不用重新构站；
- **模块按学科分开维护**（页签里先选学科）：两个学科各有一个「听力」是两条互不相干的模块，
  这不是重复，也不必共用；**没有模块的学科照样能开课**（组合只用到学科那一层），
  但诊断推荐要模块才能说清"补的是哪一块"；
- **删除要谨慎**：删一个学段或学科之前，先想想有没有课程、报课、排课还在引用它。
  服务端会拦住"引用了不存在的行"这种明显错误，但"已经没人用了"这件事只有你知道；
  删学科时会连同它下面的模块一起删（页面上会先问一次，并告诉你少了几个模块）；
- **删维度会连带清掉引用它的开放组合**：删一个班型 / 模块 / 学科时，
  确认框会告诉你"还有 N 条开放组合引用着它"，保存后那些组合的勾选**会一起被清除**
  （日志里也记着"连带清掉几条"）。组合的开放与否是经营决定，所以只有在**你自己动手删**
  的时候才会被动到；从外部导进来的一份不一致数据不会被偷偷清掉，而是列在「开放矩阵」页
  的「失效的组合」那一块里，由你点「清除这些失效设置」处理。
- **校验是实时的**：重名、引用不存在的东西、班型人数写反、学段或班型被删空、
  新加的行还没写名字 —— 这些都会在页面上用红字列出来，红字在时保存按钮是灰的。
  服务端会再拦一次（同一份校验），所以不必担心"界面骗人"；
- **组合本身（哪一条开放、多少钱）** 不在这一页：那是下一步的「开放矩阵」，
  要等这一份维度表稳定下来再做（否则矩阵的行列天天变）。

> **谁能改**：技术管理员、财务管理员、招生老师。普通教师能看不能改
> （老师要用「班型」下拉，但"本机构开哪些班型"不该由每位老师各改一份）。

#### 7.0.4 开放矩阵（哪些组合真的开）

「课程类型」管的是**维度**（可以有哪些学段 / 学科 / 模块 / 班型 / 交付），
「开放矩阵」管的是**组合**（本机构到底开哪些）：

> 一条组合 = 学科 × 内容模块 × 班型
> 例如「语文 · 客观题 · 一对一 · 网课+答疑」。

为什么单独一页、单独一张表：全部组合铺开是六百多条（133 个学科模块格 × 5 班型），
而机构真正开的通常只是一小片 —— 所以只有**你表过态**的组合才存下来。

**三种格子**（点一下依次循环，所以按错了能退回去）：

| 格子 | 含义 |
| --- | --- |
| 空格 | **还没设过** —— 还没人想过这件事（新增班型 / 新增模块之后会一片片冒出来，那正是要你回来看一眼的信号） |
| ✓ | 开放 |
| ✗ | **明确关闭** —— 你表过态：这条不开（例如"这个班型不做网课"）。它和"还没设过"不是一回事 |

**怎么用**：

0. 矩阵的**列就是「课程类型」里的班型**（当前 5 个）；将来在那一页加一个班型，这里就多一列；
1. 上面先选**学段**（矩阵很大，默认落在第一个学段；选「全部学段」时批量动作会作用到所有行）；
2. 想找得快就在右边按学科 / 模块名筛（例如输「阅读」只看阅读相关的行）；
3. 一行一行点，或者用批量：
   - 「全部开放 / 全部关闭 / 全部清除设置」——对**当前筛选出来的**所有格子；
   - 按**班型**整片勾（「一对一：全开 / 全关」…）；
   - 每个学科标题那一行还有「本学科全开 / 全关 / 清除本学科设置」；
4. 点「保存修改」一次落库（在那之前都只是草稿，刷新会丢）。

**几条口径**：

- 「**（不分模块）**」那一行是"这门课不细分到模块"的组合 —— 它是合法的一条，
  不是缺漏。诊断推荐才需要模块那一层（"这个学生该补阅读还是文言文"）；
- **学段不在这张表里**：选了哪一段只影响"看到哪些行"。同一条组合不会因为"小学和初中都开"
  变成两行 —— 因为模块各自挂在学科下，学段 + 学科 + 模块已经唯一确定一门课；
- **价格不在这里**：课程价与班型系数仍在「报价」页。这一页只管"开不开"；
- **AI 排课与诊断推荐按这份表判定**，而且会把「没设过」与「明确关闭」分开处理
  （没设过＝要先问你，明确关闭＝就是不做）；
- **删掉一个维度**（学段 / 学科 / 模块 / 班型）时，引用它的那些组合会在保存时
  被**一起清掉**（删除确认框里会先说清有几条）—— 因为那些格子在矩阵里已经没有列 / 行了，
  留着它们只会让"保存"永远报错却找不到改哪一格。想恢复就重新勾一遍；
- 万一页面上出现「**失效的组合**」那一块（从外部导进来的一份不一致数据），点一下
  「清除这些失效设置」即可 —— 那一块就是为这些"看不见却会让保存被拒"的行准备的出口。

> **谁能改**：技术管理员、财务管理员、招生老师（与「课程类型」同一档）。普通教师只读。

### 7.1 排课
### 7.1.1 排课前先查课时：**不够就不给排**

机构的规则是「**课时不够就不排课**」—— 宁可少排一节，也不要欠账（欠着的课时事后很难收回来）。
所以排课之前系统会先算一遍：这几位学生在这门科目上**还能排几节**
（= 该科目剩余课时 − **已排未上**的节数），并按结果决定：

| 情况 | 系统怎么做 |
| --- | --- |
| 单节排课，课时不够 | **保存按钮不可用**，并写明是谁不够；服务端也会再拦一次（直接调接口同样拦） |
| 批量排课，要的节数超过还能排的 | **按"还能排几节"封顶**，并在预览里明说"你填了 20 节，只排 8 节（少 12 节）、谁不够" |
| 多人班课，各人剩余不同 | 按**剩余最少的那位**算（班课是同一份课表走） |
| 补课 | 同样先查课时：不够就先续费（补课也扣 1 节） |
| **改课**（把已有课改成别的科目/学生，或把「已取消」翻回「已排」） | **同样复核**：新科目/新学生没课时就拒绝（点名是谁不够）；只改备注或改时间不受影响 |

> **课时用完了怎么办**：到「学生 → 报课与课时」页点「报课」或「续费」，课时到账后就能排了。
>
> **改课也算排课**：新建被拦住了，不代表改一改旧课就能绕过去 —— 服务端是同一套判定，
> 只是复核时会把"这节课自己"排除掉（否则改个备注都会被自己挡下来）。
>
> **万一还是超用了**（例如排课时够、后来退课或手工调减课时）：标记已上时系统会**明确提示
> "某某 已超用 N 节"**，不会假装"剩余 0"。这时请续费，或用报课面板上的
> 「**调整课时**」按实际情况补录 / 纠错（填正数加、负数减，**必须写原因** ——
> 它改的是账，系统会连同原因一起记进操作日志与课时流水）。

### 7.1.2 按周批量排课（一次排一串，不用一节一节点）

学生报了 20 节、每周二、五 17:00 上课 —— 不用点二十次。做法：

1. 「课程安排」页右上角 →「**按周批量排课**」；
2. 填：科目、班型、教师、教室、上课学生；
   - **`排多少节` 有小字提示**：选好学生与科目后会显示"该科目剩余课时 N 节"（这个数来自报课记录，
     不用你去翻）；
3. 填「按周重复」：**起排日期 + 每周几（可多选）+ 开始时间 + 时长 + 节数**；
4. 点「**预览**」→ 列出将生成的**每一节（几月几日 周几 几点）**，
   并标出哪一节撞了谁（教师已有课 / 教室被占 / 学生已有课 / 教室该时段不开放 / 超容量 / 科目不符）；
5. 点「**排入这 N 节**」→ **能排的排上，冲突的跳过并逐条说明原因**。

几条要知道的：

| 事项 | 说明 |
| --- | --- |
| **不会硬塞** | 与已有安排冲突的节**跳过**（在结果里逐条写清原因），事后不用一节节去查 |
| **预检与写入是同一套判定** | 预览说能排的，写入时就能排 —— 不会出现"预览说行、写入说不行" |
| **调休、节假日、寒暑假不自动跳过** | 就是"按星期几往后数"（机构确认这类手动处理：挪课改单节时间，缺课走「待补课」）。哪几天是法定假日、哪几天是调休上班，看后台「**日历 → 假期与作息**」（见 §8） |
| 排完还能改 | 每一节都是普通排课，可单独改时间 / 标记已上 / 取消 |
| 上限 | 一次最多 200 节（防手滑填成 2000） |


「课程安排」→「排课」→ 填：日期、开始时间、时长、状态、科目、班型、教师、教室、备注，
并在「**上课学生（已选 N 位）**」里勾选学生（**至少要选一位**，否则不能保存）。

保存按钮是「**排课**」（改已有的课时是「保存修改」）。

> **课次与课时的口径**：**已取消的课不算课次、也不算课时**（今日概览、课程安排、课表与占用、
> 统计都按这一条算；有几节被取消会单独显示成"另有 N 节已取消，未计入"）。
> 早先四个页面各算一遍，同一屏能出现两个不同的小时数 —— 现在只有一处实现
> （`lib/backend/lesson-stats.ts`）。

### 7.2 保存前系统会拦下这几种情况

| 情况 | 提示方式 |
| --- | --- |
| 同一**教师**时间重叠 | 提示与哪节课冲突（教师、教室、学生三类分开提示，因为处理方式不同） |
| 同一**教室**时间重叠 | 同上 |
| 同一**学生**被排了两节 | 同上 |
| 教室**不在可用时段** | 提示「该时段不开放」并禁止保存 |
| 学生数**超过场地容量** | 提示「学生数超过场地容量，请换场地或拆课」 |
| 教师**科目不符** | 教师登记了可带科目但不含这节课的科目时提示 |

**相邻不算冲突**：前一节 10:00–11:00、后一节 11:00 开始，是允许的。
**已取消的课不占时间**：取消了就不再挡别的课。

> ⚠️ 这些提示是**帮你先发现问题**，不是只在提交时才拒绝 —— 页面上改动时间/老师/教室就会实时提示。

### 7.3 标记已上（按出勤扣课时）

列表里每节课的「操作」列有「**标记已上**」（已经标记过的课不再显示这个按钮）。

- 点它时，系统按**每位学生的出勤**决定扣不扣课时，并写入课时流水。
- **幂等**：已经标记过的课再点一次**不会重复扣课时**（会提示「这节课之前已经标记过『已上』，没有重复扣课时」）。
- 课节状态只有三种：**已排 / 已上 / 已取消**。

> ⚠️ **把状态从「已上」改回「已排」或「已取消」时，已扣的课时会自动退回**（按流水撤销，留痕）。
> 也就是说「点错了」是可以救的，但会留下操作记录。

### 7.4 课堂记录（出勤 / 专注 / 互动）

每节课上可以给每位学生写课堂记录：**出勤**（到课 / 请假 / 旷课）、专注、互动、备注，
出勤选「请假」时会出现「**请假时间**」字段。

> **请假时间决定扣不扣课时**（见下）。老师请务必填 ——
> 不填的话，系统会按**临时缺课**处理（扣课时），因为「没记录」不能默认成对机构有利的解释。
> 补录之后课时会自动调整回来。

### 7.5 请假与补课：24 小时规则

一句话口径：**一节课扣一次，扣的是「这次时间被占用」。**

| 情况 | 扣课时 |
| --- | --- |
| 到课 | 扣 1 |
| **提前 24 小时（含）以上请假** | **不扣** |
| 临时请假（不足 24 小时）、旷课、请假但没记请假时间 | 扣 1 |
| 补课 | 扣 1（补课重新占用了老师和教室的时间） |

由此推出两个家长最常问的例子：

- **提前请假 + 补课 = 扣 1 节**（等于正常上了课）；
- **临时缺课 + 补课 = 扣 2 节**（缺课占了一次时间，补课又占一次）。

**安排补课**：在「课程安排」的待补课列表里点「**安排补课**」→ 填日期、开始时间、时长 →
点「**确认补课（扣 1 节）**」。补课课节会带上「补课 · 原课 X月X日」的标记，列表里一眼看得出。

> 「待补课」看的是**有没有上到课**，不是有没有扣课时 ——
> 所以提前请假（没扣课时）的学生，同样会出现在待补课里。

### 7.6 作业记录与阶段测评

- **作业记录**：科目、日期、正确率、本次错题知识点、提交情况（按时 / 迟交 / 未交）、备注。
- **阶段测评**：科目、测评日期、本次分数、薄弱知识点、备注。

这两项填了之后，「待跟进」才可能挑出「作业异常」「测评下滑」——
**不填就不会提醒**（系统不拿「没有记录」当「表现不好」）。

## 8. 日历、假期与作息、课表

> **谁能用**：所有登录的人（普通教师看自己的课表）；寒暑假段的录入归 技术管理员 / 财务管理员 / 招生老师；节假日「重新抓取」只有技术管理员。

- **日历**（一页两个页签）：
  - **看课（周 / 月）**：左上角切**周**或**月** —— 同一件事的两个缩放级别（同一条数据、同一个"点开某天看明细"）。
    **只读**，避免两处都能改导致冲突。
    - **周视图**：七天卡片，每张写着当天的课与时段；「← 上一周 / 本周 / 下一周 →」；
    - **月视图**：**同一张日卡片**（内容和周视图完全一样：日期、节数、日子徽标、适用时段、
      当天的课与"空档"），只是按日历的排布摆成"一周一行、周一到周日七列"。
      **上个月 / 下个月的卡片淡一档**（它们与本月同处一行，但不是这个月的主角）；
      窄屏不把七列压扁，而是整块横向滚动。
      点任意一张卡片 → 下面的「选中那天」就换成那一天的明细（点隔壁月的卡片会标一句「不在本月」）；
      切换周/月时选中的那天不会丢。
    每天的栏头会标出
    **这一天是什么日子、按哪一组时段排**：`休`（法定假日）/ `班`（调休上班日）/ `寒`、`暑`（寒暑假段内）
    / 工作日 / 周末，下面一行写着"工作日组 17:30–21:30（2 段）"或"周末组 08:00–22:00（6 段）"；
  - **假期与作息**：① **寒暑假段**（机构每年手动录入，见下）② 两组上课时段的**只读**展示
    ③ **法定节假日年度表**（原来的「节假日」页，含两个来源的校验结论与「重新抓取」）。
- **课表与占用**：两个视角 —— 「按教师」（教师课表）/「按教室」（教室占用），按周切换；
  可以点「**导出本周课表（ICS）**」，老师在手机上导入日历就能看自己的课，不用来后台查。
- **空档会单独显示成虚线卡片**，三段各有各的说法：
  「上课前空 9 小时 30 分钟」（`08:00–17:30`）、「两节课之间空 30 分钟」（`18:30–19:00`）、
  「下课后空 1 小时」（`21:00–22:00`）。每天栏头还会给出**当天空档合计**
  （如「3 · 空 11 小时 30 分钟」），一眼看出哪天空、哪几天满。
  四条口径（都影响你怎么读它）：
  - **课前 / 课后按「上课时间」算**（取自内容里的「上课时间」字段，默认 8:00–22:00）：
    机构改上课时间，头尾两段跟着变；课排在窗口之外时不会凭空生出空档；
  - **已取消的课不算占用**：所以取消一节课后，空档会把两边连成一整段；
  - **时间重叠的课之间不会显示空档**（说明这两节课排重了，要去课程安排里核对）；
  - **一节课都没有的那天不显示空档卡片**（整天空着由「空档」空状态表达），
    因此那种日子栏头也不会显示空档合计。

### 8.1 假期与作息（哪一天按哪一组时段）

> **谁能用**：所有登录的人都能看；**寒暑假段的录入**归 技术管理员 / 财务管理员 / 招生老师；
> 节假日「重新抓取」只有技术管理员。

机构 2026-09 定下的口径（原话）：**假期要上课**；**寒暑假开始和结束的日期每次手动输入**；
**作息和现在的周末上课时间完全一样**；寒暑假**按学段**录。

于是每一天都归到**两组时段**之一：

| 这一天是什么 | 能不能排 | 按哪一组时段 |
| --- | --- | --- |
| 学期内的工作日 | 能 | **工作日组**（「时间安排」里的「工作日排课」：17:30–19:30、19:30–21:30） |
| 学期内的周末 | 能 | **周末组**（「周末排课」：08:00–22:00 六节） |
| **法定假日**（国庆 / 春节 / 清明…） | **能**（照常上课，假期是旺季） | **周末组** |
| **调休上班日**（周末被调成上班） | 能 | **工作日组**（学生要上学，白天的课得挪到晚上） |
| **寒暑假段内** | 能（每天都行） | **周末组**（作息与周末相同） |

优先级：**寒暑假 > 调休上班日 > 法定假日 > 周末 / 工作日**。最需要注意的一条是它为什么这么排：
**春节的法定假日与调休上班日都落在寒假里**，而那时学校已经放假、学生不上学，
所以寒假整段按假期作息（否则"寒假里的那个调休周六"会被判成只能排晚上）。

**两组时段只有一份来源**：「网站内容 → 时间安排」里那两组（工作日排课 / 周末排课）。
日历页只把它们**读出来显示**，不另设一份配置 —— 网站上家长看到的时间与这里判定的口径必须同一份。

**寒暑假段**（「日历 → 假期与作息」里录）：一段 = 名称（寒假 / 暑假 / 自定义）+ 类别 + **学段** + 起 + 止。
- **每年手动录**，系统不推算（不按农历、不按往年）；
- **按学段**（小学与初中的放假日期通常接近但不完全相同；日期一样时勾多个学段、录一条即可）；
- 页面上「复制」一段可以少填几个日期；
- **允许重叠**（国庆集训套在暑假里是正常安排），但页面会提示，重叠的那几天按"最早开始"的那一段显示；
- 没录的时候：每一天只按"星期几"判（工作日 / 周末），与今天的行为一致。

**它只供查看，不会自动改排课。** 「课程安排」里的批量排课仍然是"按星期几往后数"
（不识别调休、节假日、寒暑假），教室可用时段也是按星期几配的 ——
遇到调休与节假日，仍然像现在这样**手动处理**（挪课改单节时间、缺课走「待补课」）。
这句话在页面上也写着，免得有人以为"排课已经自动跳过假期了"。
机构已经定了"后续的排课再另外安排"：等那一步接上这份判定之后，页面上的提示会跟着改。

**为什么这件事值得单独一张表**：家长会问、排课要看，而它有两个容易记错的点 ——

- **放假日不等于停课日**：假期通常正是旺季（白天反而能排课）；
- **调休上班的那几个周末**才是真正打乱作息的（学生要上学，白天的课得挪到晚上）。

**数据是从哪来的（两个来源，逐日比对一致才会写进来）**：

| 来源 | 地址 | 说明 |
| --- | --- | --- |
| Apple 日历「中国大陆节假日」 | `calendars.icloud.com/holidays/cn_zh.ics` | 带机器可读标记（放假 / 调休上班），国内网络可达，作**主源** |
| 国务院公告口径（holiday-cn） | `github.com/NateScarlet/holiday-cn`（三个镜像轮着试） | 自动抓 gov.cn 公告，只有安排日、没有噪音，作**校验源** |

- **两个来源逐日比对**：调休上班日必须完全一致；国务院列的放假日 Apple 那份必须都有；
  Apple 多出来的放假日**必须都是周六或周日**。对不上就**拒绝写入**并列出差异，由人去查公告 ——
  这种数据错了会直接影响排课与家长沟通，而它一年只看一两次、没人会逐日核对，
  所以宁可这次没导进来（页面上会写着缺哪一年），也不要静默用错数据。
- 顺带说清一处**口径差异**：Apple 会把假期块里正好落在周六周日的那两天一起标成放假，
  而国务院口径只列"法定安排日"。所以 2024 年两边的天数差 2 天（6/08、6/09）—— 那不是打架，
  规则里已经把这种情况单独判成"口径差异"，不算冲突。
- **2027 年及以后暂时没有数据**：国务院通常在上一年 11 月公布次年安排，公布前**没有数据是正常的**。
  页面上会写"某年还没有数据"，而**不会**把它当成"全年无假期"。

**怎么更新**（一年一两次）：

- 界面上点「**重新抓取（今年与明年）**」（技术管理员）。抓完逐年告诉你结局：
  已写入 / 还没有公布 / 没有通过校验（哪一条对不上）；
- 或者命令行 `npm run holidays:fetch`（不加参数就是今年与明年，也可以
  `npm run holidays:fetch -- 2026 2025`；加 `--dry-run` 只校验不写文件）。
  它走的**是同一段代码**，所以不存在"命令行能过、界面过不了"。

**数据的存放与手工修正**：一年一个文件，在 `data/holidays/<年>.json`（进版本库，
`git log` 能看出哪一年哪天改过）。它**不在数据库备份里**（丢了重新抓一次即可）。
想手工加一天特殊安排就直接编辑那个文件 —— 读的时候会校验，坏数据会**明确报错**，
不会静默当成"这天没假期"。

## 9. 统计（数字的口径）

> **谁能用**：招生老师（招生口径）· 财务管理员（收费口径）· 技术管理员；普通教师看自己的课时。

「统计」页回答的是决策问题：这间教室值不值、谁排满了、学生在什么阶段退。

| 指标 | 口径 |
| --- | --- |
| 教室利用率 | 已排时长 ÷ 可用时长。教室**设了可用时段**就按时段算；没设的按**上课时间**估算（每天 8:00–22:00，**14 小时** × 7 天）。已取消的课不占时间 |
| 空档日 | 该教室有可用时段、但这天一节都没排 |
| 教师课时 | 按教师汇总已排/已上的课时量 |
| 退课与流失 | 已退课报课数、退课时平均已上节数、退掉的剩余课时、暂停/结课学生 |

> 注意：利用率的分母用的是**上课时间（8:00–22:00）**，不是前台的**营业时间（9:00–21:00）**——
> 教室能不能用取决于「这个时段能不能上课」，不是「前台有没有人」。

## 10. 待跟进：今天该联系谁

打开就是清单，不用自己想。每一条都带：等级（紧急 / 提醒 / 关注）、原因（带具体数字）、

**触发规则与阈值**（全部集中在一处，要调松紧只改一处）：

| 类型 | 触发条件 |
| --- | --- |
| 课时不足 | 某科目剩余课时 **≤ 5 节**（**≤ 2 节** 标为紧急）—— 判据是**剩余最少的那一门**（排课受单科限制：数学只剩 3 节就排不了第 4 节数学课）；括号里同时给"全部在读科目合计"。阈值与判据只有一处实现（`lib/backend/followup.ts` 的 `FOLLOWUP_RULES` + `lessonBalance`），今日概览的「课时预警」用的是同一份，两个页面不会给出不同答案 |

| 测评下滑 | 最近一次比上一次**低 10 分**及以上（低于 10 分只标「关注」） |
| 出勤异常 | 最近 **5** 次记录里，旷课 ≥ **1** 次（提醒）或请假 ≥ **2** 次（关注） |

### 10.1 话术专区（按场景直接复制）

左侧「话术」页把机构日常要说的话按 11 个场景摆好了（接待 / 报价 / 试课 / 排课 / 请假 /
续费 / 欠费 / 反馈 / 投诉 / 退费 / 教师），一共 30 多条，每条都写清了**什么时候用**、
**该说什么**、**不该说什么**。用法：

1. **先筛**：顶部按场景点分组，或用搜索框搜内容（例如搜「24 小时」「手续费」）；
2. **想套用到具体学生**：在「套用到某个学生」里选学生（有多个在读科目的再选科目）——
   话术里的 `{学生}` `{科目}` `{剩余课时}` 会自动填好；
3. 卡片右边点「**复制**」，粘到微信里；缺的占位符会在卡片上标红提示（例如 `{老师}` `{时间}`），
   提醒你补上再发；
4. 一次要发很多条时，点「复制全部」复制当前筛选结果（带分组标题）。

三条要知道的：

- 这些话术的**规则口径与系统一致**（提前 24 小时请假不扣课时、试课满 10 节免费、
  只报 1 节加收 10%、退费默认按实付比例退）—— 改了规则代码后话术会跟着一起更新；
- 里面**不会出现内部信息**（教师分成、机构留存这类内容一条都没有），可以放心转发；
- 但**它仍然是草稿**：称呼、时间、语气请按这位家长改两句再发。

> ⚠️ **话术是草稿，不是定稿。** 里面填好了具体数字，但发之前请自己看一遍、按这位家长的语气改两句 ——
> 别让家长收到机器味的话。

## 12. 报价：改价格、给家长试算、算教师课时费

> **谁能用**：试算 → 招生老师 · 财务管理员 · 技术管理员；**改价 → 财务管理员 · 技术管理员**。


#### 12.0.1 班型的名字以「课程类型」为准（v25）

报价这一页里的**班级系数**（一对一 1.0 / 一对二 0.7 / 一对三 0.6 / 一对多（4-8）0.5 /
班课（9-20）按人数分摊）是"这个班型多少钱"，而**班型的名字与人数的范围**来自
「课程类型」页（那是全系统唯一口径）：

- 在「课程类型」页把班型改名（例如「一对三」→「一对三（小组课）」），报价页、网站上的
  报价器、以及你导出的 `data/site/pricing.md` 片段都会跟着用新名字，**不用手改**；
- 引用它的地方（课程库的「可开班型」、学生档案的班型、排课的班型）只认**班型 id**，
  改名不影响它们；
- 报价页顶部会在两种情况下给一句提示，两种都要处理一下：
  1. **「课程类型里有 N 个班型还没有系数」** —— 新加的班型还没定价，家长问到它时**算不出价**，
     在这里把系数填上即可；
  2. **「这里还有 N 个班型在课程类型里已经找不到了」** —— 那些行已经不会被任何课用到，
     去「课程类型」页确认是改名了还是删掉了（改名的话，把这一行的名字跟着改回来更有意义：
     直接删行会让历史报价的口径少一档）。
- **同一个班型不能有两行系数**（会出现"这个班型算哪一行"两说），保存时会被拦住。

### 12.1 四个价格维度（先理解这张表，后面都靠它）

| 维度 | 含义 | 默认 |
| --- | --- | --- |
| **基础价** | **一对一、1 小时、报 2 节及以上**的价格（元 / 节）—— 所有换算的基准 | 分阶段设定 |
| **科目系数** | 同一阶段里不同科目的差异 | 1.0（不加价） |
| **班级系数** | 人越多每人越便宜 | 一对二 0.7、一对三 0.6、一对多 0.5 |
| **时长乘数** | 一节课上多久（1 小时为基准） | 1 / 1.5 / 2 小时 → ×1.0 / ×1.5 / ×2.0 |

再加上两条规则：**手续费**（只报 1 节时加收，默认 10%；报 2 节及以上不加收）、
**试课**（报课后满 10 节则试课免费，否则按课程原价收 1 节试课费）。

两个**不是乘系数**的例外：

- **班课（9-20 人）**：按「教师课时总费用 ÷ 班级人数」分摊，不用班级系数；
- **试课费**：永远按课程**基础价原价**收，不带科目系数、班级系数、时长与手续费。

### 12.2 给家长试算

「报价」页上半部分：选课程、科目、班型、每节课时长、报课节数（**节数手动填**），
点「算一下」→ 显示**课单价 / 节**、正课总价、试课费、**总价**，以及每一项是怎么来的。

### 12.3 教师分成（教师课时费）

课内课程里**按系数计价**的班型（一对一定制课 / 一对二 / 一对三小组课 / 一对多小班课，1–8 人）适用：

```
教师课时费 = 小时数 × (课程单价 / 小时) × (0.4 + (学生人数 − 1) × 0.1)
```

人话就是：**第一名学生 40%，此后每多一名学生加 10 个百分点**（2 人 50%、3 人 60% … 8 人 110%）。
时长按实际小时数乘（1.5 小时乘 1.5）。

- 公式里的「课程单价」默认取**课程标准单价**（基础价 × 科目系数，不含班级人数折扣），
  也可以在页面上切成**班型课时价**（再乘班级系数）。切换**不影响家长看到的报价**。
- **9 人以上大班课不适用**这条规则：那类按「教师课时总费用 ÷ 班级人数」另议，页面上会直接说明。
- 页面上的「**人数对照表**」把 1–8 人各自的**分成比例 / 教师课时费 / 机构留存**列出来，
  老师问「这个班我拿多少」直接看表。试算结果里也会显示教师课时费与机构留存。

### 12.4 改价格

下半部分可以直接改：基础价（每门课）、科目系数、班级系数、课时时长、手续费、试课门槛、
教师分成（基准分成 / 每加一名学生 / 单价口径）、其他项目。

点「**保存修改**」。改完请**再用试算器核对一遍** —— 页面上会做合法性检查
（系数必须是正数、手续费 0–100、课程名不能重复），不合法的配置**存不进去**。

> ⚠️ **改价不会自动上线。** 后台的价格存在**服务端数据库**里，它不会写回网站的内容文件；
> 而家长看到的报价页读的是 `data/site/pricing.md`。所以必须点「**导出配置**」，
> 把导出的内容替换进 `data/site/pricing.md`
> （替换「## 学习阶段」及其后的部分，**页面文案字段不要动**），再提交发布，家长页面才会更新。
> 改过、还没导出的配置会显示「后台修改（未导出上线）」。

## 13. 数据与备份

> **谁能用**：技术管理员（导出 / 导入 / 重置 / 恢复 / 批量导入）；财务管理员只导出财务数据。

**先说清谁在备份**：后端**每天自动备份一份**到 `server/backups/`，保留最近 **90 份**（约三个月），
**不需要你做任何事**（后端一启动就先把今天的份补上，之后每小时检查一次 —— 只要后端开着就不用管它）。
想手动备一次：`npm run server:backup`；看现有备份清单：
`npm run server:backup -- --list`。这套备份的**恢复能力演练过**（`npm run drill:restore`：
它自己起一个临时库，删库后只用备份文件恢复再核对一致，**不会碰真实数据**）。

页面上这些按钮，是给你**「要带走一份给别人 / 放到别处」**用的：

| 按钮 | 作用 |
| --- | --- |
| 导出全部数据（JSON） | **完整备份**（档案、报课、流水、记录、收款），也是换机器 / 换数据库时搬运用的文件 |
| 导出学生名单（CSV） | 只有学生名单，方便用 Excel 看 |
| 导出全部课程（ICS 日历） | 课表进手机日历 |
| 导入 | 用备份文件覆盖当前数据（**整体替换，不是合并**） |
| 恢复导入前的数据 | 导错了以后的后悔药 |
| 清空日志 | 只清操作日志，**不动**学生、排课、收款这些业务数据 |

> ⚠️ **导入是唯一能一次性毁掉全部数据的操作。** 它有三道保险：结构校验（不合格直接拒收、不动现有数据）、
> **导入前自动备份**、一键恢复。即便如此，导入前请自己再导出一份 JSON 放好。

> ⚠️ **自动备份和数据库在同一台电脑上。** 所以「这台电脑丢了 / 硬盘坏了」这种情况，
> 自动备份救不了你 —— 请**每周手动导出一次 JSON，并存到这台电脑之外**（网盘、U 盘、另一台机器）。
> 换电脑前也一定先导出。

> **页面上没有「重置示例数据」这个按钮了。** 那是早期纯前端阶段的临时功能（点一下会把机构真实数据
> 换成演示数据，很危险），已经撤掉。现在想「从零开始录真实数据」，走的是导入一份空库 JSON 这条路
> （这条路会先自动帮你备一份）。

### 13.1 按需导出（只导一部分）

「数据与备份」页有「按需导出」：**选数据集 → 选行 → 选格式 → 导出**。

- 数据集：学生 / 排课 / 教师 / 教室 / 课程 / 报课记录 / 收款记录 / 课堂记录；
- 选行：**不勾任何行 = 导出该数据集的全部**；勾了几行就只导这几行（顶部会写「共 N 条，已选 M 条」）；
- 格式：CSV（给 Excel）、JSON（给别的系统）；**排课**还可以导 ICS 直接进手机日历，
  **课程**可以导 Markdown —— 那是内容文件里的卡片行，粘进 `data/site/content.md` 的课程栏目即可；
- 常用场景：把某位老师的课导出来发给他（排课 → 搜索老师姓名 → 全选当前结果 → ICS）；

导出完成后请看一眼提示里的「已导出 M 条（共 N 条）」——如果 M 小于 N，说明你只导了一部分。

### 13.2 批量导入：把表格里的名单一次录进来

学生、教师、教室、课程都支持**批量导入**（CSV 或 JSON）。**两个入口，功能完全一样**：

- **各个页面上（推荐）**：「学生 / 教师 / 教室 / 课程库」页右上角，紧挨着「新增…」按钮
  有一个**次要样式的「批量导入」按钮**，点开就是导入面板 —— 这里的导入对象已经定好，
  不用再选（你正看着那份名单，导它就是了）；再点一次收起。
- **「数据与备份」页**：那里也有一个「批量导入（CSV / JSON）」面板，可以**切换导入对象**，
  适合一次处理几种数据；面板默认收起，不会占着页面。

**四步**：

1. **选对象**（在「数据与备份」页要选；在各实体页不用选）→ 点「下载 CSV 模板」或「下载 JSON 模板」；
2. **填数据**：模板第一行是表头（**列名不要改**），第二行是示例（可删）；存成 .csv 即可。
   - 用 Excel / 数字表格填写没问题：中文列名、`是/否`、用 `|` 或 `、` 分隔多个值都能识别；
   - 也可以**不存文件**：在表格里复制一块，直接粘进面板的文本框；
3. **看预览**：面板先说清"识别到几列 / 可导入几条 / 哪几行不通过（带行号与列名）"，
   改完再导；
4. **点「导入」**：显示"新增 N 条，跳过 M 条（已存在）"。

### 13.3 导入遇到同名怎么办（覆盖 / 跳过 / 保留两份）

导入**默认不会偷偷改你的数据**：点「检查并导入」时，它先**体检**一遍 —— 如果发现同名记录，
会把这 N 条列出来（显示"文件里那条"与"库里已有那条"），**此时一个字节都没写**，然后让你选：

| 选择 | 会发生什么 | 什么时候用 |
| --- | --- | --- |
| **跳过**（默认） | 保留库里那条，忽略文件里这条 | 库里已经录好，只是文件里有重复 |
| **覆盖** | 用文件里的值**更新**库里那条（id 不变，是更新不是新建） | 文件是更新过的版本，要以文件为准 |
| **保留两份** | 两条都留：第二条加序号后缀（王老师 → 王老师（2）） | 确实是两个人 / 两间房，或想留档对比 |

- 可以先选「**全部这样处理**」，也可以**逐条**改（一行一选）；选完点「按以上选择导入」；
- 选之前随时可以「取消」，库里不会有任何变化；
- **覆盖只改文件里真的填了值的字段**：文件里空着的格子不会把库里已有内容清掉；
  报课记录、采集表、可用时段这些**结构性数据也绝不会被导入覆盖**；
- 「保留两份」对**学生**不加后缀（同名同家长可能是兄弟姐妹 —— 那是真实数据，不能改）；
- 不确定时选「跳过」：那是最安全的，之后到对应页面手工改也很快。

**四条要记住的规矩**：

| 规矩 | 说明 |
| --- | --- |
| **默认只新增，不覆盖** | 同名记录先列出来问你（上面那三个选择），你不选就不会动已有数据 |
| **重复导入是安全的** | 同一份文件再导一次：新增 0 条、全部同名待你处理，不会翻倍 |
| **导入前自动留一份快照** | 导错了可以到「数据与备份」页的「恢复导入前的数据」回退（注意：**只回退最近一次**导入） |
| **报课、收款、课时不在这里导入** | 那些牵动账本（实收、已用课时），必须在学生的「报课与课时」页走正规流程 —— 一次导入几百条"看起来对"的账，是最难查的事故 |

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 打开后台看不到数据 | 后端没在跑（页面会提示连不上），或后端连到的不是你以为的那个库 | 看终端 A 是否在跑 `npm run server`、页面顶部是否显示「**已连接后端**」；**换电脑或清缓存都不会丢数据**（数据存在服务端数据库里，不在浏览器里） |
| 忘了口令 / 口令提示不对 | 口令由后端生成，**不在网页代码里**，网页上查不到 | 打开 `server/data/admin-credential.json` 看；或停掉后端，用 `NEXGENEDU_ADMIN_PASSWORD=新口令 npm run server` 启动一次换掉（见第 1 节） |
| 用着用着被弹回登录页 | 后端重启过（登录状态不落盘，这是刻意的） | 重新输入用户名 `admin` 与口令即可 |
| 在线上站点打开后台（线上地址 + `/admin`）登不进去 | 线上是给家长看的静态站，那份后台连不上本机后端，会显示「后台需要本机后端」 | 后台只能在本机用：打开 http://localhost:3000/admin |
| 保存排课时提示冲突 | 教师 / 教室 / 学生时间重叠 | 页面上会说明和哪节课冲突：换时间、换人或换教室 |
| 提示「所选教室在该时段不开放」 | 课落在教室可用时段之外 | 换教室、改时间，或去「教室」页补一段可用时段 |
| 提示「学生数超过场地容量」 | 勾选的学生多于教室容量 | 换大教室，或把这节课拆成两节 |
| 学生课时该退回来 | 课节状态改错、或请假时间没填 | 把状态从「已上」改回「已排」，或补录请假时间 —— 课时会自动退回并留痕 |
| **保存时提示「这条记录刚被别人改过…请刷新后再提交」** | **两个人（或两个标签页）同时改了同一条记录**：你开始填的时候是甲版本，别人先保存了，于是你手上的内容已经过期 | **先刷新这一页，再重新填一次**。你原来填的内容不会被覆盖掉，别人改的也不会丢 —— 系统宁可让你重填一次，也不让任何一边白干（见 15.5） |
| 标记已上没扣课时 | 可能已标记过（幂等，不重复扣）；或该科目没有在读报课 | 看课时流水与提示；没有报课记录就先报课 |

| 改了报价但家长页面没变 | 后台改价不会自动上线 | 点「导出配置」→ 替换 `data/site/pricing.md` → 提交发布 |
| 报价算出来是 0 或很奇怪 | 配置被改坏（系数填 0 等） | 重新保存配置（非法值存不进去），或点「恢复为站点内容」 |
| 数据被清空了（有人跑了清空脚本、或导入了空库） | 业务数据被整体清掉（课程库与报价配置会保留） | 先别录新数据：用「数据与备份」导入最近一次 JSON；后端每天也自动备了一份，可请技术同事从 `server/backups/` 里找回（见第 13 节） |

## 15.1 连不上后端怎么办（看状态信号 + 手动指定地址）

后台**右上角**（登录页上则是在表单上方）有一个**后端状态信号**，它显示的是**真实探活结果**，
不是"配了就当作连着"：

| 显示 | 含义 | 该怎么办 |
| --- | --- | --- |
| 后端：已连接 · 数据库 v2 | 探活通过，且已登录，数据库与最近备份都正常 | 无需处理 |
| 后端：已连接（未登录…） | 后端活着，但还没登录，数据库细节看不到 | 正常登录即可 |
| 后端：检查中… | 正在探活 | 等一下；点开可手动"重新检查" |
| **后端：连不上** | 探活失败（后端没跑 / 地址或端口不对 / 端口上跑着别的程序） | 点开看原因，或手动填地址 |

点开这个信号，里面有：

- **当前地址**，以及它是"界面手动指定"还是"构建期配置"来的；
- **重新检查**：立刻再探一次；
- **自动探测本机**：依次试 `localhost:4000`、`127.0.0.1:4000`、`4001`、`4002`，
  找到第一个**自报为本系统后端**的地址并记住它 —— 端口上跑着别的程序时**不会被误判**；
- **手动指定地址**：直接填，例如 `http://localhost:4000`。

改完地址要**刷新页面**才全局生效（页面加载时才会决定"走本地还是走后端"）。

> ⚠️ 填**非本机**地址（例如局域网里另一台机器）时，登录口令会发到那台机器 ——
> 只有确认那是你自己的机器时才这么做，界面上会一直显示提醒。
>
> ⚠️ **端口号一定要看终端里打印的那行**：前端默认 3000，被占用时会自动换成 3001，
> 而后端默认 4000。前端地址与后端地址是两个东西，别混。

### 15.2 点「批量导入」以后"好像没反应"

九成是**它在等你做决定**，不是坏了。按这个顺序看：

| 你看到什么 | 发生了什么 | 怎么办 |
| --- | --- | --- |
| 面板里列出"有 N 条同名"，每条后面有选择框 | 这是**体检**（§13.3）：**此时一个字节都没写**，它在等你选「跳过 / 覆盖 / 保留两份」 | 逐条选（或先「全部这样处理」）→ 点「按以上选择导入」 |
| 写着"检查完成"就没了下文 | 体检通过之后**必须点**那一下导入按钮；只点「检查」不会写库 | 点导入按钮 |
| 写着"缺少必填列 / N 行没通过校验" | 体检失败：这种情况**一份都不导**（宁可全不导，也不导一半） | 按提示改文件（行号会指出来），或点「下载模板」对齐表头 |
| 写着"新增 0 条，跳过 N 条" | 这些记录库里已经有了（判重按名字），或你选的是「跳过」 | 想覆盖就选「覆盖」重导一次 |
| 那行结果小字**根本没出现** | 请求没发出去 | 看右上角后端状态信号（§15.1），确认后端在跑、已登录 |

导入的东西到哪儿看：在**同一页的列表里**（教师页就是下面那张表），不是浏览器缓存。

> **这一条是踩出来的**：导入流程最初只做了"体检"、忘了接着写入 —— 于是点了没反应、
> 库里也没数据，而提示又显示在面板很下面（看不见）。现在体检与写入是**同一段代码**
> （`runTwoPhaseImport`），结果就写在按钮旁边，`npm run check` 还有三条断言钉住
> "该写的时候必须写、不该写的时候一条都不写"。
> （当年出问题的那个「从网站导入」入口本身已在 v32 / v36 删掉，但这条流程还在，
> 批量导入走的就是它。）

### 15.2.1 左边导航以前会跟着页面一起滚（已改）

以前整页往下滑时，**左边的导航会跟着滚走** —— 想点「数据与备份」得先滚回页面顶端。
现在顶栏与左侧导航都**钉住**（滚动时不动）：导航一直停在左边，随时能点；
右上角的搜索框与「退出登录」也一直在。

改法是 `position: sticky`（**不是** fixed）：fixed 会把元素移出文档流、文档高度随之变矮，
而这套界面里有一批机制依赖"文档高度 / 窗口滚动位置"（就是你下面 §15.3 会看到的那一整套）——
sticky 的元素仍然占着原来的位置，只是渲染时钉在视口上，对它们完全透明。

两个附带的口径：

- 导航比屏幕还高时（导航项多、或窗口压得很扁），**导航自己会滚** —— 所以最下面那几项仍然点得到；
- 手机 / 窄窗口下不变：导航是顶栏下面的一条横向滚动条。

### 15.3 点某个按钮后页面跳回顶部

这一页把"跳回顶部"的**全部**成因写清楚（**对着现象认原因**，不必猜）。

先分两类 —— **看它"多久才跳"，一眼就能分掉一半**：

| 现象 | 是哪一类 | 往下看 |
| --- | --- | --- |
| 点下去**那一瞬间**就跳 | 即时跳 | 原因一 / 二 / 三 |
| 点完**过一会儿**才跳（几秒、十几秒、几十秒） | 延迟跳 | 原因四 / 五 / 六 |

#### 即时跳（点下去就跳）

**原因一：界面在刷新时把整块内容换成了"加载中…"。** 页面高度一下子从很高塌成一行，
浏览器只好把滚动位置拉回顶部，等数据回来你就得重新往下滑。

**原因二：画面里"滚动位置上方"少了一块内容。** 这一条最容易被当成"见鬼了"：浏览器要保住
你正在看的东西，位置上方一变矮，它就把滚动位置往上收 —— 收过头就停在顶部。页面上方
那些**会出现/会消失的东西**都属于这一类：页顶的提示条（成功 / 失败那两行）、
右上角后端状态那句话（会话失效时会换一种说法）、以及**被点的那张卡片上面的整块面板**。

**原因三（不是真的滚动，但看着像"页面乱跳"）：动作失败却什么都没说。** 例如登录已失效时
点「设为开放 / 暂未开放」——请求被服务端拒了，如果界面上一个字都不显示，人只会觉得
"点了就跳顶部"（其实是"点了没反应"，他就反复点、再往下猜）。现在这一类失败会**当场**写在
你点的那张卡片上。

#### 延迟跳（点完过一会儿才跳）

这一类是"点了之后**过一会儿**自己跳"，与点击那一瞬间无关，因此前面那三条**都不是它**。
只剩三种可能：

**原因四：定时器 / 轮询在几秒或几十秒后重渲染了页面上方的东西。**
本系统里与**课程库这一页**有关的定时器只有一处：连接状态复查（每 30 秒一次，另外切回窗口时
也会查一次）。它的结论就显示在**课程清单上方**那条提示条里（"已连接后端…" / "登录已失效…" /
"连不上后端…"），也在顶栏那个状态徽标里。这些说法的长短并不一样，换一次说法就是一次页高变化。
（另外「跟进」与「话术」两页各有一个"已复制"2 秒后自己变回"复制"的定时器 —— 那是**按钮上的字**
换回来，不新增也不移除块级元素、也不在课程库，量级只有一行字，不是这一页的成因。）

> **它跳的幅度很小。** 实测这四种说法：字号 `text-xs`、行高 `leading-relaxed`，每行 19.5px；
> 最短的那句（"正在检查后端状态…"）1 行，最长的两句 2~3 行。也就是说页面上方的高度差
> **最多一两行、约 20~60 像素** —— 页面上方矮一两行，浏览器只会把滚动位置往上收**几十像素**，
> 做不到"回到最顶部"。所以：**如果你分明看到它跳回了最顶部、还得重新往下滑很久，
> 那就不是原因四。**

**"响应回来那一刻的重渲染"也归到这一类，而且它同样做不到"跳回最顶部"** —— 这一条这轮专门量过、
逐项确认过（因为最容易怀疑它）：

- 点一次「设为暂未开放」要发两次请求（先写库、再读一次计数）。**实测在本机后端上，每次往返
  只有 2~3 毫秒，两次合计约 4.5 毫秒** —— 而且这两次请求是**浏览器直连后端**的
  （`NEXT_PUBLIC_API_BASE` 指到 :4000），根本不经过 Next 的开发编译，所以"dev 编译慢"这件事
  不在这条路上。
- 拿到响应后的那次重渲染，**被点击的那张卡片原地复用**（列表项的 key 是课程 id，`version` 变了
  也只是字段变了：它没有进 key、没有进排序、也没有进分组的键）—— 卡片的位置、DOM 节点都不变。
- 这次动作**只碰四个地方**：这张卡片本身、卡片上的结果提示、按钮上的"切换中…"、页顶那一行计数。
  **页顶那两条横幅（成功/失败）它一个字都不改**（失败也写在卡片上）。逐个量化高度差：
  | 重渲染波及的地方 | 高度差 |
  | --- | --- |
  | 被点的那张卡片（按钮文案变短、多一行结果提示、状态徽标可能换行） | 就地 ±1 行（19.5px），**不**在列表上方 |
  | 页顶那一行计数（数字位数变化） | 最多 ±1 行（19.5px） |
  | 每门课下面那行报价状态 | 0（这次动作不重读报价配置） |
  | 页顶提示条（连接状态） | 0（见本节原因四：结论没变时连重渲染都没有） |
  | 顶栏右上角的连接状态徽标 | 0（它在 `h-14` 固定高的顶栏里） |
  | 页顶那两条横幅（成功/失败） | 0（这个动作根本不碰它们） |
- **"要夹到 0 需要多大差值"的算式**：浏览器把 `滚动位置` 夹成
  `max(0, 文档高度 − 视口高度)`。要夹到 **0**，就必须 `文档高度 ≤ 视口高度`。而课程库这一页
  在清单之外还有约 700 像素的固定内容（页头、提示条、那段说明、按钮行、两个默认收起的面板），
  所以**只有当清单整块被卸载、或整页重载渲染出"正在检查登录状态…"那一屏时**才可能夹到 0；
  上面表格里那些 20 像素级的差值**在数学上做不到**。

现在的做法是两层，把它从"大概不会"变成"结构上不可能"：

- **结论没变时一次通知都不发**：复查回来的结论与屏幕上那份逐项比过，一样就**不通知**界面 ——
  组件根本不会重渲染，页面上一个字都不会变，页高自然也不变。也就是说"后端一直好好的"
  这种最常见的状态下，30 秒一次的复查在界面上**什么都不会发生**。
- **说法真的变了时，只许变高、不许变矮**：五种说法渲染在同一个段落里、共用同一份**最小高度**
  （3 行）。变高是安全的（页面只是把下面的内容往下推一点，浏览器不会因此调整滚动位置），
  只有变矮才会把滚动位置夹回去 —— 而那已经不可能了。

自检（`npm run check` 第 14 节）里三条断言守着它：纯函数的"什么算没变"判定表、
**真的跑两遍复查要求"一次通知都不发"**、以及"最小高度类必须与预留行数算得出来的一致"。

**再加一层兜底（就地动作期间的滚动守护）**：每点一次「设为开放 / 暂未开放」，系统会在
动作开始前记下你当前的滚动位置，动作带来的那几次就地更新都做完之后再核对一次 ——
**只有在"文档高度确实变了、你的位置也确实被挪走了"时**，才把它放回原处；
如果高度没变而位置变了（＝你自己在滚），它**一个字都不写**。它写回的永远是**记下来的那个位置**，
因此它没有能力"跳到某个地方"。这一手防的是"就地更新让文档高度动一下、浏览器顺手把你的位置挪走"
（哪怕只是挪几十像素，也不该让你重新找位置）。

**原因五：整页重载（唯一能把位置夹到"最顶部"的机制）。**
要把滚动位置夹到 **0**，文档高度必须**塌到不足一屏** —— 页面上方少几十像素只能让位置往上
收几十像素。整页重载正好会这样：重载之后界面先显示"正在检查登录状态…"（那是一个**正好一屏高**
的占位屏），滚动位置在那一刻被夹到 0；等后台内容再长回来，位置也不会自己回去。

本仓库里唯一会**在你点完按钮之后隔几秒**触发整页重载的东西是 `npm run dev` 的
「**盯着后端**」（`SITE_LIVE=1`）：它每 2 秒比一次后端公开数据的内容指纹，一变就重写
`data/site/.backend-snapshot.ts`；而那个生成文件**在后台页面的模块图里**
（课程库页 → 后端接口层 → 网站数据模块 → 那个快照），于是 Next 重编译并**整页重载**。
点一下「设为暂未开放」正好会改变后端公开数据（课程状态是网站卡片的一部分），
时间点就是"点一下 → 过 1~5 秒页面自己跳回顶部"。

现在的做法：**默认关**。要开得显式写 `SITE_LIVE=1`，那是"正在编辑网站文案、想让网站跟着变"
时才用的模式；做日常运营（切开放状态、改教师、改报价）时别开。
自检第 14 节有一条断言：这个开关**不许改回默认开**（改回去会立刻报红，并告诉你为什么）；
另有一条"事实核对"钉住"那个生成文件确实在后台页面的模块图里"。

> **为什么"1~5 秒"这个数字本身就是这一条的指纹**：机构反馈的原话是"点一下，**过一会儿**
> 页面跳到最顶部"，而这一条的时间构成正好是**轮询（0~2 秒）+ 重写快照与进程启动（约 0.2~1 秒）
> + 重编译与整页重载（约 0.5~2 秒）= 1~5 秒**，与仓库里早就记下的那句
> "点一下 → **过 1~5 秒**页面自己跳回顶部（机构真实反馈）"**逐字对得上**。
> 对比一下：那两次请求的往返实测只有**几毫秒**（见原因四），慢的从来不是请求，是重载。

**再加一层兜底（整页重载后放回原位）**：重载前记下你的滚动位置，重载后**等页面长够高**
再放回去。为什么这是**补回浏览器本来就该做的那一步**，而不是"掩盖问题"：

- 浏览器**本来就会**在重载后恢复滚动位置 —— 但后台外壳重载后先渲染"正在检查登录状态…"
  （一个正好一屏高的占位屏），位置在那一刻被夹成 0，等内容长回来，浏览器也不会再来一次。
  所以这一手补的是**我们自己那个占位屏造成的缺口**，不是掩盖谁的错。
- 它**只在整页重载、并且地址没变**时才动：普通跳转、首次进入、前进后退一律不插手。
- 它写回的**只有"记下来的那个位置"**（必要时夹进当前能滚到的范围），没有"跳到顶部"这种路径。
- **你一动手它就收手**：页面长起来的那一两秒里你自己滚了的话，它立刻停手，绝不去抢滚动条。
- **它不是"掩盖问题"**：动作本身的结果**一条都没被藏起来** —— 卡片上的绿字/红字、页顶的计数、
  失败原因，全都照旧显示；被保住的只有"你原来在看哪一段"。

**原因六：某个提示自己超时消失了。** 那会让页面上方少一块 —— 与原因二同一类机制，
只是发生得晚几秒。现在的做法：就地动作的提示**不自动消失**（要改就由下一次动作改），
自检第 14 节有一条断言：课程库页与页顶提示条里**不许出现任何定时器**。

#### 判断方法（先分两类，再按类往下走）

**第 0 步：看多久才跳。**

- **点下去就跳** → 走下面 1 / 2 / 3；
- **点完过一会儿才跳** → 走下面 4 / 5 / 6（下面那三条即时跳的判据对这一类**完全无效**，
  别在"加载中…"和"页面上方少一块"上找原因）。

即时跳：

1. 点一下按钮，**看列表是不是短暂变成一行"加载中…"** —— 是的话就是原因一
   （让"刷新时不替换已有内容"即可，`load({ quiet: true })`）；
2. 不是的话，**看它点下去之后页面上方有没有多出/少掉一块**（提示条、状态行、上面的面板）
   —— 是的话就是原因二（把那条提示搬到动作发生的地方，或让它不改变高度）；
3. 两种都看不出来，**看控制台有没有 401 / 报错** —— 那就是原因三（会话失效，
   见 §15.1 与顶栏状态的「重新登录」）。

延迟跳：

4. **先看跳的幅度**：是"回到了最顶部、要重新往下滑很久"，还是"只往上收了一点点"？
   - 只收了一点点（几十像素）→ **原因四**（30 秒的连接复查换了一次说法）。把"结论没变不发通知"
     与"各说法共用最小高度"保持住即可（自检第 14 节守着）。
   - 回到了最顶部 → 看下一条。
5. **跳之前页面有没有闪一下、顶栏有没有短暂出现"正在检查登录状态…"** —— 有的话就是
   **原因五（整页重载）**。去确认启动命令：`SITE_LIVE=1 npm run dev` 会这样；
   平时应当用 `npm run dev`（不带那个开关）。若不是整页重载、但跳之前**刚才点过的那条提示
   自己不见了**，那是**原因六**（自动消失的提示）。
6. 都看不出来：按原因三的延迟版看控制台有没有 401 / 报错；并把四件事记下来交给维护者 ——
   **① 隔几秒才跳；② 跳之前有没有闪烁 / 顶栏那句话；③ 是回到最顶部还是只往上收一点；
   ④ 启动时有没有设 `SITE_LIVE`、控制台有没有 401**。这四条能把上面六种原因唯一地定下来。

已经做到的（就是按上面六条来的）：

- **一处显式"滚到顶部"都没有了**：以前课程库有两处（点「编辑」时把你带到页顶的表单、
  删小节被拒时把你带到页顶的原因），现在编辑器**就地展开**、被拒的原因写在**你刚点的那一节**里。
  自检里有一条断言守着这件事（`npm run check`：前端源码里写滚动的**只允许一个文件** ——
  `components/admin/scroll-io.ts`，而且那个文件里写进去的必须是**参数**、不许是常量，
  所以别处一句"跳顶部"都过不了；`scrollIntoView` / `scrollBy` 一律不许出现）。
- **两层"恢复型滚动"兜底**（这一节原因四/五里说的那两手）：就地动作期间只在"高度变了、
  位置也被挪了"时把位置放回原处；整页重载后等页面长够高再放回原处。两处的判定都是纯函数，
  自检第 15 节把判定表穷举了（包括"高度没变就别动手"和"只在整页重载时恢复"这两条）。
- **就地动作不再让页面"上方少一块"**：最典型的是课程库的「新增课程」表单 —— 它原来一直摊在
  课程清单**上面**，点某张卡片的「编辑」时它被收起，上方就矮了几百像素（正是原因二）。
  现在它**默认收起**（只剩一行 + 「填写新课程」按钮），点编辑不会再把页面顶上那一段拿走；
  课程卡片上的切换 / 删除结果、删小节被拒的原因也都写在**那一下动作发生的地方**，
  页顶那两行提示不再随一次点击忽隐忽现。
- **就地动作一律"安静刷新"**：课程库的「设为开放 / 设为暂未开放」（就地改这一条）、
  「保存编辑」「删除」「批量导入」，以及**其余每个后台页面**的
  刷新、保存、切换、导入 —— 刷新时都不清空已有内容（首屏加载仍然显示加载态，那是正常的）。
  自检里同样有断言：**带加载态的页面里，`load(...)` 必须带 `quiet`**，裸 `load()` 只允许首屏那一处。
- **30 秒一次的连接复查不会再动页面**：复查结论与屏幕上那份一样时**连重渲染都不发生**
  （不通知界面）；结论真的变了才改口，而五种说法**共用同一份最小高度**，因此只可能变高、
  不会变矮。这一条是行为级自检出来的：真的跑两遍复查，要求"一次通知都不发"。
- **延迟型整页重载的唯一开关是显式开启的**：`npm run dev` 默认**不盯后端**，要 `SITE_LIVE=1`
  才开；自检里有一条断言不许把这个默认改回去，并有一条"事实核对"钉住
  "那个生成文件确实在后台页面的模块图里"（也就是为什么这个开关不能放宽）。
- **点了就一定看得见回应**：安静刷新之后"刷新中"改在**刷新按钮上**说（按钮上写字不改变页面高度）；
  卡片上的切换会先把按钮变成「切换中…」；失败（例如登录已失效）也写在卡片上，
  不会再出现"点了没反应"，让人以为是页面乱跳。

### 15.4 为什么有的档案「删不掉」（有账就拒绝）

**删除是真的删**，而档案被别的东西引用着 —— 删掉之后那些记录就失去了主人：
收款还在账上、课时流水还在、课还在课表上，但找不到人 / 老师 / 教室。

所以现在**有账就拒绝删除**，并且把"还有哪些记录、该怎么办"写在提示里：

| 你想删 | 会被拦下的情况 | 该怎么办 |
| --- | --- | --- |
| **学生** | 有任何收款、课时流水、课堂记录、阶段测评、作业记录，或出现在任何一节课的名单里 | 先退课结清、取消或删掉 TA 的排课；只是不再来上课就改成「结课 / 暂停」（数据都留着） |
| **教师** | 名下有排课 | 离职请把「在职」关掉（**停用**），不要删 —— 课时费要按历史记录核算 |
| **教室** | 有排课 | 先取消或改掉那些课，或者改成「停用」 |
| **课程** | 有报课或排课在用这个科目名 | 不再开的课改成「**暂未开放**」 |
| **一节课** | 已经扣过课时（有未撤销的上课流水）或已有课堂记录 | 先「撤销已上」（课时会按流水退回），再处理课堂记录 |

提示文字会**逐项列出**还剩什么（例如"2 条收款记录（合计 ¥2000）、2 条课时流水、1 节排课"），
并告诉你下一步做什么 —— 而不是只回一句"不能删"。

> 一句话记住：**档案可以停用，账不能删**。删除只留给"录错了、还没产生任何记录"那种情况。

### 15.5 两个人同时改同一条记录会怎样

**结论先说：不会有人白干，也不会有人把别人的改动悄悄盖掉 —— 后点保存的那个人会看到一句提示，让他刷新。**

具体是这样：

1. 李老师打开了「示例·李同学」的信息采集表，开始填；
2. 同时王老师也打开了同一个学生的采集表，先填完、先点保存 —— **他的填写正常保存**；
3. 李老师接着点保存时，屏幕上方出现一句话：

   > 学生「示例·李同学」刚被别人改过（当前版本 3，你手上的是 2），请刷新后再提交。

4. 李老师重新打开这张表（刷新），就能看到王老师填的内容，再把自己要填的补上。

几件值得知道的事：

- **为什么不是"后点的覆盖前面的"**：那是最糟的结果 —— 李老师以为保存成功了，
  而王老师填的那几项已经不声不响地没了，谁都不知道。现在的做法是**宁可让你重填一次**；
- **系统不会替你合并两份填写**：它分不清"同一条记录上两处不同，到底谁写的算"，
  所以它不猜，只告诉你这条记录被人动过；
- **看到这句话就先刷新再重填**（不要在原表单上反复点保存 —— 版本对不上，点多少次都是同一句提示）；
- **一个人开两个标签页改同一条记录也会看到这句提示**（两个标签页之间不会互相通知）；
- 这条规则管的是**同一条记录**（同一个学生 / 同一门课 / 同一位教师 / 同一间教室 / 同一节课）。
  不同记录之间互不影响：你改李同学、他改王同学，两个人都不会被拦。

### 15.6 老接口（`/api/students` 这类）已经下线

如果你手上有**早期写好的脚本或书签**在调 `/api/students`、`/api/lessons`、`/api/pricing` 这类地址，
现在会收到 **410 Gone** 和一句指路：

```json
{ "ok": false, "error": "这个接口已经下线：GET /api/students。它属于早期的参考实现（读写的是另一套表，
  与界面看到的数据不相通）。请改用统一入口 POST /api/call（{ method, args }），方法清单见 docs/后台API约定.md。" }
```

**为什么下线**：那些接口是早期"路线 A"留下的参考实现，读写的是**另一套表**，与界面用的数据
（`/api/call` → 库里的那份快照）**不是同一份**。于是它们会给出两种最误导的答复：
`GET` 返回"空数据"（看起来像库里什么都没有），`POST` 返回 201"成功"（其实写进了界面永远不读的地方）。
更要紧的是：**删除护栏原先只挂在它们身上**（"有账的学生不能删"），而界面走的是另一条路 ——
也就是说那道保护对机构而言是装饰（审计里那条：删档案留下了无主的收款记录）。

**现在只有一条数据通路**：界面上的一切（包括账号管理、节假日抓取）都走 `/api/call` 或那几条
服务端自己的路由，权限判定与日志也都只有一份。

**我要写脚本怎么办**：用统一入口，形状是

```bash
curl -s http://127.0.0.1:4000/api/call \
  -H "authorization: Bearer <登录拿到的令牌>" \
  -H 'content-type: application/json' \
  -d '{"method":"students.list","args":[]}'
```

方法名清单见 [后台API约定](./后台API约定.md)（也可以直接看 `lib/backend/contract.ts`）。

## 17. 现在做不到的事（别白等）

| 你可能会想要 | 现状 |
| --- | --- |
| 多人同时用、各自账号 | **账号与角色已经有了**（四个角色分别能看到哪一页、能调哪些接口，都在服务端拦着，见「谁能做什么」一节）。但**多人同时改数据**只做到一半：同一条记录的并发编辑有保护（后交的人会被提示刷新，见 15.5），**跨记录**的操作（比如一边在报课、一边在退同一门课）仍可能撞在一起 |
| 手机 / 平板上用 | 页面能开，但后台是按电脑屏幕设计的高密度表格，手机上会难用 |
| 在外面（家里、校区外）用后台 | 不行。后台只在这台电脑上跑，数据也不上公网；线上那份后台连不上后端，登不进去 |
| 家长自己查课时 / 线上支付 | 没有做（V1 明确不做支付与家长端） |
| 改完价格直接自动生效 | 需要「导出配置 → 替换内容文件 → 提交发布」，见 12.4 |
| 误删学生 / 教师 / 教室后恢复 | 做不到（是真删）。课时与收款反而不能删，只能撤销 / 退款 |
| 排课自动按假期作息 | **口径已经定下来、判定已经落地，但排课还没接**（机构："后续的排课再另外安排"）。现状：「日历 → 假期与作息」里能录寒暑假段、能看到每天按工作日还是按周末时段（见 §8.1），但批量排课仍是"按星期几往后数"。口径是：**假期照常上课**（法定假日与寒暑假都按周末那一组时段）、**调休上班日按工作日作息**；接进排课时要动 `lib/backend/recurrence.ts` 的日期生成，并按 `dayPlanFor` 的判定逐日筛 |
| 云端备份（电脑丢了也能恢复） | 没有。后端每天在本机自动备份一份，但备份和数据库在**同一台电脑**上；要防电脑丢，得自己把导出的 JSON 放到别处（见第 13 节） |

> 上面这些不是「以后再说」，而是当前阶段的边界：这套后台已经接上**真实服务端**
> （SQLite + 服务端会话认证 + 每天自动备份），但它按**两个人以内、本机使用**来设计。
> 其中"两个人同时改"这件事已经有了一层保护：**同一条记录**的并发编辑会被挡住并提示刷新（15.5）；
> 而**跨记录**的并发（"要么全成要么全不成"的那种）仍然不在范围内。
> 远程访问要等真的需要时再做（见 docs/后端开发方案.md §7）。
> 分工不用等：四个角色分别该看到哪一页、哪些接口能看到哪几行数据，都已经落地
> —— 方法级在服务端按角色拦，行级（普通教师只看自己的课与自己学生的课时余额）也在服务端按会话过滤，
> 口径写在上面「谁能做什么」一节与 [后台API约定 §三](./后台API约定.md)。
