# 内容维护手册（宣传网站）

> **读者**：机构运营 / 负责人。不需要写代码，但需要会在项目目录跑几条命令。
> **这份手册解决什么**：把宣传网站上的文案、课程、价格、常见问题、学生案例、时间安排改成机构现在的真实情况，并安全发布到线上 —— 不碰代码，也不碰后台里的数据。
> **改内容的最小闭环（日常，推荐）**：在**后台**改（教师页 / 课程台账 / 网站内容 / 报价）→ `npm run site:export`（把库里的内容写回 `data/site/*.md`，并自动接着跑 `sync-content`）→ `npm run sync-content` → `npm run dev` 看效果 → `npm run check` 自检 → `git commit`（推送由负责人决定，见 §9）。
> **直接改 `.md`** 只在不连后端、或要改「模版兜底那一份」时用 —— 而且下次导出会覆盖它（见 §2.5）。
>
> 下文示例摘自现有文件，**行内容与文件一致**；为省篇幅省略了字段之间的空行与 `#### 名称:` 行（文件里每个字段之间都有一行空行，照原样写即可）。

## 1. 内容都在哪：`data/site/` 六个文件

这六个文件现在是**导出产物**：内容在后台数据库里，`npm run site:export` 把它们写回文件。

| 文件 | 管什么 | 对应页面 |
| --- | --- | --- |
| `content.md` | 全站品牌与联系方式、首页、课程详情、教师、关于我们、联系我们（**6 个页面段**） | `/` `/courses` `/teachers` `/about` `/contact` |
| `pricing.md` | 报价页的选项与价格：学习阶段、课程基础价、人数系数、时长、计费规则、教师分成、其他项目 | `/quote`，以及后台「报价」页的初始数据 |
| `faq.md` | 常见问题（8 个分组） | `/faq` |
| `cases.md` | 学生案例（当前 3 个） | `/cases` |
| `schedule.md` | 课程时间安排（4 组时段表） | `/schedule` |
| `featured.md` | 特色课程的分组、每门课的独立页面与面包屑 | `/courses/featured/**` |

想立刻看到某一页：首页 `/`；课程总览 `/courses`；栏目页 `/courses/primary`（小学课内）、`/courses/junior`（初中课内）、`/courses/senior`（高中课内）、`/courses/languages`（外语）、`/courses/interests`（课外兴趣）、`/courses/adults`（成人课程）；卡片页 `/courses/<卡片的路径>`（如 `/courses/primary-chinese`）；其余 `/teachers` `/about` `/contact` `/quote` `/faq` `/cases` `/schedule`。

> **后台的数据不在这些文件里。** 教务后台（`/admin`）的学生、排课、收费等都存在**服务端数据库**里
> （本机后端进程管的 `server/data/nexgenedu.db`，**不在浏览器里**）。
>
> 而**网站上的教师、课程、课程正文与报价**：从 2026-09 起**两边都能改**了 ——
> 网站构站时连得上后端就用**库里的**，连不上就用这里的文件（完整规则见
> [技术架构 §5.1](./技术架构.md)）。因此动手前先看这一节：

### 1.1 改内容之前：先确认网站吃的是哪一份

| 你想要的 | 改哪里 | 怎么让网站更新 |
| --- | --- | --- |
| 教师资料、课程卡片、课程分区、课程正文、报价 —— 日常维护 | **后台**（教师页、「课程 → 课程台账」页签、报价页） | 重新构站一次（`npm run build`，**构站那台机器要连得上后端**） |
| **学生案例**（`/cases` 与首页那块） | **后台「网站内容」页**（v19 起） | 重新构站一次（`npm run build`，那台机器要连得上后端） |
| **特色课程**（三级课程树 + 各课程页） | **后台「网站内容」页**（v20 起） | 重新构站一次（那台机器要连得上后端） |
| **两组上课时段**（工作日排课 / 周末排课 —— 日历上"哪天按哪一组"用的就是它们） | **后台「网站内容」页 → 时间安排**（分组标题里要含「工作日」/「周末」与「排课」） | 重新构站一次（那台机器要连得上后端） |
| **寒暑假段**（起止日期，按学段） | **后台「日历」页 → 假期与作息**（每年手动录一次） | 后台立刻生效；网站上的展示要重新构站一次 |
| **课程类型**（学段 / 学科与项目 / 内容模块 / 班型这四个维度） | **后台「课程 → 课程类型」页签**（v23 起，v29 合并进「课程」页） | 后台各处的班型下拉**立刻**生效；网站上的展示要重新构站一次（那台机器要连得上后端） |
| **哪些组合真的开**（学科 × 内容模块 × 班型） | **后台「课程 → 开放矩阵」页签**（v24 起，v29 合并进「课程」页） | 目前只影响后台与将来的 AI 排课 / 诊断推荐（判定口径在那里），网站展示不必重构 |
| **常见问题**（`/faq`） | **后台「网站内容」页**（v21 起） | 重新构站一次（那台机器要连得上后端） |
| **品牌与联系方式 / 首页 / 关于 / 联系我们 / 时间安排的文案** | **后台「网站内容」页**（v22 起，五个页签） | 重新构站一次（那台机器要连得上后端） |
| 教师 / 课程 / 报价 / 案例 —— 想在**没连后端**时也看到内容 | 不必改文件：用 `SITE_CONTENT_SOURCE=template npm run dev` 就能看模版那一份（默认口径下那五块是**空白**）。这六个文件是**导出产物**，别在这里做日常维护 | — |
| 新增一门课要上网站 | 后台「课程库」加一行并填「网站上怎么展示」（见 §4.6） | 同第一行 / 第二行 |

上表第三列的「重新构站」只让**本机构建**跟上；要让**内容文件（线上 Pages 读的那份）**也跟上，
再跑一次 `npm run site:export` —— 它把六个文件一起对齐，并顺带做 `sync-content`。

判断"这次构站用的是哪一份"：构建日志里那行 **`[site-data] 本次网站数据来源：…`**。
三种可能：**后端**（库里的，构站时连得上）/ **空白**（连不上：那五块**没有内容**）/**模版**（`SITE_CONTENT_SOURCE=template` 显式要求时）。

**这些文件是 GitHub Pages 那份的唯一出处**，也是"连不上后端"时的整站内容 ——
因此它们依然是发布链的一环。但方向已经明确：**网站内容的真源是后台数据库；
`data/site/*.md` 这六个文件是它的导出产物（`npm run site:export` 写回），手工改动会被下次导出覆盖。**
要改内容去后台改，改完 `npm run site:export` → `npm run sync-content`；
推送前用 `npm run site:export -- --check` 确认网站与后台已同步（不一致退出码 1）。
两边还没对齐时，构站那台机器连得上后端就显示**库**那一份，连不上就显示**文件**那一份
（二选一，不混合）—— 所以**文件落后于库时，线上 Pages 发出去的就是旧内容**。
内容文件只在**新装系统**时作为初始数据进库（v32 起的口径）。

> **已完成**：首页 / 关于 / 联系 / 常见问题 / 案例 / 时间安排 / 特色课程这些文案
> v19–v22 起也进了库，都能在后台上表第二行那几处改。这些 `.md` 因此彻底变成
> 「导出产物 + 没连后端时的兜底」这一种用途 —— 手工改它们不再是日常维护方式。

数据的流转方向（模版这一条路）：`data/site/*.md`（导出产物；没连后端时的兜底就是这一份）→ `npm run sync-content` → `data/site/*.ts`（自动生成，勿手改但**要提交**）→ `lib/data/*.ts`（解析成结构）→ 页面渲染。一句话：**`.md` 是导出产物、`.ts` 是它的生成物 —— 两个都不要手工改。**

## 2. 通用格式约定（六个文件都适用）

> 这些格式说明现在的用途是**核对导出结果**（判断格式坏了没、比对导出得对不对）：
> 日常改这些内容请到后台（见 §1.1 那张表），改完跑 `npm run site:export` 把内容写回文件 ——
> 手工改这里会在下次导出时被覆盖（见 §2.5）。

### 2.1 六种基本写法

| 写法 | 作用 | 示例（摘自现有文件） |
| --- | --- | --- |
| `# 标题` | 文件第一行的总标题 | `# NexGenEdu · 新锐教培 · 网站内容` |
| `## 页面: 名称` | **页面分段标记**，一个文件可有多段 | `## 页面: 首页` |
| `---` … `---` | 该页面的**短字段**块，一行一个字段 | `title: 让学习真正发生` |
| `## 分组名` / `### 分组名` | 页面内的分组（几级井号看文件自己的用法） | `### 教学特色` |
| `#### 名称 \| 值` | 分组里的条目，**名称与值之间用半角竖线 `\|`** | `#### 覆盖学段 \| 小学、初中、高中` |
| `- · 字段名: 内容` | 字段（`featured.md` 的课程字段用这种写法） | `- · 适合对象: 需要课内同步提升的学生` |

条目写成 `#### 名称: 值`（半角或全角冒号）也能识别，**但值里含冒号时必须用竖线**；`>` 开头的引用块是写给你自己看的说明，**不会显示在网站上**。

### 2.2 每个文件的格式速查（最容易混的地方）

| 文件 | 分段 | 分组 | 条目写法 | 字段写法 |
| --- | --- | --- | --- | --- |
| `content.md` 全站 / 首页 / 关于 | `## 页面: 全站` | `### 课程栏目` | `#### 卡片名 \| 路径: …`；`#### 标题 \| 说明` | `字段: 值`（在 `---` 块里） |
| `content.md` 课程 | `## 页面: 课程` | `### 语文` | `#### 小学语文｜建立阅读与表达的基础` + 正文 | 核心能力用 `- 核心能力：…` |
| `content.md` 教师 | `## 页面: 教师` | `### 陈老师` | —（只有字段） | `#### 科目: 数学, 英语` |
| `pricing.md` | `## 页面: 智能报价` | `## 学习阶段` → `### 小学课内`（＝网站栏目名） | `#### 课程: 小学语文: 150` | `#### 名称: 一对一` |
| `faq.md` | `## 页面: 常见问题` | `## 试课与报名` | `### 问题 \| 答案` | — |
| `cases.md` | `## 页面: 学生案例` | `### 初二 李同学｜数学从 62 分到 91 分` | — | `#### 年级: 初二` |
| `schedule.md` | `## 页面: 课程时间安排` | `### 工作日排课` | `#### 晚第一节 \| 17:30–19:30` | — |
| `featured.md` | `## 页面: 特色课程` | `### 课内辅导` | `#### 一对一`（二级课）、`##### 小学晚托`（三级课） | `- · 路径: one-on-one` |

### 2.3 会「静默失效」的写法（重点）

这些错误**不会报错**，页面只是少了东西 —— 最需要小心的一类问题：

| 写错的地方 | 你看到的现象 | 怎么发现 |
| --- | --- | --- |
| `## 页面: 首页` 改成 `## 页面 首页`（少冒号）或改了名称 | 该页整页空白 | 终端出现 `[content] … 中缺少「## 页面: 首页」段落…` |
| 页面开头的 `---` 只写一半 / 少一行 | 该页标题、说明等短字段全空 | 终端出现 `[content] … 缺少 --- 包裹的字段块` / `字段块未闭合` |
| 条目里的半角竖线 `\|` 写成全角 `｜`（如卡片写成 `#### 初中数学｜路径: junior-math`） | 解析器找不到半角竖线，退而按冒号切，卡片名变成「初中数学｜路径」这种怪名字 | 页面名字不对；`npm run check` 的卡片名 / 锚点断言会红 |
| `- · 字段名: 内容` 少了中间的 `·`（写成 `- 字段名: 内容`） | 该字段读不到（特色课程页缺一段说明） | 特色课程页缺字段 |
| 内容写进了 `>` 引用块 | 永远不显示 | 引用块**从不**渲染到页面 |
| 卡片 `路径:` 里出现中文、空格或斜杠 | 卡片点进去 404 | `npm run check` 会拦（要求小写字母 / 数字 / 连字符） |
| 把「暂未开放」写成「未开放」等别的说法 | 不再被当成「暂未开放」，报价时提示无法报价 | 报价页试算一次即可发现 |

**页面空白先看终端**：内容格式问题一律只警告、不报错，页面继续渲染（只是缺内容），所以终端里那行 `[content] …` 是你唯一也最准确的线索。

### 2.4 `data/site/*.ts` 是生成的

- 每个 `.md` 都有同名 `.ts`（`content.md` → `content.ts`），由 `scripts/sync-content.mjs` 生成，文件头写着「请勿手工编辑」；它**必须提交**（仓库跟踪它，线上构建也依赖它）。
- `data/site/.sync-stamp.ts` 是同步时间戳，未纳入版本库，**不要提交、不要手建**。
- 手改 `.ts` 的后果：下次同步被覆盖，改动只在线上产物里存在，再构建一次就消失。

### 2.5 六个 .md 是导出产物

**网站内容的真源是后台数据库**；`data/site/*.md` 这六个文件是它的**导出产物**
（`npm run site:export` 写回），手工改动会被下次导出覆盖。

1. **`npm run site:export`** 从后台（`GET /api/public/site` 这个只读接口）把网站内容写回
   `content.md` / `pricing.md` / `faq.md` / `cases.md` / `featured.md` / `schedule.md`，
   写完自动接着跑 `npm run sync-content`；只写**真的变了**的文件，退出码 0。
   它要求后端在跑（`npm run server`），但**不需要登录**。
2. **要改内容请去后台** —— 教师资料 / 课程台账 / 网站内容 / 报价，去哪一处见 §1.1 那张表。
   导出之后文件头会多一行提醒（反复导出不会重复追加），文件里**写给人看的说明**
   （文件头引用块、分组标题下的「格式为…」、`<!-- -->` 注释）都会保留，
   被替换的只有库里拥有的数据。
3. **`npm run site:export -- --check`** 用来确认"网站与后台同步了"：只比对不写盘，
   六个文件与后台不一致时**退出码 1** 并列出是哪几个文件；一致时退出码 0
   并打印「网站内容与后台一致（线上那份就是最新的）」。**推送前跑它**
   （退出码 2 = 连不上后端，要先 `npm run server`）。
4. §2.1–§2.3 的格式说明**保留**，用途变成「核对导出结果 / 判断格式坏了没」：
   导出会尽量保住文件里的说明文字，但库里表达不了的东西会**逐条打印警告**，
   不会静默丢 —— 例如教师分成规则（`pricing.md` 的「教师分成」一节，公开接口不给这一份
   内部成本口径，导出沿用文件里原有那份并在输出里说明）、后台设了「不在网站展示」的老师
   （不会写进文件）、以及 `.md` 表达不了的内容（字段在库里有换行、特色课程的字段名不在
   四个可用字段里、卡片在后台显式设过「点进哪一节」）。

## 3. `content.md`：全站与各页面

> 以下格式说明用于**核对导出结果**；日常改这些内容请到后台（教师页 / 课程台账 / 网站内容 / 报价），
> 改完跑 `npm run site:export` 写回文件。手工改这里会在下次导出时被覆盖。

### 3.1 全站段（`## 页面: 全站`）

控制浏览器标题、页头页脚与联系方式，字段写在 `---` 块里：

```markdown
brand_name_zh: 新锐教培
phone: +86 138-6853-0992（陈老师）
wechat: JeremyThierryChan（陈老师）
business_hours: 每日 9:00–21:00（含节假日）
class_hours: 每日 8:00–22:00（含节假日）
```

**营业时间与上课时间是两个字段，不要混着写**：`business_hours` 是**营业时间**（工作人员在校区接待咨询），页脚显示为「接待时间」；`class_hours` 是**上课时间**（教师与学生实际上课），显示在页脚与课程时间安排页。自检会校验：两者都有值、不是同一句话、上课时间 8:00 开始且 22:00 结束（比营业时间早开始晚结束）、两者都写「含节假日」。

### 3.2 首页段（`## 页面: 首页`）

短字段管首屏标题/副标题、两个按钮与各区块的标题说明。三个分组：`### 首屏数据`（当前 6 条）、`### 教学特色`（当前 7 条）、`### 教室照片格位`（当前 3 条）。

**首页区块顺序由代码固定，改内容不会改顺序**：教学特色 → 负责的教师团队 → 学生案例 → 试课体验 → 课程 → 教室环境。教室照片放进 `public/images/`（目录不存在就新建），再把文件名填进格位，例如 `#### 301 教室 | classroom-301.jpg`；文件名留空时显示一个中性的图片位。

### 3.3 关于段与联系我们段

- 关于页四组：`### 教学理念`（4 条）、`### 服务形式`（5 条）、`### 校区数据`（4 条）、`### 校区介绍`（3 段）。「校区数据」里的数字（如「学科数量 | 19 门」）请按实际情况替换。
- 联系我们页：`### 联系方式清单`，当前 6 行（电话 / 微信 / 邮箱 / 地址 / 营业时间 / 上课时间）；不需要显示邮箱就删掉那一行。

### 3.4 教师段（`## 页面: 教师`）

每位教师是一个 `### 姓名` 分组，字段写作 `#### 字段: 值`：

| 字段 | 说明 |
| --- | --- |
| `科目` | 逗号分隔。**它同时决定课程页「这门课谁来上」**：某位老师的科目出现在某门课的名字或小节名里，这位老师就出现在那门课页面上 |
| `职务` / `教龄` | 不需要就删掉那一行；教龄如 `10 年` |
| `简介` | 一句话，显示在教师卡片上 |
| `推荐理由` | 选填；**目前只有第一位教师填**（自检要求其余为空） |
| `类型` | 填 `AI` 表示这是 AI 智能体（卡片显示「AI 智能体」标记）；不填即真人教师 |
| `排序` | 数字，越小越靠前（不显示在页面上，但决定顺序，不能重复） |
| `状态` | `在职` / `离职`；离职保留资料但不展示 |

字段之后、下一位教师之前的文字是这位教师的详细介绍。首页的教师卡片读这里的前三位 —— 改这里，首页与教师页一起更新。

**自检钉住**：首位必须是「陈老师」、其职务是「全科教师」；除首位外的教师**不要填推荐理由**；AI 智能体必须排在真人教师之后（靠 `排序` 控制）。

## 4. 课程结构：栏目 → 子标题 → 卡片

> 以下格式说明用于**核对导出结果**；日常改这些内容请到后台（教师页 / 课程台账 / 网站内容 / 报价），
> 改完跑 `npm run site:export` 写回文件。手工改这里会在下次导出时被覆盖。

这部分在 `content.md` 的「全站」段：`### 课程栏目`。首页课程区与课程页共用它。

### 4.1 六个栏目

| 栏目 | 栏目页 | 卡片数（当前） |
| --- | --- | --- |
| 小学课内 / 初中课内 / 高中课内 | `/courses/primary` `/courses/junior` `/courses/senior` | 6 / 8 / 10 |
| 外语 / 课外兴趣 / 成人课程 | `/courses/languages` `/courses/interests` `/courses/adults` | 7 / 2 / 9 |

合计 **42 张卡片 = 课程库里的 42 门课**（2026-09 起，见 §4.4 / §4.6）。
高中课内从 12 变成 10，是因为机构把直接挂在这个栏目上的「高考冲刺」「特殊计划专项」
从课程库里删掉了（报价里那两行也跟着删了，见 PROJECT.md 的 E14）。
自检只要求「每个栏目、每个子标题下都有卡片」「卡片总数 ≥ 20」「卡片名不重复」—— 增删卡片不会被数量拦住，但结构错误会被拦住。

### 4.2 卡片行的写法

```markdown
#### 小学语文 | 路径: primary-chinese · 班型: 一对一、一对二、一对三、小班课（4-8人）、大班课（9-20人） · 栏目: 小学课内
#### 高中物理 | 路径: senior-physics · 班型: 一对一、一对二、一对三、小班课（4-8人）、大班课（9-20人） · 栏目: 高中课内 · 子栏目: 七选三
#### 3D建模 & 3D打印 | 路径: 3d-printing · 班型: 一对一、一对二、一对三、小班课（4-8人）、大班课（9-20人） · 栏目: 课外兴趣 · 状态: 暂未开放
```

> 注意：**没有 `标签:` 这一项了**（2026-09 起，见 §4.4）。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 卡片名（`\|` 之前） | ✅ | 一门课程的名字，如「高中物理」「雅思」 |
| `路径:` | ✅ | 卡片页 URL 片段，**必须是小写字母 / 数字 / 连字符** |
| `班型:` | ✅ | 该课程开设的班型，顿号分隔；**必须是 `featured.md` 里存在的班型名** |
| `栏目:` | ✅ | 上面六个栏目之一 |
| `子栏目:` | 选填 | 高中课内用：`必考科目` / `外语` / `七选三` |

> **`栏目:` / `子栏目:` 与后台的「课程分区」是同一件事的两种写法**（v18 起）：
> 后台里分区是一份数据（可增删改名排序），库里存的是分区 id；这两行文字是**模版兜底**
> —— 没有后端的环境（GitHub Pages）靠它构站；库里的分区是初始数据，之后在后台维护
> （同名同上级就复用现有的那一条，**只增不改**，不会覆盖你在后台改过的名字与顺序）。
> 因此在两边都改过名字之后，你看到的差异是"真的差异"：`npm run site:diff` 就是把这份
> 内容文件与库里的分区结构逐项比一遍（栏目、子栏目、卡片与先后顺序都比）。
| `状态:` | 选填 | 填 `暂未开放` 时卡片显示标记 |
| `标签:` | **已废弃** | 2026-09 起**不要写**：级别信息写在课程正文的小标题里（见 4.4） |

字段之间用 ` · ` 分隔：**间隔号（U+00B7）两边各一个空格**。它既不是英文句点、也不是全角的「・」—— 最稳妥的做法是从现有卡片行里连空格一起复制那个符号。

### 4.3 路径 slug 的铁律

- **只能用英文小写字母、数字、连字符**：`primary-chinese`、`senior-physics`、`3d-printing`。
- **不能用中文、空格、斜杠**：历史上这里踩过坑 —— 路径里带了空格与斜杠，卡片点进去 404（斜杠会被 URL 当成层级分隔符）。
- 路径不能重复（自检拦），也不要与栏目路径（`primary`/`junior`/`senior`/`languages`/`interests`/`adults`）同名。
- 改路径等于换网址：**已发出去的链接会失效**，没有特别理由不要改。

### 4.4 级别信息写在课程正文里，卡片上**不再有标签**（2026-09 起）

**机构的原话是「课程全都按照课程库里的来，课程库以外的全部都应该删掉」**（记在 PROJECT.md 的 E12）。
做法是「方案 B」：

- 一张卡片 = 一门课 = 一个页面 = **课程正文里的一段**；正文段名（锚点）**就是课程名**；
- 原来的级别 / 技能（七选三的 `学考` / `选考`、外语的 `N5–N3` 与 `A1–B2`、雅思的四项、
  3D 建模的三个软件、编程的四个方向…）**不再是独立小节，也不再有可点的标签入口** ——
  它们变成了**那门课正文里的 `### 小标题`**；
- 因此 `#### 高中物理` 这一节的正文里写着 `### 学考｜合格考基础` 与 `### 选考｜等级考拔高`：
  **内容一个字没少**，只是不再各占一个锚点；
- 卡片行里**不要再写 `标签:`**（后台已经没有这个字段了，写了导出时也会丢掉）。

一句话记住：**以前"点标签进到某一级"，现在"往下读就是那一级"。**

正文里的小标题在文件里写成 `\### 学考｜合格考基础`（**反斜杠 + 三个井号**）——
`#` 开头的行在 `.md` 里是标题，不转义就会被读成新的分组、把那门课的正文**拦腰截断**。
这层转义在导出与解析里是自动配对的，**手工改文件时别把那个反斜杠删掉**。

自检现在的固定两条：七选三每张卡的正文里必须有 `### 学考` 与 `### 选考`；
外语栏目每张语言卡的正文里必须有该语种的全部级别小标题。**标签没了不等于级别没了。**

### 4.5 班型与特色课程的联动

卡片 `班型:` 里的名字必须存在于 `featured.md`（自检拦），因为课程页要用它们反查「这个班型开设了哪些科目」。

**2026-09 起班型只有五个**（机构口径：「现在只有一对一、一对二、一对三、小班课（4-8人）、大班课（9-20人），其他的班型信息全部删除清空」，见 PROJECT.md 的 E13）：

- 每张卡片都写全这五个，**卡片上不许出现第六个写法**（自检有一条直接盯住这件事）；
- 那两个「不是班型」的服务（**晚托管**、**周中预习课**）**不再写进卡片的 `班型:` 里** ——
  它们仍留在 `featured.md` 里当二级课程（网站上那一门还在），只是不参与班型反查；
  自检同样有两条：晚托管不挂到任何学科、周中预习课不再是卡片上的班型。

### 4.6 新增一门课程的完整步骤

> **v32 起课程以库为准**：新增课请直接在后台「课程 → 课程台账」里加（原来那个「从网站同步课程」按钮已删）。
> 在后台课程库加课，**重新构站后**网站上就会出现这张卡片（课程库是后台的课程台账）；
> 想把卡片写回内容文件，跑 `npm run site:export` ——
> 它会把库里的卡片结构写回 `content.md`，**不要手工改 `.md`**。

以新增「书法」为例：

1. 在 `## 页面: 课程` 的 `### 数学` 下加小节 —— **一门课一个小节，小节名（「｜」之前那一段）必须与卡片名逐字一致**（见 §5）：

   ```markdown
   #### 书法｜从执笔到作品

   面向零基础、想把字写稳的学生。

   \### 楷书基础｜基本笔画与结构规律

   先练笔画与结构，再进入整字与章法。

   - 核心能力：执笔与坐姿 · 基本笔画 · 结构规律 · 章法 · 作品临写
   ```

   `\### …` 就是这门课内部的**级别 / 阶段小标题**（想分几级就写几个）。它是正文的一部分，
   页面上渲染成三级标题；**不写也完全合法**（一门课一整段，不分级）。

2. 在 `### 课程栏目` 里加卡片行（路径用英文）：`#### 书法 | 路径: calligraphy · 班型: 一对一、一对二、一对三 · 栏目: 课外兴趣`
3. 要报价的话，在 `pricing.md` 对应阶段加基础价：`#### 课程: 书法: 200`
   —— 这两步也可以合并成一步：在后台「课程 → 课程台账」里点「填写新课程」，
   表单里同时有卡片字段与报价（见后台使用手册 §12.0.2）。
4. **日常照这一步走**：后台改完 → `npm run site:export`（把库里的卡片、正文与报价一起写回 `data/site/*.md`，并自动接着跑 `npm run sync-content`）→ `npm run dev`（看 `/courses` 与 `/courses/calligraphy`）→ `npm run check`（卡片路径、锚点、班型联动都会被校验）。
   —— 上面 1–3 那三步是**文件里的对应写法**，用来核对导出结果；手工改完文件仍要 `sync-content`，但下次导出会覆盖它。

> ⚠️ **报价里只加一行、课程库里没有那门课**是行不通的（v37 起自检会拦）：
> 价目表上的每一门课都必须在课程清单里有对应的一门。只用在后台排课 / 报课、
> 不想上网站的课，请在台账里把「卡片」选成「不展示」。
>
> **2026-09 起课程库里不再有"只在后台用"的课**：原来那十二门（小学奥数、小学英语竞赛、
> 小升初、中考冲刺、提前招专项、高考冲刺、特殊计划专项、医学、机械行业英语、贸易、
> 成人旅游出行、跨国交友）已经**全部上网**，各自都有正文 —— 当时是课程库 44 门 = 网站 44 张卡片。
> 后来机构自己删掉了「高考冲刺」「特殊计划专项」两门（**报价里那两行也跟着删了**，见 PROJECT.md 的 E14），
> 因此现在是 **课程库 42 门 = 网站 42 张卡片**。
> 详见 PROJECT.md 的 E12。

## 5. `content.md` 的课程详情段（`## 页面: 课程`）

> 以下格式说明用于**核对导出结果**；日常改这些内容请到后台（课程台账 / 课程正文），
> 改完跑 `npm run site:export` 写回文件。手工改这里会在下次导出时被覆盖。

```markdown
### 语文

#### 小学语文｜建立阅读与表达的基础

语文素养的起点是识字、朗读与表达，让孩子先敢读、敢说、愿意写。

- 核心能力：识字写字 · 朗读与积累 · 阅读理解 · 口语表达 · 写话起步 · 学习习惯

#### 初中语文｜打通阅读与写作

从读懂到读懂意图，从会写到写得有条理。
```

- `### 学科名` 是一个**学科分组**（语文 / 数学 / 英语 / … / 雅思 / 日语 / 3D建模 & 3D打印…），
  它是个容器，**分组里的每个 `#### 小节` 才是一门课**。同一学科的各学段（小学 → 初中 → 高中）
  放在一组里，家长才能对比进阶路径；
- **小节名 = 「｜」之前的部分，而且它必须就是那门课在课程库里的名字**
  （「小学语文｜建立阅读与表达的基础」→ 小节名 `小学语文`）。它必须与「课程栏目」里的
  **卡片名逐字一致**，否则那张卡片点进去会跳空、自检报「每张学科卡片 = 一段正文，段名就是课程名」；
- 「｜」是全角竖线。写成半角 `|` 会被解析成「名称 | 值」，小节名就变了；
- 「｜」**后面**那半句是页面上的一句导语（`小学语文｜建立阅读与表达的基础`）。
  多段合并出来的课（高中物理 / 日语 / 3D建模…）**没有**这半句也合法 —— 小节名就是课程名本身；
- **一门课内部不分二级小节**：级别 / 阶段写成正文里的 `\### 小标题`（见 §4.4），
  不再是 `####` 小节。写成一个独立的 `#### 高中物理学考` 是不行的 —— 那会变成另一门课；
- `核心能力` 写成 `- 核心能力：… · …` 一行；没有这一行也可以，但不建议空着。

> 每一节正文里可能带 `\### 小标题`（反斜杠 + 井号）。**别删那个反斜杠**：
> `#` 开头的行在 `.md` 里是标题，删了它，解析器会把小标题当成新的 `###` 分组，
> 这门课的正文从那里被**截断**，页面上只看到前半段（而且不报错，最难查）。

## 6. `featured.md`：特色课程

> 以下格式说明用于**核对导出结果**；日常改这些内容请到后台（「网站内容」页 / 课程类型里的班型），
> 改完跑 `npm run site:export` 写回文件。手工改这里会在下次导出时被覆盖。

标题层级决定课程层级，也决定独立页面与面包屑：

| 写法 | 含义 | 页面 |
| --- | --- | --- |
| `### 课程名` | 一级课程（`### 课内辅导`） | `/courses/featured/in-class` |
| `#### 课程名` | 二级课程（`#### 一对一`） | `/courses/featured/in-class/one-on-one` |
| `##### 课程名` | 三级课程（`##### 精品小升初`） | 再深一层路径 |

字段**必须**写成 `- · 字段名: 内容`（可用字段：`路径` / `适合对象` / `课程定位` / `主要做法` / `可以期待`），字段之后的正文是该课程的详细介绍：

```markdown
### 课内辅导

- · 路径: in-class
- · 适合对象: 需要课内同步提升的学生
- · 课程定位: 按学生当前学段与校内进度上课，把课内没弄懂的地方补上。
- · 主要做法: 先测评定位薄弱点，再按学段与课程类型排课，课后由授课教师跟进作业与错题。
```

> **字段不能写成标题。** 把「适合对象」写成 `#### 适合对象: …` 会与「二级课程」无法区分（两者都是四个井号），导致子课程被当成字段。`路径` 同样必须是 ASCII。

**当前结构**（`### 课内辅导` 之下）：一对一、一对二、一对三、小班课（4-8人）、大班课（9-20人）、晚托管（小学晚托 / 初中晚托）、周中预习课、假期预习课（精品小升初 / 精品初升高 / 基础小升初 / 基础初升高）。

**这个文件来自后台**：特色课程的分组、每门课的独立页面与面包屑都在后台维护，
`npm run site:export` 把它们写回本文件（曾经的"后台的「班型」候选项来自这个文件"已经反过来：
文件是库的导出产物）。因此这里的课程名要与 `content.md` 卡片 `班型:` 里写的名字一致 ——
两边都由库导出，一致是导出结果的核对项。

## 7. `pricing.md`：价格与规则

这个文件是**线上那一份宣传站的价目表**（`/quote` 的可选项与价格），**也是后台「报价」页的初始数据**
（后台只在第一次打开时读它一次）。改价之后要不要动这个文件，取决于**网站在哪儿构站**：见 §7.7。

### 7.1 学习阶段与课程基础价

```markdown
## 学习阶段

### 小学

#### 课程: 小学语文: 150

#### 课程: 小学奥数: 260
```

每个 `### 阶段名` 是一个学习阶段，下面写这个阶段的「课程」与它的基础价（**没有「科目」这一维** —— 机构已定：这一维整个删掉，系数那一处改叫「人数系数」）。`#### 课程: 名字: 基础价` 的基础价是**元 / 小时**（口径：一对一、报 2 节及以上），**不是元 / 节** —— 家长选的「每节课 1 / 1.5 / 2 小时」是再乘上去的：

```
课单价（元 / 节） = 基础价（元 / 小时） × 每节课几小时 × 人数系数
（报 1 节时再加 10% 手续费）
```

例：基础价 150 元/小时、选 1.5 小时一节 → 课单价 225 元/节。不想开放的课程写成 `#### 课程: 医学: 暂未开放`（**这四个字要原样**），该课程在报价页显示但不可选。

**两条口径（以课程清单为准；分组口径 2026-09 改过一次）：**

1. **阶段名 = 网站栏目的名字** —— 也就是每门课在「课程库」里所属的**顶级分区**
   （小学课内 / 初中课内 / 高中课内 / 外语 / 课外兴趣 / 成人课程），与课程页、
   课程总览用的是**同一套名字**。没有课的栏目不建组。
   ⚠️ **v37 时这里写的是"阶段名 = 课程类型里的学段"（小学 / 初中 / 高中 / 其他类型），
   那条已经作废**：机构原话「高中课内的 6 科高考外语和外语不能是一回事，虽然有同样的语言
   但是要单独分开」—— 按学段分组会把「高考外语」（栏目＝高中课内）与日语等语种课
   （栏目＝外语）混进同一组。现在**高考外语在「高中课内」、日语等语种课在「外语」**。
2. **课程名 = 课程库里的课程名**（去后台「课程 → 课程台账」看的那些名字）。
   同一个名字在整份价目表里**只能出现一次**（报价按名字查价，重名会报错价，服务端会拦住），
   因此**一门课只出现在一个分组里** —— 分组由它所属的栏目唯一决定。

改价的正路是**后台「报价」页**：改完跑 `npm run site:export` 把整份写回本文件
（不再是手工替换某一段）。

### 7.2 人数系数

写法：`### 一对二` → `#### 名称: 一对二` → `#### 系数: 0.7`。

| 班型 | 系数 | 含义 |
| --- | --- | --- |
| 一对一 / 一对二 / 一对三 / 小班课（4-8人） | 1.0 / 0.7 / 0.6 / 0.5 | 每人按基础价的这个比例 |
| 大班课（9-20人） | `按人数分摊` | 不用系数：按「教师课时总费用 ÷ 班级人数」算 |

`系数` 写 `按人数分摊` 这几个字（而不是数字）时，该班型走「教师费用 ÷ 人数」的算法。

> **这一节以前叫「班级系数」**（机构口径：「班级系数改成人数系数」）——
> 名字改了，含义与数值一个字没变：它讲的是**人数**，不是"班级"。
> 代码里的标识符（`classTypes` / `PricingClassType` / `coefficient`）也没改，
> 只是文档里的人话统一成了「人数系数」。

### 7.3 课时时长与乘数

写法：`### 1.5 小时` → `#### 名称: 1.5 小时` → `#### 小时: 1.5` → `#### 乘数: 1.5`。

`小时` 用于算课单价，`乘数` 用于乘价格，1 小时为基准 1.0。若某个时长不是简单按比例定价，把 `乘数` 改成实际比例（例如 1.5 小时收 1.4 倍 → 写 `1.4`）。

### 7.4 计费规则

```markdown
## 计费规则

### 手续费

#### 百分比: 10

### 试课免费门槛

#### 节数: 10

### 试课未达门槛

#### 收费: 是
```

| 项 | 当前 | 含义 |
| --- | --- | --- |
| 手续费百分比 | 10 | 只报 1 节时加收 10%；报 2 节及以上不加收 |
| 试课免费门槛 | 10 | 试课后报课满 10 节，试课免费 |
| 试课未达门槛收费 | 是 | 未满门槛时按该课程原价收 1 节试课费；填 `否` 则不收 |

### 7.5 教师分成（课时费）

```markdown
## 教师分成

### 基准分成

#### 百分比: 40

### 每增加一名学生

#### 百分比: 10

### 课程单价口径

#### 取值: 标准
```

口径：`教师课时费 = 小时数 × (课程单价/小时) × (第一名学生比例 + (学生人数 − 1) × 每加一名学生的比例)`，即第一名学生 40%，每多一名学生加 10 个百分点（8 人 110%）。适用于课内按系数计价的班型（一对一 … 小班课（4-8人）），**大班课（9-20人）不适用**（那类按「教师费用 ÷ 人数」另议）。`取值` 填 `标准` = 课程单价按**基础价**（标准单价，不含人数折扣）；填 `班型` = 再乘**人数系数**（= 家长每生实付的课时价）。

> 这条规则在后台「报价」页有**人话版与人数对照表**（教师课时费 / 机构留存一目了然），给老师解释时直接打开 `/admin/pricing` 看即可。

### 7.6 其他项目

写法：`### 课后晚辅导` → `#### 名称: 课后晚辅导` → `#### 小学: 6000 / 学期 / 人` → `#### 初中: 8000 / 学期 / 人`。

按学期 / 按期的独立产品（晚辅导、特色网课），不参与课时公式，报价页单独列出；字段名（`小学` / `初中` / `价格`）就是显示的小标题。

### 7.7 这个文件与后台「报价」页的关系（重要）

后台「报价」页**首次打开时按这个文件初始化**价格与规则；之后在后台改价只存在**服务端数据库**里
（不在浏览器里，也不会自己跑回这个文件）。**改完价以后网站在多久之后跟着变，看它是哪一份：**

| 网站是哪一份 | 报价从哪来 | 改价后要做什么 |
| --- | --- | --- |
| **本机构建**（`npm run dev` / `npm run build`，后端在跑） | **库里那一份**（`sync-site-data` 在构站那一刻取的后端快照） | **重新构站**（`npm run build`）就行 —— 不必导出、也不必改本文件 |
| **线上 Pages**（CI 里写着 `SITE_CONTENT_SOURCE=template`） | **本文件** | 跑 `npm run site:export`（把库里的整份报价写回本文件，其余五个内容文件也一起对齐）→ 提交推送（导出已经顺带做了 `sync-content`，见 §9） |
| 本机构建但后端没开 | 阶段 / 人数系数**为空**（页面文案仍来自模版） | 先起后端再构站；或 `SITE_CONTENT_SOURCE=template` 显式用本文件 |

也就是说：**本文件是导出产物 —— 后台为准，本文件是它的快照**；本机构建时库里那份优先
（自检有一条断言盯着这个优先级：文件里写 999 也不会盖住库里的 700）。
线上 Pages 读的虽然仍是本文件，但那是**上一次导出的快照**，不是"以文件为准"：
文件落后于库，线上就会发旧价格。
自检里 `npm run check` 的「前后台同一份配置必须算出同一个价」则保证两条路的口径一致。

> 想在后台看「报价」页，要先在本机把后端跑起来（`npm run server`，见《使用手册》第 0 节）；
> 只改网站文案的话不需要后端，`npm run dev` 就够（见 §9.1）。

| 学生案例数量（当前 3） | 学生案例数 |

| 常见问题 8 个**分组名**（条数只设下限 ≥ 30，当前 43） | 常见问题分组数 |
| 报价：阶段数 6、小学 4 门课与价格、初中 5、高中 4、班级类型 5 个、时长 3 个、其他项目 3 条 | 报价数据一节的对应项 |
| 课程页 `### 成人课程` 下任一课程去掉 `状态: 暂未开放` | 选修课程当前全部未开放 |

| 教师：首位不是陈老师、其职务改了、非首位教师填了「推荐理由」、`排序` 重复 | 教师一节的对应项 |
| 课程栏目：卡片名重复、路径重复 / 非 ASCII、班型名不在 `featured.md`、高中课内的命名子标题名变了 | 卡片 / 子标题的对应项 |

## 9. 改完必须做的四步 + 发布

### 9.1 本地四件事

```bash
npm run site:export    # 1. 把后台里的网站内容写回 data/site/*.md，并自动接着跑 sync-content
npm run sync-content   # 2. 把 .md 生成成 .ts（site:export 已自动做了；手工改 .md 时才需要单独跑）
npm run dev            # 3. 打开 http://localhost:3000 逐页看效果
npm run check          # 4. 自检：格式、卡片与锚点、报价公式
```

- **顺序很重要**：`npm run check` 校验的是**生成出来的 `.ts`**。改了内容却忘了同步，自检校验的就是旧内容 —— 你会以为「没问题」。`npm run site:export` 已经把 `sync-content` 串在里面了，所以日常只要「导出 → dev / check」。
- `npm run dev` 会监听 `data/site/*.md`，保存即自动同步并刷新页面，因此开发时不必手动跑第 2 步 —— 但它是给**手工改文件**准备的，下次导出会覆盖你的手改（见 §2.5）。
- **改网站文案需要后端**（内容在库里）：`npm run site:export` 要问的就是它，所以先另开一个终端跑 `npm run server`；不跑的话导出会以退出码 2 结束，网站本身仍可 `SITE_CONTENT_SOURCE=template npm run dev` 看文件那一份。
- 想连 404 页面与站内链接一起检查（更慢，需要先构建）：`npm run build && npm run check:404 && npm run check:links`。

### 9.2 提交

```bash
git status                                        # 看清自己改了哪些文件
git add data/site/content.md data/site/content.ts # 只加自己改的（.md 与同名 .ts 一起）
git commit -m "content(价格): 高中课程基础价调整"
```

提交信息风格（与仓库历史一致）：`类型(范围): 说明`，类型用 `content`（内容）/ `docs`（文档）/ `fix`（修错）/ `feat`（新功能）/ `style`（样式）。历史例子：`content(时间): 节假日照常，两处口径一致`、`content(FAQ): 常见问题从 17 条扩到 42 条`。

### 9.3 发布（推送与自动部署）

- **本项目的约定：不要每改一处就推送。** 先在本地提交，攒一批由负责人手动推送。
- **推送前先确认网站与后台同步了**：`npm run site:export -- --check`（只比对不写盘；六个文件与后台不一致时退出码 1，那就先跑一次 `npm run site:export` 并把结果提交）。
- 一旦推送到 `main`，GitHub Actions 自动跑：`lint` → `sync-content` → `typecheck` → `check`（就是上面那条自检）→ `build` → `check:404` → `check:links` → 部署到 GitHub Pages。
- 线上地址：`https://jeremythierrychan.github.io/NexGenEdu/`。**等 Actions 变绿再去核对线上**（仓库 Actions 标签页看进度）；变红说明自检或构建没过，线上仍是旧版本 —— 先修本地，别急着再推。
- 核对线上时强制刷新（`Cmd+Shift+R`）：Pages 有缓存，旧页面可能还在。

## 10. 常见症状 → 原因对照表

| 症状 | 最可能的原因 | 怎么办 |
| --- | --- | --- |
| 某个页面整页变空 | `## 页面: X` 标记被改坏 | 看终端 `[content] … 缺少「## 页面: X」段落`，把标记改回来 |
| 页面标题、说明全空 | 该段开头的 `---` 字段块少了或未闭合 | 补上 `---`；终端会有对应警告 |
| 卡片点进去 404 | 卡片 `路径:` 里有中文、空格或斜杠 | 改成 `primary-chinese` 这种 ASCII 写法，跑 `npm run check` |
| 课程卡片点进去只有标题、正文没了 | 正文里 `### 小标题` 前的**反斜杠被删了** —— 它被当成新的 `###` 分组，正文从那里截断 | 把 `\### …` 的反斜杠补回来（见 §4.4 / §5） |
| 卡片点进去跳空 / 页面 404 | 卡片名与小节名不逐字一致 | 让 `## 页面: 课程` 里那一节的小节名等于卡片名（注意全角「｜」） |
| 首页某段根本不显示 | 内容写在了 `>` 引用块里，或分组标题名写错 | 写成正式条目（`#### 名称 \| 值`），不要放进引用块 |
| 某个字段（适合对象 / 课程定位）不显示 | 字段没写 `- · ` 前缀，或写成了标题 | 改回 `- · 适合对象: …` |
| 价格改了，线上没变 | 线上那份读的是上次导出的快照：只改了后台（库里）却没跑 `npm run site:export`（或没提交那六个文件 / 没 push） | 按 §7.7：`npm run site:export` → commit 并推送 |
| 本机构建后，在后台改了数据网站上却没变 | 网站是**静态**的：只在构站那一刻取一次库里的数据，不会实时跟着库变 | 重新构站（`npm run build`，那台机器要连得上后端）；线上那份还要按 §7.7 处理价格 |
| 报价试算提示「所选课程暂未开放」 | 「暂未开放」四个字被改写成了别的说法 | 改回 `暂未开放`，或补上价格 |
| 开发时改完内容页面还是旧的 | 后台改完没跑 `npm run site:export`（文件没跟上），或只改了 `.md` 没同步，或 dev 没在跑 | 跑 `npm run site:export`（顺带 `sync-content`）再刷新，或重启 `npm run dev` |
| 图片位置是灰块 | 照片没放进 `public/images/` 或文件名写错 | 放图，并把文件名填进 `### 教室照片格位` |

## 11. 不要做的事

- [ ] 不要手工改 `data/site/` 下的六个 `.md`（content / pricing / faq / cases / featured / schedule）—— 它们是**导出产物**（`npm run site:export` 从后台写回），下次导出会覆盖你的改动；要改内容去后台。
- [ ] 不要手工改 `data/site/*.ts`（生成物，下次同步会覆盖）。
- [ ] 不要提交 `data/site/.sync-stamp.ts`（未纳入版本库的同步时间戳）。
- [ ] 不要把条目里的半角竖线 `|` 写成全角 `｜`，也不要混用中英文冒号。
- [ ] 不要在卡片 `路径:` 里用中文、空格、斜杠（线上会 404）。
- [ ] 不要把「暂未开放」写成别的说法（会被当成一个价格）。
- [ ] 不要删除或改名 `## 页面: X` 段落标记（整页会变空）。
- [ ] 不要在内容里写 HTML、`<script>`、内联样式 —— 页面不会执行，只会显示成文字。
- [ ] 不要在没有同步自检的情况下改动 §8 里那些被钉住的数量与名称。
- [ ] 不要在内容里编造案例、承诺或数字（`cases.md` 与 `faq.md` 顶部都写着这条约定：拿不准就写「以咨询确认为准」）。
- [ ] 不要 `git add -A` / `git add .`（会把无关文件甚至别人的改动一起提交）。
- [ ] 不要把后台数据库文件（`server/data/nexgenedu.db`）或它的备份当成内容文件去改 —— 网站内容**以后台为准**，`data/site/*.md` 是它的**导出快照**（见 §1、§2.5）。
- [ ] 不要每改一处就推送，更不要在自检未通过时推送。

## 12. 拿不准的时候

1. **先看终端**：内容格式问题只警告不报错，页面空白时终端那行 `[content] …` 就是答案。
2. **跑自检**：`npm run sync-content && npm run check`，报什么就改什么；红了不要推。**推送前先跑 `npm run site:export -- --check`** 确认网站与后台同步了（不一致退出码 1）。
3. **不确定的规则**：宁可写「以咨询确认为准」，也不要为好看编数字 —— 报价页、FAQ、时间安排三处对外承诺必须与 `pricing.md` / `schedule.md` 的实际口径一致（自检会校验其中一部分，例如常见问题里的试课规则必须与「满 10 节」一致）。
4. **改了没效果**：按 §10 的表逐条对照；仍不确定就把「改了哪个文件的哪一行 + 终端输出」发给开发者。
