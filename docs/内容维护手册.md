# 内容维护手册（宣传网站）

> **读者**：机构运营 / 负责人。不需要写代码，但需要会在项目目录跑几条命令。
> **这份手册解决什么**：把宣传网站上的文案、课程、价格、常见问题、学生案例、时间安排改成机构现在的真实情况，并安全发布到线上 —— 不碰代码，也不碰后台里的数据。
> **改内容的最小闭环**：改 `data/site/` 下的 `.md` 文件 → `npm run sync-content` → `npm run dev` 看效果 → `npm run check` 自检 → `git commit`（推送由负责人决定，见 §9）。
>
> 下文示例摘自现有文件，**行内容与文件一致**；为省篇幅省略了字段之间的空行与 `#### 名称:` 行（文件里每个字段之间都有一行空行，照原样写即可）。

## 1. 内容都在哪：`data/site/` 六个文件

| 文件 | 管什么 | 对应页面 |
| --- | --- | --- |
| `content.md` | 全站品牌与联系方式、首页、课程详情、教师、关于我们、联系我们（**6 个页面段**） | `/` `/courses` `/teachers` `/about` `/contact` |
| `pricing.md` | 报价页的选项与价格：学习阶段、基础价、科目、班级系数、时长、计费规则、教师分成、其他项目 | `/quote`，以及后台「报价」页的初始数据 |
| `faq.md` | 常见问题（8 个分组） | `/faq` |
| `cases.md` | 学生案例（当前 3 个） | `/cases` |
| `schedule.md` | 课程时间安排（4 组时段表） | `/schedule` |
| `featured.md` | 特色课程的分组、每门课的独立页面与面包屑 | `/courses/featured/**` |

想立刻看到某一页：首页 `/`；课程总览 `/courses`；栏目页 `/courses/primary`（小学课内）、`/courses/junior`（初中课内）、`/courses/senior`（高中课内）、`/courses/languages`（外语）、`/courses/interests`（课外兴趣）、`/courses/adults`（成人课程）；卡片页 `/courses/<卡片的路径>`（如 `/courses/primary-chinese`）；其余 `/teachers` `/about` `/contact` `/quote` `/faq` `/cases` `/schedule`。

> **后台的数据不在这些文件里。** 教务后台（`/admin`）的学生、排课、收费等都存在**服务端数据库**里
> （本机后端进程管的 `server/data/nexgenedu.db`，**不在浏览器里**）。
>
> 而**网站上的教师、课程、课程正文与报价**：从 2026-09 起**两边都能改**了 ——
> 网站构站时连得上后端就用**库里的**，连不上就用这里的文件（完整规则见
> [技术架构 §5.1](./技术架构.md)）。因此动手前先看这一节：

### 1.1 改内容之前：先确认网站吃的是哪一份

| 你想要的 | 改哪里 | 怎么让网站更新 |
| --- | --- | --- |
| 教师资料、课程卡片、课程分区、课程正文、报价 —— 日常维护 | **后台**（教师页、课程库、报价页） | 重新构站一次（`npm run build`，**构站那台机器要连得上后端**） |
| **学生案例**（`/cases` 与首页那块） | **后台「网站内容」页**（v19 起） | 重新构站一次（`npm run build`，那台机器要连得上后端） |
| **特色课程**（三级课程树 + 各课程页） | **后台「网站内容」页**（v20 起） | 重新构站一次（那台机器要连得上后端） |
| **课程类型**（学段 / 学科与项目 / 内容模块 / 班型 / 交付形态这五个维度） | **后台「课程类型」页**（v23 起） | 后台各处的班型下拉**立刻**生效；网站上的展示要重新构站一次（那台机器要连得上后端） |
| **哪些组合真的开**（学科 × 内容模块 × 班型 × 交付形态） | **后台「开放矩阵」页**（v24 起） | 目前只影响后台与将来的 AI 排课 / 诊断推荐（判定口径在那里），网站展示不必重构 |
| **常见问题**（`/faq`） | **后台「网站内容」页**（v21 起） | 重新构站一次（那台机器要连得上后端） |
| **品牌与联系方式 / 首页 / 关于 / 联系我们 / 时间安排的文案** | **后台「网站内容」页**（v22 起，五个页签） | 重新构站一次（那台机器要连得上后端） |
| 教师 / 课程 / 报价 / 案例 —— 想在**没连后端**时也看到内容 | 不必改文件：用 `SITE_CONTENT_SOURCE=template npm run dev` 就能看模版那一份（默认口径下那五块是**空白**） | — |
| 新增一门课要上网站 | 后台「课程库」加一行并填「网站上怎么展示」；或在这里加卡片（§4.6） | 同第一行 / 第二行 |

判断"这次构站用的是哪一份"：构建日志里那行 **`[site-data] 本次网站数据来源：…`**。
三种可能：**后端**（库里的，构站时连得上）/ **空白**（连不上：那五块**没有内容**）/**模版**（`SITE_CONTENT_SOURCE=template` 显式要求时）。

**这些文件是 GitHub Pages 那份的唯一出处**，也是"连不上后端"时的整站内容 ——
因此改它们依然有意义。但**库里改过的内容不会自动回到文件里**：两边不一致时，
构站那台机器连得上后端就显示**库**那一份，连不上就显示**文件**那一份（二选一，不混合）。
想让两边一致又不手工抄：后台「课程库 → 从网站导入内容」是**文件 → 库**这一条路；
反过来（库 → 文件）目前没有自动通道 —— 手动把改动补进 `.md`，或者接受"以后端为准"。

> **即将变化**（见 PROJECT.md）：首页 / 关于 / 联系 / 常见问题 / 案例 / 时间安排 / 特色课程
> 这些文案也在往库里搬。搬完之后，**上表第二行就从"改这里"变成"改后台"**，
> 这些 `.md` 会退化成"没连后端时的模版"这一种用途。

数据的流转方向（模版这一条路）：`data/site/*.md`（你改这里）→ `npm run sync-content` → `data/site/*.ts`（自动生成，勿手改但**要提交**）→ `lib/data/*.ts`（解析成结构）→ 页面渲染。一句话：**只改 `.md`，永远不要手工改 `.ts`。**

## 2. 通用格式约定（六个文件都适用）

### 2.1 六种基本写法

| 写法 | 作用 | 示例（摘自现有文件） |
| --- | --- | --- |
| `# 标题` | 文件第一行的总标题 | `# NexGenEdu · 新锐教培 · 网站内容` |
| `## 页面: 名称` | **页面分段标记**，一个文件可有多段 | `## 页面: 首页` |
| `---` … `---` | 该页面的**短字段**块，一行一个字段 | `title: 让学习真正发生` |
| `## 分组名` / `### 分组名` | 页面内的分组（几级井号看文件自己的用法） | `### 教学特色` |
| `#### 名称 \| 值` | 分组里的条目，**名称与值之间用半角竖线 `\|`** | `#### 小组课规模 \| 1-3 人` |
| `- · 字段名: 内容` | 字段（`featured.md` 的课程字段用这种写法） | `- · 适合对象: 需要课内同步提升的学生` |

条目写成 `#### 名称: 值`（半角或全角冒号）也能识别，**但值里含冒号时必须用竖线**；`>` 开头的引用块是写给你自己看的说明，**不会显示在网站上**。

### 2.2 每个文件的格式速查（最容易混的地方）

| 文件 | 分段 | 分组 | 条目写法 | 字段写法 |
| --- | --- | --- | --- | --- |
| `content.md` 全站 / 首页 / 关于 | `## 页面: 全站` | `### 课程栏目` | `#### 卡片名 \| 路径: …`；`#### 标题 \| 说明` | `字段: 值`（在 `---` 块里） |
| `content.md` 课程 | `## 页面: 课程` | `### 语文` | `#### 小学语文｜建立阅读与表达的基础` + 正文 | 核心能力用 `- 核心能力：…` |
| `content.md` 教师 | `## 页面: 教师` | `### 陈老师` | —（只有字段） | `#### 科目: 数学, 英语` |
| `pricing.md` | `## 页面: 智能报价` | `## 学习阶段` → `### 小学` | `#### 课程: 小学课内: 150` | `#### 名称: 一对一` |
| `faq.md` | `## 页面: 常见问题` | `## 试课与报名` | `### 问题 \| 答案` | — |
| `cases.md` | `## 页面: 学生案例` | `### 初二 李同学｜数学从 62 分到 91 分` | — | `#### 年级: 初二` |
| `schedule.md` | `## 页面: 课程时间安排` | `### 工作日排课` | `#### 晚第一节 \| 17:30–19:30` | — |
| `featured.md` | `## 页面: 特色课程` | `### 课内辅导` | `#### 一对一定制课`（二级课）、`##### 小学晚托`（三级课） | `- · 路径: one-on-one` |

### 2.3 会「静默失效」的写法（重点）

这些错误**不会报错**，页面只是少了东西 —— 最需要小心的一类问题：

| 写错的地方 | 你看到的现象 | 怎么发现 |
| --- | --- | --- |
| `## 页面: 首页` 改成 `## 页面 首页`（少冒号）或改了名称 | 该页整页空白 | 终端出现 `[content] … 中缺少「## 页面: 首页」段落…` |
| 页面开头的 `---` 只写一半 / 少一行 | 该页标题、说明等短字段全空 | 终端出现 `[content] … 缺少 --- 包裹的字段块` / `字段块未闭合` |
| 条目里的半角竖线 `\|` 写成全角 `｜`（如卡片写成 `#### 初中数学｜路径: junior-math`） | 解析器找不到半角竖线，退而按冒号切，卡片名变成「初中数学｜路径」这种怪名字 | 页面名字不对；`npm run check` 的卡片名 / 锚点断言会红 |
| `- · 字段名: 内容` 少了中间的 `·`（写成 `- 字段名: 内容`） | 该字段读不到（特色课程页缺一段说明） | 特色课程页缺字段 |
| 内容写进了 `>` 引用块 | 永远不显示 | 引用块**从不**渲染到页面 |
| 卡片 `路径:` 里出现中文、空格或斜杠 | 卡片点进去 404 | `npm run check` 会拦（要求小写字母 / 数字 / 连字符） |
| 把「暂未开放」写成「未开放」等别的说法 | 不再被当成「暂未开放」，报价时提示无法报价 | 报价页试算一次即可发现 |

**页面空白先看终端**：内容格式问题一律只警告、不报错，页面继续渲染（只是缺内容），所以终端里那行 `[content] …` 是你唯一也最准确的线索。

### 2.4 `data/site/*.ts` 是生成的

- 每个 `.md` 都有同名 `.ts`（`content.md` → `content.ts`），由 `scripts/sync-content.mjs` 生成，文件头写着「请勿手工编辑」；它**必须提交**（仓库跟踪它，线上构建也依赖它）。
- `data/site/.sync-stamp.ts` 是同步时间戳，未纳入版本库，**不要提交、不要手建**。
- 手改 `.ts` 的后果：下次同步被覆盖，改动只在线上产物里存在，再构建一次就消失。

## 3. `content.md`：全站与各页面

### 3.1 全站段（`## 页面: 全站`）

控制浏览器标题、页头页脚与联系方式，字段写在 `---` 块里：

```markdown
brand_name_zh: 新锐教培
phone: +86 138-6853-0992（陈老师）
wechat: JeremyThierryChan（陈老师）
business_hours: 每日 9:00–21:00（含节假日）
class_hours: 每日 8:00–22:00（含节假日）
```

**营业时间与上课时间是两个字段，不要混着写**：`business_hours` 是**营业时间**（工作人员在校区接待咨询），页脚显示为「接待时间」；`class_hours` 是**上课时间**（教师与学生实际上课），显示在页脚与课程时间安排页。自检会校验：两者都有值、不是同一句话、上课时间 8:00 开始且 22:00 结束（比营业时间早开始晚结束）、两者都写「含节假日」。

### 3.2 首页段（`## 页面: 首页`）

短字段管首屏标题/副标题、两个按钮与各区块的标题说明。三个分组：`### 首屏数据`（当前 6 条）、`### 教学特色`（当前 7 条）、`### 教室照片格位`（当前 3 条）。

**首页区块顺序由代码固定，改内容不会改顺序**：教学特色 → 负责的教师团队 → 学生案例 → 试课体验 → 课程 → 教室环境。教室照片放进 `public/images/`（目录不存在就新建），再把文件名填进格位，例如 `#### 301 教室 | classroom-301.jpg`；文件名留空时显示一个中性的图片位。

### 3.3 关于段与联系我们段

- 关于页四组：`### 教学理念`（4 条）、`### 服务形式`（5 条）、`### 校区数据`（4 条）、`### 校区介绍`（3 段）。「校区数据」里的数字（如「学科数量 | 19 门」）请按实际情况替换。
- 联系我们页：`### 联系方式清单`，当前 6 行（电话 / 微信 / 邮箱 / 地址 / 营业时间 / 上课时间）；不需要显示邮箱就删掉那一行。

### 3.4 教师段（`## 页面: 教师`）

每位教师是一个 `### 姓名` 分组，字段写作 `#### 字段: 值`：

| 字段 | 说明 |
| --- | --- |
| `科目` | 逗号分隔。**它同时决定课程页「这门课谁来上」**：某位老师的科目出现在某门课的名字或小节名里，这位老师就出现在那门课页面上 |
| `职务` / `教龄` | 不需要就删掉那一行；教龄如 `10 年` |
| `简介` | 一句话，显示在教师卡片上 |
| `推荐理由` | 选填；**目前只有第一位教师填**（自检要求其余为空） |
| `类型` | 填 `AI` 表示这是 AI 智能体（卡片显示「AI 智能体」标记）；不填即真人教师 |
| `排序` | 数字，越小越靠前（不显示在页面上，但决定顺序，不能重复） |
| `状态` | `在职` / `离职`；离职保留资料但不展示 |

字段之后、下一位教师之前的文字是这位教师的详细介绍。首页的教师卡片读这里的前三位 —— 改这里，首页与教师页一起更新。

**自检钉住**：首位必须是「陈老师」、其职务是「全科教师」；除首位外的教师**不要填推荐理由**；AI 智能体必须排在真人教师之后（靠 `排序` 控制）。

## 4. 课程结构：栏目 → 子标题 → 卡片

这部分在 `content.md` 的「全站」段：`### 课程栏目`。首页课程区与课程页共用它。

### 4.1 六个栏目

| 栏目 | 栏目页 | 卡片数（当前） |
| --- | --- | --- |
| 小学课内 / 初中课内 / 高中课内 | `/courses/primary` `/courses/junior` `/courses/senior` | 4 / 5 / 10 |
| 外语 / 课外兴趣 / 成人课程 | `/courses/languages` `/courses/interests` `/courses/adults` | 7 / 2 / 4 |

合计 **32 张卡片**。自检只要求「每个栏目、每个子标题下都有卡片」「卡片总数 ≥ 20」「卡片名不重复」—— 增删卡片不会被数量拦住，但结构错误会被拦住。

### 4.2 卡片行的写法

```markdown
#### 小学语文 | 路径: primary-chinese · 班型: 一对一定制课、一对二 / 一对三小组课、一对多小班课、9 人以上大班课 · 栏目: 小学课内
#### 高中物理 | 路径: senior-physics · 班型: 一对一定制课、一对二 / 一对三小组课、一对多小班课、9 人以上大班课 · 栏目: 高中课内 · 子栏目: 七选三 · 标签: 学考→高中物理学考、选考→高中物理选考
#### 3D建模 & 3D打印 | 路径: 3d-printing · 班型: 一对一定制课、一对二 / 一对三小组课、一对多小班课、9 人以上大班课 · 栏目: 课外兴趣 · 状态: 暂未开放 · 标签: Shapr3D、OpenSCAD、Bambu Studio
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 卡片名（`\|` 之前） | ✅ | 一门课程的名字，如「高中物理」「雅思」 |
| `路径:` | ✅ | 卡片页 URL 片段，**必须是小写字母 / 数字 / 连字符** |
| `班型:` | ✅ | 该课程开设的班型，顿号分隔；**必须是 `featured.md` 里存在的班型名** |
| `栏目:` | ✅ | 上面六个栏目之一 |
| `子栏目:` | 选填 | 高中课内用：`必考科目` / `外语` / `七选三` |

> **`栏目:` / `子栏目:` 与后台的「课程分区」是同一件事的两种写法**（v18 起）：
> 后台里分区是一份数据（可增删改名排序），库里存的是分区 id；这两行文字是**模版兜底**
> —— 没有后端的环境（GitHub Pages）靠它构站，「从网站同步 / 导入内容」也按它把分区补进库
> （同名同上级就复用现有的那一条，**只增不改**，不会覆盖你在后台改过的名字与顺序）。
> 因此在两边都改过名字之后，你看到的差异是"真的差异"：`npm run site:diff` 就是把这份
> 内容文件与库里的分区结构逐项比一遍（栏目、子栏目、卡片与先后顺序都比）。
| `状态:` | 选填 | 填 `暂未开放` 时卡片显示标记 |
| `标签:` | 选填 | 卡片内的细分阶段，写法 `标签名→目标小节名`（见 4.4） |

字段之间用 ` · ` 分隔：**间隔号（U+00B7）两边各一个空格**。它既不是英文句点、也不是全角的「・」—— 最稳妥的做法是从现有卡片行里连空格一起复制那个符号。

### 4.3 路径 slug 的铁律

- **只能用英文小写字母、数字、连字符**：`primary-chinese`、`senior-physics`、`3d-printing`。
- **不能用中文、空格、斜杠**：历史上这里踩过坑 —— 路径里带了空格与斜杠，卡片点进去 404（斜杠会被 URL 当成层级分隔符）。
- 路径不能重复（自检拦），也不要与栏目路径（`primary`/`junior`/`senior`/`languages`/`interests`/`adults`）同名。
- 改路径等于换网址：**已发出去的链接会失效**，没有特别理由不要改。

### 4.4 标签 = 同一页面里的不同阶段（不是新页面）

- 一张卡片 = 一门课 = 一个页面；课程内部没有细分时**不要写标签**。
- 标签只用于「这门课内部确实有并列阶段」：外语级别（A1–B2 / N5–N3）、高考外语的 6 个语种、七选三的学考与选考。
- 写法 `标签→目标小节`（`学考→高中物理学考`）；不写 `→` 时标签名本身即目标小节名。
- **标签的目标小节必须真的存在于该卡片页面上**（§5 里那个学科下要有同名小节），否则自检报「标签都能在本卡片页面里找到对应阶段」失败 —— 这就是「点了没反应 / 跳空」的根源。

自检固定两条：七选三每张卡片必须带 `学考` + `选考`；外语栏目每张语言卡片必须有级别标签。

### 4.5 班型与特色课程的联动

卡片 `班型:` 里的名字必须存在于 `featured.md`（自检拦），因为课程页要用它们反查「这个班型开设了哪些科目」。两条特殊情况：**晚托管不挂到任何学科**（单独的服务，不分科目）；**周中预习课只挂初中科目**（自检拦）。

### 4.6 新增一门课程的完整步骤

> **新增之后还要在后台点一次同步**：后台「课程库」页有一个「从网站同步课程」按钮，
> 它会把这里新增的卡片拉进课程库 —— 没有同步的课程，在排课、报课的下拉里选不到
> （课程库是后台的课程台账，网站卡片是它的来源之一；反过来，在后台课程库加课
> **不会**让网站上多出卡片）。

以新增「小学奥数」为例：

1. 在 `## 页面: 课程` 的 `### 数学` 下加小节（小节名与卡片名一致，见 §5）：

   ```markdown
   #### 小学奥数｜思维拓展与竞赛入门

   面向校内成绩稳定、想进一步拓展思维的学生。

   - 核心能力：数感 · 图形与空间 · 逻辑推理 · 计数与枚举 · 解题策略
   ```

2. 在 `### 课程栏目` 里加卡片行（路径用英文）：`#### 小学奥数 | 路径: primary-olympiad · 班型: 一对一定制课、一对二 / 一对三小组课 · 栏目: 小学课内`
3. 要报价的话，在 `pricing.md` 对应阶段加基础价：`#### 课程: 小学奥数: 260`
4. 保存后跑 `npm run sync-content` → `npm run dev`（看 `/courses` 与 `/courses/primary-olympiad`）→ `npm run check`（卡片路径、锚点、班型联动都会被校验）。

## 5. `content.md` 的课程详情段（`## 页面: 课程`）

```markdown
### 语文

#### 小学语文｜建立阅读与表达的基础

语文素养的起点是识字、朗读与表达，让孩子先敢读、敢说、愿意写。

- 核心能力：识字写字 · 朗读与积累 · 阅读理解 · 口语表达 · 写话起步 · 学习习惯

#### 初中语文｜打通阅读与写作

从读懂到读懂意图，从会写到写得有条理。
```

- `### 学科名` 是一个学科；学科内每个 `#### 学段｜一句话` 是该学科的一个**学段小节**。同一学科的不同学段**放在一起**（小学 → 初中 → 高中），家长才能对比进阶路径。
- **小节名 = 「｜」之前的部分**（「小学语文｜建立阅读与表达的基础」→ 小节名 `小学语文`）。它必须与「课程栏目」里的卡片名 / 标签目标**逐字一致**，否则卡片跳空。
- 「｜」是全角竖线。写成半角 `|` 会被解析成「名称 | 值」，小节名就变了。
- `核心能力` 写成 `- 核心能力：… · …` 一行；没有这一行也可以，但不建议空着。

## 6. `featured.md`：特色课程

标题层级决定课程层级，也决定独立页面与面包屑：

| 写法 | 含义 | 页面 |
| --- | --- | --- |
| `### 课程名` | 一级课程（`### 课内辅导`） | `/courses/featured/in-class` |
| `#### 课程名` | 二级课程（`#### 一对一定制课`） | `/courses/featured/in-class/one-on-one` |
| `##### 课程名` | 三级课程（`##### 精品小升初`） | 再深一层路径 |

字段**必须**写成 `- · 字段名: 内容`（可用字段：`路径` / `适合对象` / `课程定位` / `主要做法` / `可以期待`），字段之后的正文是该课程的详细介绍：

```markdown
### 课内辅导

- · 路径: in-class
- · 适合对象: 需要课内同步提升的学生
- · 课程定位: 按学生当前学段与校内进度上课，把课内没弄懂的地方补上。
- · 主要做法: 先测评定位薄弱点，再按学段与课程类型排课，课后由授课教师跟进作业与错题。
```

> **字段不能写成标题。** 把「适合对象」写成 `#### 适合对象: …` 会与「二级课程」无法区分（两者都是四个井号），导致子课程被当成字段。`路径` 同样必须是 ASCII。

**当前结构**（`### 课内辅导` 之下）：一对一定制课、一对二 / 一对三小组课、一对多小班课、9 人以上大班课、晚托管（小学晚托 / 初中晚托）、周中预习课、假期预习课（精品小升初 / 精品初升高 / 基础小升初 / 基础初升高）。

**后台的「班型」候选项就来自这个文件**（取一级课程下的二级课程名），所以这里的课程名要与 `content.md` 卡片 `班型:` 里写的名字一致。

## 7. `pricing.md`：价格与规则

这个文件决定 `/quote` 报价页的可选项与价格，**也是后台「报价」页的初始数据**（后台只在第一次打开时读它一次；
之后两边各走各的 —— 后台改的价格要「导出配置」才回到这个文件，见 §7.8）。

### 7.1 学习阶段与课程基础价

```markdown
## 学习阶段

### 小学

#### 课程: 小学课内: 150

#### 课程: 小学奥数: 260

#### 科目: 语文、数学、英语、科学
```

每个 `### 阶段名` 是一个学习阶段，下面同时写「课程」与「科目」两部分。`#### 课程: 名字: 基础价` 的基础价是**元 / 节**，口径是「一对一、1 小时、报 2 节及以上」的价格。不想开放的课程写成 `#### 课程: 医学: 暂未开放`（**这四个字要原样**），该课程在报价页显示但不可选。

### 7.2 科目与科目系数

科目用顿号分隔（`#### 科目: 语文、数学、英语、科学`）；只有分科目的阶段才写这一行（出国考试 / 专业英语 / 成人兴趣没有）。需要单独加价的科目写成 `科目 ×系数`，例如 `物理 ×1.1`；省略即按 1 计（不加价）。

### 7.3 班级系数

写法：`### 一对二` → `#### 名称: 一对二` → `#### 系数: 0.7`。

| 班型 | 系数 | 含义 |
| --- | --- | --- |
| 一对一 / 一对二 / 一对三 / 一对多（4-8） | 1.0 / 0.7 / 0.6 / 0.5 | 每人按基础价的这个比例 |
| 班课（9-20） | `按人数分摊` | 不用系数：按「教师课时总费用 ÷ 班级人数」算 |

`系数` 写 `按人数分摊` 这几个字（而不是数字）时，该班型走「教师费用 ÷ 人数」的算法。

### 7.4 课时时长与乘数

写法：`### 1.5 小时` → `#### 名称: 1.5 小时` → `#### 小时: 1.5` → `#### 乘数: 1.5`。

`小时` 用于算课单价，`乘数` 用于乘价格，1 小时为基准 1.0。若某个时长不是简单按比例定价，把 `乘数` 改成实际比例（例如 1.5 小时收 1.4 倍 → 写 `1.4`）。

### 7.5 计费规则

```markdown
## 计费规则

### 手续费

#### 百分比: 10

### 试课免费门槛

#### 节数: 10

### 试课未达门槛

#### 收费: 是
```

| 项 | 当前 | 含义 |
| --- | --- | --- |
| 手续费百分比 | 10 | 只报 1 节时加收 10%；报 2 节及以上不加收 |
| 试课免费门槛 | 10 | 试课后报课满 10 节，试课免费 |
| 试课未达门槛收费 | 是 | 未满门槛时按该课程原价收 1 节试课费；填 `否` 则不收 |

### 7.6 教师分成（课时费）

```markdown
## 教师分成

### 基准分成

#### 百分比: 40

### 每增加一名学生

#### 百分比: 10

### 课程单价口径

#### 取值: 标准
```

口径：`教师课时费 = 小时数 × (课程单价/小时) × (第一名学生比例 + (学生人数 − 1) × 每加一名学生的比例)`，即第一名学生 40%，每多一名学生加 10 个百分点（8 人 110%）。适用于课内按系数计价的班型（一对一 … 一对多小班课），**9 人以上大班课不适用**（那类按「教师费用 ÷ 人数」另议）。`取值` 填 `标准` = 课程单价按「基础价 × 科目系数」（不含班级折扣）；填 `班型` = 再乘班级系数。

> 这条规则在后台「报价」页有**人话版与人数对照表**（教师课时费 / 机构留存一目了然），给老师解释时直接打开 `/admin/pricing` 看即可。

### 7.7 其他项目

写法：`### 课后晚辅导` → `#### 名称: 课后晚辅导` → `#### 小学: 6000 / 学期 / 人` → `#### 初中: 8000 / 学期 / 人`。

按学期 / 按期的独立产品（晚辅导、特色网课），不参与课时公式，报价页单独列出；字段名（`小学` / `初中` / `价格`）就是显示的小标题。

### 7.8 这个文件与后台「报价」页的关系（重要）

后台「报价」页**首次打开时按这个文件初始化**价格与规则；之后在后台改价只存在**服务端数据库**里
（不在浏览器里，也不会自己跑回这个文件）。因此后台改完价要用页面上的「导出配置」，把导出内容替换
本文件里「`## 学习阶段`」及其后的部分（页面文案字段不要动），再按 §9 提交，线上才会变。
两者不一致时**以本文件（宣传页）为准** —— 家长看到的、对外报价的是它。

> 想在后台看「报价」页，要先在本机把后端跑起来（`npm run server`，见《使用手册》第 0 节）；
> 只改网站文案的话不需要后端，`npm run dev` 就够（见 §9.1）。

## 9. 改完必须做的三步 + 发布

### 9.1 本地三件事

```bash
npm run sync-content   # 1. 把 .md 生成成 .ts（npm run dev 运行时已自动做）
npm run dev            # 2. 打开 http://localhost:3000 逐页看效果
npm run check          # 3. 自检：格式、卡片与锚点、报价公式
```

- **顺序很重要**：`npm run check` 校验的是**生成出来的 `.ts`**。改了 `.md` 却忘了 `sync-content`，自检校验的就是旧内容 —— 你会以为「没问题」。
- `npm run dev` 会监听 `data/site/*.md`，保存即自动同步并刷新页面，因此开发时不必手动跑第 1 步。
- **改网站文案不需要后端**。只有要顺手打开教务后台（`/admin`，例如核对「报价」页）时，才需要另开一个终端跑 `npm run server`；不跑的话后台会显示「后台需要本机后端」，网站本身不受影响。
- 想连 404 页面与站内链接一起检查（更慢，需要先构建）：`npm run build && npm run check:404 && npm run check:links`。

### 9.2 提交

```bash
git status                                        # 看清自己改了哪些文件
git add data/site/content.md data/site/content.ts # 只加自己改的（.md 与同名 .ts 一起）
git commit -m "content(价格): 高中课程基础价调整"
```

提交信息风格（与仓库历史一致）：`类型(范围): 说明`，类型用 `content`（内容）/ `docs`（文档）/ `fix`（修错）/ `feat`（新功能）/ `style`（样式）。历史例子：`content(时间): 节假日照常，两处口径一致`、`content(FAQ): 常见问题从 17 条扩到 42 条`。

### 9.3 发布（推送与自动部署）

- **本项目的约定：不要每改一处就推送。** 先在本地提交，攒一批由负责人手动推送。
- 一旦推送到 `main`，GitHub Actions 自动跑：`lint` → `sync-content` → `typecheck` → `check`（就是上面那条自检）→ `build` → `check:404` → `check:links` → 部署到 GitHub Pages。
- 线上地址：`https://jeremythierrychan.github.io/NexGenEdu/`。**等 Actions 变绿再去核对线上**（仓库 Actions 标签页看进度）；变红说明自检或构建没过，线上仍是旧版本 —— 先修本地，别急着再推。
- 核对线上时强制刷新（`Cmd+Shift+R`）：Pages 有缓存，旧页面可能还在。

## 10. 常见症状 → 原因对照表

| 症状 | 最可能的原因 | 怎么办 |
| --- | --- | --- |
| 某个页面整页变空 | `## 页面: X` 标记被改坏 | 看终端 `[content] … 缺少「## 页面: X」段落`，把标记改回来 |
| 页面标题、说明全空 | 该段开头的 `---` 字段块少了或未闭合 | 补上 `---`；终端会有对应警告 |
| 卡片点进去 404 | 卡片 `路径:` 里有中文、空格或斜杠 | 改成 `primary-chinese` 这种 ASCII 写法，跑 `npm run check` |
| 卡片上的标签点了没跳转 / 跳空 | 标签的目标小节在该卡片页面里不存在，或名字不逐字一致 | 在 `## 页面: 课程` 里补同名小节（注意全角「｜」） |
| 首页某段根本不显示 | 内容写在了 `>` 引用块里，或分组标题名写错 | 写成正式条目（`#### 名称 \| 值`），不要放进引用块 |
| 某个字段（适合对象 / 课程定位）不显示 | 字段没写 `- · ` 前缀，或写成了标题 | 改回 `- · 适合对象: …` |
| 价格改了，线上没变 | 只改了本地、或没 push、或改了后台报价页但没导出回文件 | 确认：文件已改 → 已 `sync-content` → 已 commit 并推送 |
| 在后台改了数据，网站上却没变 | 后台数据（服务端数据库）与网站内容（`data/site/*.md`）是两套，互不影响 | 网站要变：价格按 §7.8 导出回 `pricing.md` 再提交；网站新增的课程卡片要回后台「课程库」点一次「从网站同步」 |
| 报价试算提示「所选课程暂未开放」 | 「暂未开放」四个字被改写成了别的说法 | 改回 `暂未开放`，或补上价格 |
| 开发时改完内容页面还是旧的 | 只改了 `.md` 没同步，或 dev 没在跑 | 跑 `npm run sync-content` 再刷新，或重启 `npm run dev` |
| 图片位置是灰块 | 照片没放进 `public/images/` 或文件名写错 | 放图，并把文件名填进 `### 教室照片格位` |

- [ ] 不要删除或改名 `## 页面: X` 段落标记（整页会变空）。
- [ ] 不要在内容里写 HTML、`<script>`、内联样式 —— 页面不会执行，只会显示成文字。
- [ ] 不要在没有同步自检的情况下改动 §8 里那些被钉住的数量与名称。
- [ ] 不要在内容里编造案例、承诺或数字（`cases.md` 与 `faq.md` 顶部都写着这条约定：拿不准就写「以咨询确认为准」）。
- [ ] 不要 `git add -A` / `git add .`（会把无关文件甚至别人的改动一起提交）。
- [ ] 不要把后台数据库文件（`server/data/nexgenedu.db`）或它的备份当成内容文件去改 —— 网站内容只看 `data/site/*.md`（见 §1 开头那个「两个交点」）。
- [ ] 不要每改一处就推送，更不要在自检未通过时推送。

## 12. 拿不准的时候

1. **先看终端**：内容格式问题只警告不报错，页面空白时终端那行 `[content] …` 就是答案。
2. **跑自检**：`npm run sync-content && npm run check`，报什么就改什么；红了不要推。
3. **不确定的规则**：宁可写「以咨询确认为准」，也不要为好看编数字 —— 报价页、FAQ、时间安排三处对外承诺必须与 `pricing.md` / `schedule.md` 的实际口径一致（自检会校验其中一部分，例如常见问题里的试课规则必须与「满 10 节」一致）。
4. **改了没效果**：按 §10 的表逐条对照；仍不确定就把「改了哪个文件的哪一行 + 终端输出」发给开发者。
